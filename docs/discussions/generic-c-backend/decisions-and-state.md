## Decisions locked

Converged with the architect (2026-05-26). Recorded so they're not relitigated.

  cross-track deps). L2 = per-phase plan-first design doc → spec → Codex

- **Phase roadmap (L1) — authoritative doc: `roadmap.md`.** P1 = full supported
  **Rust surface + diagnostic logging** (fully scoped). P2 = **RegseqError** —
  the abstraction for authoring OS-agnostic errors mapped to OS-specific error
  codes during lowering; **definition only — detailed description + spec + tasks
  deferred to Phase-2 start** (per architect). **P3+ = domain constructs one at
  a time, deliberately UNSCHEDULED** — picked by immediate need after P1–P2
  (Register Access anticipated, NOT committed; pool also incl. Interrupts/
  Atomics/Lifecycle/Ordered-regions). Post-P1 ordering is partly forced by
  **front-end availability** (most domains aren't bridged — spec stages 16/17/18).
- **Domain phases are gated by what's in `RegseqModel`.** Diag-logging is the
  ONLY domain construct currently bridged (survives as
  `AttrData::Intrinsic(IntrinsicKind::Log(level))` on the callee item).
  MMIO/interrupt/atomic are spec stages 16/17/18, NOT implemented (atomics
  rejected). So P3+ each need a front-end (bridge) phase to land the construct
  in the IR before the backend can lower it. RegseqError bridge-status: **TBD —
  deferred to Phase-2 start**.
- **Per-phase exit gate** mirrors the bridge gate: a domain is
  "codegen-complete" when every construct lowers, compiles, runs, and
  auto-validates on the host.
- **Host-validatability varies by domain.** diag-log (printf) and register
  access (backing byte array) simulate *faithfully*; lifecycle and interrupts
  are partly *target* semantics → host validates structure only; real behavior
  needs Linux/Zephyr.
- **Phase-1 verification = a codegen-coverage harness** (bridge → `RegseqModel`
  → emit C → host `cc` → run → assert), with a DUAL oracle: diag-log **golden
  stdout** (behavior) + **golden C-file snapshot** (determinism/diff). Write
  fixtures that log *computed* values so the print is a genuine end-to-end test
  of the lowering.

  for shifted-alignment `Direct` enums (`enum E { A(u8), B(u32) }`: tag@0, A@1,
  B@4 — a naturally-aligned `uint32_t` payload cannot sit in a `union` placed at
  offset 1). Replaced canonically (§13 + Doc-2 D9) with the **union-of-views**:
  the tag cell + each non-fieldless variant become full-object §14 views (fields
  at **absolute** enum-object offsets → naturally aligned → no packing, no
  `union_start`), all sharing one `union`, **collapsed inline** for a single
  view (→ §9.8 tag-only struct, §9.9 single-field struct). Grounded against
  pinned rustc (`rustc_abi/src/layout.rs:803-824` `StructKind::Prefixed`; variant

  over-aligns; true align = `min(max_field_align, n) = layout.align`; `_Alignas`
  is invalid on a tag. Now `__attribute__((aligned(layout.align)))` (+`packed`),
  always `layout.align`. (b) **§15 fat-pointer exception** — a slice fat struct
  whose element is `Ty::Array(base,N)` emits `base (*)[N]`, and a C array needs
  its element complete even behind a pointer → an ordering edge to `base`
  (non-array elements need only a forward-decl). (c) Doc-2 D9 carried a stale
  `_Alignas(align)` → corrected to `aligned(align)` with the union-of-views.
- **Diag-log recognition (for the backend):** key on the durable model fact — a
  `Terminator::Call { callee: CallCallee::Direct(inst), .. }` where
  `model.instances[inst].item` carries `AttrData::Intrinsic(IntrinsicKind::Log(
  level))` in `domain_attrs.item_attrs`. Recognition is **location-independent**:
  bridge keys on the `#[rseq::intrinsic("log-…")]` attribute + the leaf fn name
  (`log_…`), keyed by `DefPathHash`. Args arrive **already peeled flat**
  (`[fmt_const, a1, … aN]`). **Backend rule: the log-marked item is a recognition
  tag — intercept at call sites; do NOT emit a C definition for it.**

## Project orientation

- **Regseq compiler**: Rust → C device-driver compiler. User is the
  designer/architect.
- **Where we are**: the rustc→`RegseqModel` front-end (the "bridge") is
  IR-structurally feature-complete (gate `pass`, `1a6a996`). The current stage
  is **codegen**: lowering the validated IR to C, starting with a generic-C
  (hosted-userspace) backend, built in domain phases.
- **Verification boundary (this workstream)**: a construct lowers to C that
