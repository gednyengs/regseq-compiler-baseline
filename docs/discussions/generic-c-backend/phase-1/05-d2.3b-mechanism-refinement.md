# Phase 1 — d2.3b mechanism refinement (anonymous-union `_raw` + M1)

A focused **design-refinement** (pre-spec, per `.harness/generic-c/methodology.md`)
that updates the mechanism record in `04-const-carve-out-resolution.md` §5.2 for the
**d2.3b** task (Package A: close the three documented Phase-1 const limitations
**#2-reloc / #3 / #4**). The architect approved **Package A / full closure**; this note
records the **lighter, empirically-verified mechanism** chosen over the §04 sketch, so
the d2.3b spec consumes a settled design.

> **What §04 left open.** §04 designed M1 (`_c<idx>` typed full view, for #2-reloc) and
> two **alternatives** for the inline #3/#4 family — **M2-a** (retype the niche cell +
> a nested-designator locator) and **M2-b** (give inline enums a `_raw` via a
> union-wrap), rejecting M2-b as "heavy (de-inlines every inline-enum access)". Grounding
> the mechanics against HEAD surfaced two corrections to that sketch (§1), and a verified
> refinement that resolves both (§2–§3).

## 1. Two corrections to the §04 M2-a/M2-b sketch

1. **M2-a cannot soundly close a `_Bool` niche cell *nested* in an aggregate (#4b).**
   M2-a closes #3 (a top-level `_Bool` niche cell) by emitting that field as its raw
   integer storage type (`uint8_t`) so `.<field> = 2` is byte-faithful — and `_Bool`
   is the *only* C type that normalizes a raw bit pattern (`(_Bool){2}` → `1`; Rust
   `char` maps to a 32-bit int, never C `char`). But when the niche cell is a `_Bool`
   **buried inside a nested aggregate field** (`enum E { A(struct S), B }`, niche in
   `S.b: bool`), the leaf lives in the **shared** `struct S` (emitted once,
   referenced by every user). Retyping `S`'s field would corrupt every other user of
   `S`; a nested designator `.field.b = 2` still routes through `_Bool` and normalizes.
   So M2-a leaves #4b a residual — *not* the full closure Package A requires.

2. **M2-b is light, not heavy — the §04 cost assumed a *named* union.** §04 spelled
   M2-b as `union { <inline view>; unsigned char _raw[size]; } u;` (a **named** member),
   which forces every inline-enum access to become `u.<view>.field` — de-inlining the
   whole d2.1 navigator path. But a gnu11 **anonymous** union+struct gets **member
   promotion**: the inline view's fields stay accessible as `e.field` *unchanged*, while
   a sibling `_raw` member enables the byte-image const init. The de-inlining cost was an
   artifact of the named-member spelling, not inherent to M2-b.

## 2. The refinement (verified): anonymous-union `_raw` for inline enums

Give a **single-view** inline enum (the §9.8 tag-only / §9.9 single-field collapse) a
byte-covering `_raw` through an **anonymous** union wrapping an **anonymous** struct of
the view fields:

```c
struct E {
    union {
        struct { /* the inline view fields, at absolute offsets */ };
        unsigned char _raw[size];
    };
} __attribute__((aligned(align)));
```

Member promotion keeps the runtime access path **identical** (`e.field`, `e._0.x` for a
nested aggregate field) — so `member_prefix` stays `""` and the **d2.1 navigator is
untouched**. The const path for an inline enum then **serializes to `_raw`** exactly as a
multi-view enum does (the existing `serialize_const_into` machinery, §0).

> **The inline `_raw` name MUST be collision-proof (Codex review, round 1).** Unlike the
> *multi-view* `_raw`, which is a member of the named wrapper `u` alongside only the
> *generated* `_tag`/`_v<idx>`/`_c<idx>` siblings (so a fixed `"_raw"` can never clash),
> the *single-view* `_raw` is **promoted** into `struct E`'s name scope **next to the
> user's sanitized payload field names** — and a Rust variant field literally named `_raw`
> sanitizes to `_raw` (`view_field_name`, `enum_emit.rs:227`) → a `duplicate member '_raw'`
> C error (compiler-confirmed). This is the **same hazard** the union `_raw` already guards
> against via `raw_member_name` (`layout_emit.rs:60`, seeded with the real member names).
> So the single-view raw member name must be generated through the **same reservation
> discipline** (seed the namer with the promoted view's field names), and
> `enum_raw_member` must become the **name-computing single source of truth** that both
> `emit_enum` (the definition) and the body side (the const designator) read — never a
> hardcoded `"_raw"`. (M1's `_c<idx>` `tag` sub-field, §3, needs the same.)

This:

- **closes #3 and #4 in full** — top-level `_Bool`, nested non-bool, **and the nested
  `_Bool` (#4b) M2-a could not** — because `_raw` is just bytes: the niche value lands
  at its offset regardless of the leaf's logical C type;
- **subsumes M2-a entirely** — no niche-cell retype, no nested-designator locator, no
  `niche_coinciding_field`; and it **removes** the inline-specific reconstruction
  special-casing (the inline `_raw` path is the same code as the multi-view `_raw` path);
- is **layout-neutral** — `_raw` is alignment 1 and full-object size; the anonymous
  union's size/align equal the view's, so `sizeof`/`_Alignof`/`offsetof` are unchanged
  (and still `_Static_assert`-guarded; promoted members are addressable by `offsetof`).

**Empirical verification (pinned flags `-std=gnu11 -fwrapv -Wall`, `-Wall`-clean):**

- `Option<bool>` (niche cell @0, `_Bool`): `(struct E){ ._raw = {2} }` → the runtime
  niche read (`memcpy` @offset 0) resolves `None`; `(struct E){ ._raw = {1} }` and the
  typed-field form `(struct E){ ._0 = 1 }` both read back `Some(true)` via the **promoted**
  `e._0` (union type-pun, sound under gnu11 — the same argument as the d2.2 multi-view
  `_raw`).
- **Nested `_Bool` (#4b)** `enum E { A(struct S{u8 x; bool b}), B }` (niche @offset 1):
  `(struct E){ ._raw = {0,2} }` → `disc == B`; `(struct E){ ._raw = {5,1} }` → the
  promoted nested access `e._0.x == 5`, `e._0.b == 1`. The case M2-a fundamentally
  cannot express, closed.
- All `_Static_assert(sizeof/_Alignof/offsetof …)` guards pass for both shapes (promoted
  members included).

### 2.1 Scope of the wrap (a spec-level call)

`_raw` is **needed** only for a *niche-encoded* single-view inline enum. Two options, to
settle in the spec:

- **Uniform (recommended):** every ≥1-view enum carries `_raw` (multi-view: the named
  `u._raw` today; single-view: the anonymous `_raw`). Matches the **d2.2 precedent**
  (every multi-view enum got `_raw`, not only const-bearing ones) and keeps one const
  rule. Cost: re-bless every single-view enum's text-assertion golden (text-only; layout
  guards unchanged). **Zero-view** enums (`Empty` / fieldless `Single { scalar: None }`)
  carry no `_raw` (no payload/niche const exists) — unchanged.
- **Selective:** wrap only niche-encoded single-view inline enums. Smaller re-bless, but
  adds a representation conditional and a second inline const code path. Rejected unless
  the re-bless surface proves large.

## 3. M1 confirmed unchanged (the multi-view tagged reloc case, #2-reloc)

The anonymous-union `_raw` does **not** subsume M1: a multi-view **tagged** enum const
with a relocation payload must carry **both** the tag and the relocation through **one**
union designator (a second designator overrides the first), and `_raw` (a `char[]`)
cannot hold an address constant. The existing `_tag` / `_v<idx>` views are separate
members (tag-only / payload-only), so neither carries both. M1 adds a **const-init-only**
typed full-object view per payload-bearing variant of a multi-view enum:

```c
struct { <tag field>; <payload fields…>; } _c<idx>;   /* fields at ABSOLUTE offsets */
```

fired **only when the payload carries a relocation** (the no-reloc case stays on `_raw`).
The runtime navigator (`_tag` / `_v<idx>`) is untouched (`_c<idx>` is written only by the
const path).

**Empirical verification:** `enum E { A(u8), B(&'static u32) }` (tag @0, payload @8,
size 16): `(struct E){ .u._c1 = { .tag = 1, ._0 = &Y } }` → the reloc lands in a typed
pointer slot (address-constant valid at static-init), and the runtime views read back
`tag == 1`, `*(_v1._0) == 0xCAFEBABE`, pointer identity `== &Y`. `offsetof(u._c1.tag)==0`,
`offsetof(u._c1._0)==8`, `sizeof==16`, `_Alignof==8` all assert.

- **Collision-proof sub-field name.** `_c<idx>`'s synthetic `tag` sub-field is a sibling
  of the variant's payload field names (a tuple field `_0`, or a sanitized struct-style
  name). A variant field literally named `tag` (`B { tag: T }` → `tag`) would clash — the
  same hazard `_raw`/`_pad` guard against. The `tag` sub-field name must be generated
  through the same reservation discipline (seed the namer with the payload field names).
- **Fires for `Direct` payload variants only.** A niche **untagged** reloc payload is
  already routed through `_v<untagged>` by d2.3a's **M1-lite**. A niche **tagged** variant
  carrying a relocation payload is an **external-rustc-invariant** non-case (Codex round 1):
  rustc's niche-filling encodes the *extra* variants — which it requires to be **fieldless**
  — into the spare bit-patterns of the **one** data-bearing (untagged) variant; a niched
  variant therefore carries **no payload**, let alone a relocation. The repo does **not**
  enforce this — the model structurally permits a variant with both fields and
  `tag_value: Some` (`layout.rs:115`) and the validator checks only indices/widths, not
  "niched variants are fieldless" (`layout_validator.rs:554`). So, **exactly like #5**
  (`04-…md` §2), this stays a **defensive fail-loud guard** grounded on the external
  invariant — *not* speculative handling code for an unreachable shape (implementing M1 for
  it would be over-engineering). The existing #2-reloc `EmitError::Unsupported` already
  covers it (a niche-tagged reloc is not a `Direct` variant, so M1 never routes it to
  `_c<idx>` — it falls through to the byte-image serializer, which rejects the reloc); d2.3b
  only **sharpens that message** to name the invariant. The spec records this disposition.

## 4. Revised d2.3b shape & code touchpoints

**d2.3b = M1 + anonymous-union `_raw`** (no M2-a, no named-union M2-b):

- `enum_emit.rs::emit_enum` — for a **single-view** enum, wrap the view in
  `union { struct { … }; unsigned char _raw[size]; };` (anonymous) + a `_raw` `offsetof`
  guard; the multi-view branch is unchanged. Add the M1 `_c<idx>` const-only view per
  payload-bearing variant of a **multi-view** enum (a new `build_views` output consumed
  only by `emit_enum` + the M1 navigator; the runtime `View` list is unchanged).
- `enum_emit.rs::enum_raw_member` — become the **name-computing single source of truth**:
  for a single-view inline enum, return the **collision-proof** bare name (the §2 reservation
  seeded with the promoted view field names — mirror `layout_emit::raw_member_name`, ideally
  a shared helper); for multi-view return `u.<rawname>` (the `u`-siblings are generated, so a
  fixed `_raw` is safe but compute it for uniformity); `None` for zero-view. `emit_enum` must
  spell the member through this exact function. Add a parallel `enum_variant_typed_view`
  navigator spelling `u._c<idx>.<field>` + `u._c<idx>.<tag>` for M1, with the `tag` sub-field
  name collision-proofed against the variant's payload field names.
- `body_emit.rs::enum_value_expr` — inline niche arm (`:3069-3096`): replace the
  `niche_coinciding_field` / retype / #3 / #4 logic with the uniform `_raw` serialization
  (a niched variant → `serialize_const_into` into `_raw`; the untagged / `Single`/
  fieldless cases keep their existing designator paths, which already work). Multi-view
  branch (`:3151-3155`): a **reloc** payload of a `Direct` variant → the M1 `_c<idx>`
  designator path; a **no-reloc** payload → `serialize_multiview_enum_value` (today).
- `body_emit.rs::enum_from_bytes` / `reconstruct_inline_enum_from_bytes` — the #3
  bool-niche bytes carve-out (`:2756`) → write `_raw` (inline enums now have it); the
  no-reloc inline byte image goes to `_raw` uniformly. The inline **reloc** byte image
  keeps the typed-field reconstruction (a `Byte::Reloc` cannot enter `_raw`).
- `niche_coinciding_field` and the inline-only non-reloc reconstruction become dead →
  remove (surgical: only as they are orphaned by the above).
- **Tests:** re-bless the affected enum text-assertion goldens (single-view enums gain
  the anonymous-union wrap; multi-view payload variants gain `_c<idx>`); add
  compile-AND-RUN fixtures for #2-reloc (`Direct` const with a reference), #3
  (`Option<bool> = None`), #4 (nested non-bool + nested `_Bool`). Keep the **mandatory
  post-close Codex soundness pass** ([[assessment-soundness-pass]], 7/7) — the byte-image
  / union-pun surfaces are exactly where it has caught latent miscompiles.

## 5. Soundness

Every emitted const remains a sound value or a hard `EmitError::Unsupported` — never a
silent miscompile. The inline `_raw` and the M1 `_c<idx>` both rely on the **same**
gnu11 union type-pun the locked d2.2 `_raw` already depends on (reads go through a typed
member of the same union object; the pinned flags carry no `-fno-strict-aliasing`). After
d2.3b the **const exit gate is gap-free for every reachable ENUM shape** — given the §2
collision-proof raw naming. **Correction (assessment, 2026-05-29):** the original
"every reachable enum/union shape" overstated it — a **reference-holding union**
(`static S: U = U { p: &Y }`, a `Byte::Reloc` over `Ty::Union`) is a *reachable* union
const that still fails loud (a union has no `_c<idx>` typed-view analog; §14 Unions was
scoped out), so it is a **documented residual**, not closed (tracked as a follow-on, like
`d2.3-bridge-dedup` for #6). The other remaining fail-louds are **external-rustc-invariant
defensive guards**, not shipped gaps: the niche-tagged-reloc sub-case in a genuinely
niched (non-untagged) variant (§3, rustc niche-fills only fieldless variants — the
*untagged* bytes-form reloc was a real gap, closed in the assessment as Fix #2), plus the
two retained guards #5 (union valtree, `04-…md` §2) and #6 (CMS pointee collision,
`04-…md` §3). The uniform `_raw` path introduces no silent-miscompile risk — every write
is bounds-checked. **The mandatory soundness pass (a Claude workflow + a cross-model Codex
pass) found one silent miscompile** — d2.3b's `_c<idx>` reloc emission outran the d2.2
`ConstMemoryStatic` re-typing pre-pass (`scan_const`/`scan_bytes` missed the enum-reloc
paths) → a `(const T*)&CMS` cast onto a `uint8_t[N]` CMS → strict-aliasing UB — **fixed in
the close** (the scan now covers the `Const::EnumValue` + multi-view byte-image paths; see
`decisions-and-state.md`, [[assessment-soundness-pass]]).
