### What d2.2 (`regseq-backends-14`) specifies

d2.2 lowers **every non-scalar `Const`** the bridge produces — `Const::Bytes`,
`Const::Aggregate` (reference carrier + typed valtree), multi-member `Const::EnumValue`,
and the `ConstMemoryStatic` byte-image static definitions — **soundly** under the pinned
`cc` flags (`-std=gnu11 -fwrapv -Wall`, **no** `-fno-strict-aliasing`,
`toolchain.rs:79-84`). Changes A–G (in `body_emit.rs` + `enum_emit.rs` + `mod.rs` + a
bounded §12/§13 Doc delta in `generic-c-backend.md`):

- **A — the `_raw` union member** (`enum_emit.rs`): add `unsigned char _raw[<size>];`
  to every **multi-view** enum's `union u`; const-init a fully-known enum value as
  `(struct E){ .u._raw = {bytes} }`; runtime reads stay **in-place** union accesses
  (gnu11 type-punning, sound). Layout-neutral (size/align `_Static_assert`s still hold).
  New navigator entry `enum_raw_member`. (The c2/d2.1 enum-emit text-assertion tests are
  **updated** for the added member.)
- **B — the `Const::Bytes` byte-image walker** (`body_emit.rs`): dispatch on the
  consumer `Ty` — scalars decode per `model.target.endian`; pointers via a
  `pointer_size` `Byte::Reloc(r)` run → `&<target>` / all-zero → typed null; non-enum
  aggregates slice per `FieldLayout.offset` in **source order** + recurse (ZST omitted);
  enums via `.u._raw = {bytes}` (multi-view, no-reloc) / inline; `Ty::Union` → d2.3.
  Array compound-literal type-names are **declarator-aware** (`types::declare(model,
  names, elem, "[<n>]")`, NOT a bare `<c_type(elem)>[<n>]` concat).
- **C — the reference carrier** (`body_emit.rs`): `Const::Aggregate([Reloc, Uint(meta)])`
  over `Ty::Ref(pointee)` — sized → reloc designator; `Str`/`Slice` → the §3.2 fat
  struct with `.data` via **`slice_data_ptr_type`** (`types.rs:299`, NOT hardcoded
  `const`) + `.len` `size_t`; `Dynamic` → vtable task.
- **D — the typed valtree aggregate** (`body_emit.rs`): `Tuple`/`Struct`/non-`u8`
  `Array` (source-order pairing, declarator-aware array type-name); enum + `Ty::Union`
  consumers → reject/d2.3.
- **E — multi-member `Const::EnumValue`** (`body_emit.rs`): **serialize** tag + scalar
  payload to a `layout.size` byte image (mirroring `assign_enum`, endian per target) →
  `.u._raw = {bytes}` for multi-view; **bool-niche multi-view works** via `_raw` (byte 2
  written directly; d2.1 discriminant read uses raw storage); reloc payload + inline
  bool-niche → d2.3.
- **F — `ConstMemoryStatic` re-typing pre-pass** (`mod.rs` + a new helper): a
  deterministic scan recovers each CMS's consumer pointee as a **backend-local
  `StorageTy` descriptor** — `Sized(TyId)` (→ `types::declare(ty, ident)`) or
  `Array{elem: TyId, count}` (→ the declarator-aware `types::declare(elem,
  "<ident>[<count>]")`) — referencing only **already-interned** element/pointee `TyId`s
  (the bridge interns `Slice(elem)` but NOT `Array(elem, meta)`), interning **nothing**.
  Banks 4/5 declare the CMS from it + reconstruct via Change B. Uniform: 1-byte `u8`/`i8`
  → `uint8_t[N]` (so `&str`/`&[u8]` unchanged + sound); `Ty::Char` (renders as
  `uint32_t`) → `uint32_t[count]`; else the real type. Content-hash dedup
  (`const_.rs:145-152`) collision → fail loud (d2.3).
- **G — bounded §12/§13 Doc delta** (`generic-c-backend.md`): reconcile the §12 `Bytes`
  row (currently the **unsound** flat `unsigned char[]`, lines 923–933) to the typed
  reconstruction reality + document the §13 `_raw` member. The **only** Doc edit; no
  `spec.md` change.

## Key decisions & rationale

(Durable list: `docs/discussions/generic-c-backend/decisions-and-state.md` — NOT yet
updated for d2.2; update it at d2.2 CLOSE per the established cadence.)

- **`Const::Bytes` scope = "all Bytes in d2.2"** (user-approved 2026-05-27, AskUserQuestion):
  cover reloc-bearing + non-`[u8;N]` typed reconstruction, not just the task-e `&str`
  critical path.
- **The d2.2 redesign (the load-bearing decision).** The FIRST draft used a synthesised
  packed struct for reloc-bearing `ConstMemoryStatic` + union-member designators for
  enum consts. Codex (round 1–2) found **two architectural soundness holes**: (1) the
  §13 union-of-views CANNOT be const-initialized with separate tag + payload — `.u._tag`
  and `.u._v<v>` are two members of the **same** union, and a later C designator
  **overrides** the earlier (they share offset 0), so the tag is lost (the runtime path
  works only because it uses *sequential statements*); (2) a `ConstMemoryStatic` of
  `uint8_t[N]` read through `(const T*)&X` for non-char `T` is **strict-aliasing UB +
  misaligned**. **Resolution (user chose "full clean redesign"):** the `_raw` union
  member (Change A) + re-type `ConstMemoryStatic` by consumer pointee (Change F).
- **`_raw` soundness is grounded** (Codex design consult + GCC docs): reading a union
  member other than the one initialized is gnu11 type-punning, **allowed** under
  `-fstrict-aliasing` **provided** the read is *through the union object* (the d2.1
  navigator reads in-place; it never takes `&x.u._v<v>.<f>` and dereferences a typed
  pointer later). Layout-neutral.
- **`ConstMemoryStatic` re-typing uses a backend-local `StorageTy` descriptor, NOT a
  model `TyId`.** The bridge interns `Slice(elem)` but not `Array(elem, meta)`, and
  `types::declare` needs a `TyId` — so the `Array{elem, count}` storage spells the C
  declaration **declarator-aware** via `types::declare(elem, "<ident>[<count>]")` (the
  way `Ty::Array` spells itself, `types.rs:118-120`), interning nothing. This also
  applies to Change B/D array compound-literal type-names (a bare `<c_type(elem)>[<n>]`
  is invalid C for an array-of-array / fn-pointer element).
- **Bool-niche is mostly RESCUED, not deferred wholesale.** d2.1 deferred all bool-niche
  `EnumValue` (the `(_Bool){2}` normalization). With `_raw`, a **multi-view** bool-niche
  const writes byte 2 directly (sound). Only the **inline** bool-niche case (`Option<bool>`
  — no union to `_raw` through) defers to d2.3.
- **A NEW task d2.3 is spawned** by the five carve-outs (relocation-payload enum/aggregate
  consts; inline bool-niche; CMS incompatible pointee types; union byte-image;
  typed-valtree union). The phase sequence becomes …→d2.1→**d2.2**→d2.3→e. (Record this
  in decisions-and-state at d2.2 close.)
- **`Ty::Union` is fully deferred to d2.3** (both `Bytes`-over-union and
  typed-valtree-union). `Const::Aggregate(Vec<ConstId>)` has no active `FieldIdx`
  (`pretty.rs:714-718` already rejects it); and a size-spanning union member is **not
  byte-preserving** for a padded aggregate member. Sound handling needs a union `_raw`
  member (a `types.rs`/`layout_emit.rs` change, out of scope) — so defer.
- **A bounded §12/§13 Doc delta IS in scope** (Change G). The §12 `Bytes` row currently
  describes the unsound flat `unsigned char[]` lowering; d2.2 corrects it. (This relaxes
  the prior tasks' "no Doc change" stance — legitimately, since the doc mis-described an
  unsound lowering.)
- **Soundness-pass discipline keeps paying off** ([[assessment-soundness-pass]]). The
  mandatory post-close Codex soundness pass is codified in d2.2's Quality Gate (it's
  layout-invariant-touching on TWO axes: byte-image field-offset slicing + CMS storage
  recovery/alignment).
