### The soundness finding (interior-NUL `&str` truncation)

A Rust `&str` (the template literal OR a `&str` value arg) is **length-prefixed and may
contain an interior `\0`**, but the emission goes through C's **NUL-terminated** `printf`
format string + `%s`, so an interior NUL **silently truncates** the output. `c_escape`
maps `\0`→`\000` into the C format string; `%s` stops at the first NUL. Verified (temp
probe, repo untouched): `info!("pre\0post={}", 7u32)` → `printf("[INFO] pre\000post=%u\n",
…)` → prints only `[INFO] pre`. Three paths: template + static `&str` value (both
detectable at emit), non-static runtime `&str` (NOT statically detectable). The 10 green
fixtures all use NUL-free text, so it stayed latent. **e is correct for all NUL-free text
(the milestone stands).**
