### The soundness bug fixed this session (`c8cadaa`)

**Bool-niche enum silent miscompile.** Triggering shape: `Option<bool>` (or any
`enum E { ..., V(bool), ... }` where the niche tag scalar is `Bool`). bool's invalid
bit patterns (`2..=255`) carry the niche; `None.tag_value = Some(2)`. Two compounding
faults on the niche path:
1. `render_tag_value(Bool, v)` collapsed any nonzero `v` to `"1"` (`body_emit.rs:2222`).
2. The niche cell was accessed through `c_type(Bool) = _Bool`, which C **normalizes** —
   `(_Bool){2}` stores `1`.

Net: across `Discriminant` (read), `SetDiscriminant` (write), `Aggregate::Enum` (write),
and the inline-niche `Const::EnumValue` (where `niche_coinciding_field` admitted `_Bool`
fields), `None` (niche byte 2) collided with `Some(true)` (byte 1). The 16 green compile-
and-run fixtures missed it because they only exercised pointer niches with `tag_value =
0` (representable as null). Fix: runtime niche cell accessed as the raw storage uintN +
const path rejects `_Bool` fields → d2.2.

## Key decisions & rationale

(Durable list: `docs/discussions/generic-c-backend/decisions-and-state.md`.)

- **`Const::EnumValue` split (user-approved 2026-05-27).** d2.1 handles single-member
  cases (inline enum + multi-view fieldless `Direct` variant); payload-bearing multi-
  view EnumValue defers to d2.2 (it needs the same multi-member construction d2.2
  owns). The inline-niche niched variant ONLY lowers in d2.1 when the niche cell
  coincides exactly with one inline scalar field (`offset` + `ty` match) AND that
  field's logical C type doesn't normalize raw bit patterns (post-soundness-pass:
  `Bool` is normalization-lossy, defers to d2.2). The soundness-pass narrowing of
  "non-coinciding niche cell" and the post-close addition of "Bool-normalization
  lossy" both flow from the same principle: a const compound literal can't bypass
  the field's logical C type, so any value that doesn't round-trip through it must
  defer.
- **Niche cell access — raw storage uintN, not the logical scalar C type
  (`c8cadaa`).** The niche tag is fundamentally a raw bit pattern (`tag_value mod
  2^scalar_width`), so the cell is read/written/compared as an unsigned integer of
  the scalar's storage width — never the logical C type, which can normalize
  (`_Bool`) or constrain (an invalid `char`) the value. The pinned cc flags are
  `-std=gnu11 -fwrapv -Wall` with **no** `-fno-strict-aliasing`
  (`toolchain.rs:84`), so a reinterpreting pointer cast was never an option;
  memcpy is the codebase's established aliasing-safe idiom.
- **Shared `enum_emit` navigator** (the central correctness lever for d2.1).
  `enum_emit.rs` factors `member_prefix(views, member)` + `enum_variant_field` +
  `enum_tag` as the single source of truth for the inline-vs-`union u` collapse +
  the `_tag` / `_v<idx>` member names + payload field names. BOTH `emit_enum` (the
  definition) and the body accessors call them — so the access path cannot drift
  from the emitted member path or the `offsetof` guards. The d2 `field_c_name`
  lesson generalized.
- **Niche `Discriminant` lowered at the assign site (not via a stmt-expr).** The
  cell needs an aliasing-safe memcpy-to-temp; lowering it at the assign site
  (memcpy → temp → ternary, mirroring the array / `*WithOverflow` / `Transmute`
  precedent) avoids introducing GNU statement-expressions. Direct/`Single` keep a
  pure-expression ternary over the `_tag` view read.
- **`Empty` enum is uninhabited** → structural/unreachable coverage only, never a
  runtime value/match fixture (caught in round 1 of the Codex spec review).
- **Soundness-pass discipline keeps paying off** ([[assessment-soundness-pass]]). d1
  green → soundness pass found bugs. d2 green → soundness pass found bugs. d2.1
  green (123 backend unit + 16 runner compile-AND-RUN fixtures covering Direct /
  Niche / Single-None / Single-Some / repr-int) → soundness pass found bugs. The
  mandatory pass is now codified in d2.1's Quality Gate; d2.2 should keep it.
