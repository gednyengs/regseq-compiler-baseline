## E1000 Status

## Stage 1 — Basic E1000 (functional, not performant): COMPLETE

Scope: one TCP flow round-trips. PCI bind, ring DMA, ISR-driven RX, busy-poll TX, broadcast-and-unicast filtering, zero stats.

| #            | Feature                                       | What it does                                                                                                                                                                                                                                                         |
| ------------ | --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1            | PCI vendor/device match                       | Compiler emits a PCI device-ID table from the driver's `compatible = ["intel,82540em", "pci8086,100e"]` list; the kernel's PCI subsystem binds the driver when a `0x8086:0x100E` device appears on the bus.                                                          |
| 2            | BAR0 ioremap + bus-master enable              | Compiler maps the device's 128 KB control region (BAR0) into kernel virtual address space and asserts the PCI command register's *Bus Master Enable* bit so the device is permitted to issue DMA requests.                                                           |
| 3            | Single-vector legacy INTx IRQ                 | Compiler binds one ISR to the device's legacy interrupt line; the body claims the IRQ only when `ICR.INT_ASSERTED` is set, so the driver cooperates with shared-IRQ peers on the same line.                                                                          |
| 6            | Global reset + EEPROM auto-load wait          | `Lifecycle::init` writes `CTRL.RST = 1` and polls until the bit self-clears; the compiler is contracted to additionally wait for `EECD.AUTO_RD` so RAL0/RAH0 hold a valid hardware MAC by the time `init` returns.                                                   |
| 7            | Link auto-negotiation                         | `Network::open` sets `CTRL.SLU` (Set Link Up) and `CTRL.ASDE` (Auto-Speed-Detect Enable); the integrated PHY then negotiates 10/100/1000 + half/full duplex with the link partner without further driver involvement.                                                |
| 8 (partial)  | Initial link-state observation                | Driver reads `STATUS.LU` once at `open` and publishes the result via `set_link_state`. Subsequent transitions are not yet reported — the LSC IRQ source is unmasked but the ISR does not call `set_link_state` from it.                                              |
| 9            | Coherent TX/RX descriptor rings               | Compiler allocates two DMA-coherent regions sized `entry_size × count`, populates `DmaRegion<LegacyTxDesc>` / `DmaRegion<LegacyRxDesc>` accessible from both CPU and device with no manual cache management, and frees them on deinit.                               |
| 10           | Streaming-mapped packet buffers               | `regseq::dma::map(buf, dir)` returns a `DmaMapping` carrying the bus-physical address that the body writes into a descriptor's `buffer_addr`. The mapping wraps the OS's per-direction cache/bounce-buffer dance and unmaps via RAII drop on completion.             |
| 11           | IC-10 barriers at descriptor / doorbell sites | Compiler emits the target's `dma_wmb()` between descriptor writes and the tail-doorbell write, and `dma_rmb()` between observing `STA.DD` and reading the descriptor's payload fields, so the device sees a coherent ring and the CPU sees coherent completion data. |
| 12           | 64-bit DMA addressing                         | `#[rseq::dma_region(dma_mask = 64)]` configures the DMA mask up-front and the legacy descriptor's 64-bit `buffer_addr` field is used in full, so packet buffers anywhere in physical memory can be mapped without bouncing.                                          |
| 13           | Legacy descriptor write + TDT doorbell        | `start_xmit` writes a `LegacyTxDesc` (buffer addr, length, CMD = `EOP \| IFCS \| RS`) into the next ring slot and writes the slot index into `TDT`; the device reads from `TDH..TDT` and DMAs each packet onto the wire.                                             |
| 14           | TX completion via DD-bit busy-poll            | After ringing the doorbell the body yields and re-reads the descriptor's status byte until `STA.DD` is set, mirroring the Zephyr corpus driver pattern. Correct but blocks the calling task on every packet.                                                         |
| 16 (partial) | Backpressure: TX queue stop                   | When the TX ring is full `start_xmit` calls `flow_control(TxOff)` to stop the OS-side queue and returns `Busy`. Re-enable happens implicitly on the next successful `start_xmit` rather than from a TX-completion path.                                              |
| 19           | Pre-fill RX ring + DD-bit drain in ISR        | `Network::open` allocates and maps one packet buffer per RX descriptor and points each `buffer_addr` at it; the ISR walks the ring while `STA.DD` is set, hands each packet off via `deliver_packet`, refills the slot, and advances `RDT`.                          |
| 21 (partial) | RX coalescing at fixed default                | `RDTR` is programmed once at `open` with a fixed default value so the device may briefly batch completed descriptors before raising `RXT0`. No per-deployment tuning; `RADV` is left at zero.                                                                        |
| 23           | Primary MAC from RAL0 / RAH0                  | Driver reads the 6-byte hardware MAC out of the Receive Address Registers populated by EEPROM auto-load, and reports it to the OS via `Network::open`'s implicit MAC binding.                                                                                        |
| 25           | Broadcast accept (`RCTL.BAM`)                 | `Network::open` programs `RCTL.BAM = 1` so the device accepts frames addressed to `ff:ff:ff:ff:ff:ff` in addition to the primary unicast MAC. Required for ARP and DHCP to function.                                                                                 |
| 33           | `get_stats` stub                              | `Network::get_stats` returns `NetStats::default()` (all zeros), which is enough to satisfy the trait contract. The OS reports no traffic counters; `ifconfig` shows zeros.                                                                                           |
| 37           | Diagnostic logging                            | `log_info!` / `log_warn!` / `log_error!` macro sites at notable bring-up and error paths; compiler lowers each call to the OS-native logger (`dev_err` on Linux, `LOG_ERR` on Zephyr) with the device-context prefix already prepended.                              |
| 38           | ITR programmed at fixed default               | `ITR` is written once at `open` time with the variant-pin default (8000 in 256-ns units, ≈ 31 µs minimum spacing between IRQs), capping the per-second IRQ rate. Single value, no per-deployment override.                                                           |

## Stage 2 — Medium E1000 (more complete, not yet performant): PARTIAL

Scope: production-shaped admin + filtering + flow control + statistics + reliability. Inherits all of Stage 1.

| #         | Feature                                                  | What it does                                                                                                                                                                                                                                                                           |
| --------- | -------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 4         | MSI with INTx fallback                                   | Compiler tries to allocate a single MSI vector first and falls back to legacy INTx if the bus refuses. The body's ISR `INT_ASSERTED` gate works in either mode, so no body change is needed beyond `#[rseq::interrupt(msi = true, fallback_legacy = true)]`.                           |
| 5         | Suspend / resume (`PowerManagement`)                     | `suspend` masks IRQs, disables RX/TX, and releases all streaming maps so the device is quiescent before the bus drops power. `resume` re-runs the bring-up against the same MAC and ring shapes; in-flight packet state is not preserved across the transition.                        |
| 8 (full)  | Link-state change via LSC IRQ                            | ISR observes `ICR.LSC`, re-reads `STATUS.LU`, and publishes the new state via `set_link_state(LinkState::Up/Down)`. A cable unplug/replug now propagates to the OS carrier-on/off path immediately instead of being missed.                                                            |
| 15        | TX completion via TXDW IRQ + cleanup loop (replaces #14) | `ICR.TXDW` triggers the ISR to walk the ring from `last_tx_clean`, drop each completed slot's `DmaMapping` (RAII unmap), and stop at the first not-done slot. The S1 busy-poll path is removed; `start_xmit` no longer blocks the caller.                                              |
| 16 (full) | TX queue wake from cleanup                               | When the cleanup loop frees enough slots that the ring is no longer full, the ISR calls `flow_control(TxOn)` to wake the OS queue. Pairs with the `TxOff` site in `start_xmit` for full backpressure handling.                                                                         |
| 21 (full) | RX moderation tunable                                    | `RDTR` (relative delay) and `RADV` (absolute cap) are exposed as `#[rseq::param]` knobs with cross-OS defaults; deployments can re-tune for latency-versus-throughput preferences without rebuilding the driver.                                                                       |
| 24        | `set_mac_address`                                        | Reprograms RAL0/RAH0 with a new unicast MAC inside an `ordered!` block that disables RX, writes the new value, and re-enables RX, so no half-programmed RAR0 can match a frame mid-update.                                                                                             |
| 26        | Promiscuous mode                                         | `set_rx_mode` reads the OS's current rx-mode state via `regseq::net::current_rx_mode()`; when promiscuous is requested, programs `RCTL.UPE = 1` and `RCTL.MPE = 1` so every frame on the wire is delivered up the stack.                                                               |
| 27        | Multicast hash filter (MTA[128])                         | For each multicast group the OS subscribes to, the body hashes the MAC into one of 4096 buckets and sets the corresponding bit across MTA[0..127]. Frames matching a set bit are accepted without consuming a full RAR entry. *Gated on the array-of-registers DSL extension.*         |
| 28        | Multi-MAC unicast (RAR[1..15])                           | Up to 15 additional unicast MACs may be programmed beyond the primary RAR0; useful for VRRP/HSRP secondaries, MAC-VLAN, and bonded-interface aliases. *Gated on the array-of-registers DSL extension.*                                                                                 |
| 29        | VLAN filter (VFTA + RCTL.VFE)                            | `RCTL.VFE = 1` enables hardware VLAN filtering; the 4096-bit VFTA[128] tracks the VLAN IDs the OS has subscribed to. Off-VLAN frames are dropped by the NIC before reaching the host stack.                                                                                            |
| 30        | `change_mtu`                                             | `Network::change_mtu(new)` validates against the variant-pin upper bound (1500) and the Ethernet minimum (60). Within the standard range no register update is needed because the 2 KB receive buffer already accommodates any MTU ≤ 1500.                                             |
| 31        | RX flow control                                          | `CTRL.RFCE = 1` plus FCRTL/FCRTH thresholds tells the device to honor incoming `PAUSE` frames by stalling its TX while a peer is congested. Required to claim 802.3x flow control on the variant pin.                                                                                  |
| 32        | TX flow control                                          | `CTRL.TFCE = 1` plus FCAL/FCAH/FCT/FCTTV programmed to standard 802.3x values lets the device emit `PAUSE` frames when its RX FIFO crosses the high-water mark, throttling a busy peer instead of dropping.                                                                            |
| 34        | Read-clear stats one-shot at init                        | `init` reads every statistics register once. The 82540EM clears each counter on read, so subsequent `get_stats` calls return only traffic that occurred during this driver's lifetime — not whatever was sitting in the registers from a prior owner or firmware.                      |
| 35        | Always-on counters                                       | `get_stats` reads GPRC / GPTC (good packets) and GORC / GOTC (good octets) and reports them as `rx_packets` / `tx_packets` / `rx_bytes` / `tx_bytes` in `NetStats`. Required for `ifconfig`-style traffic visibility.                                                                  |
| 36        | Error counters                                           | `get_stats` additionally reads CRCERRS, RXERRC, MPC and reports them as `rx_errors` and `rx_dropped`. Used by network monitoring tools and host-side flap detectors.                                                                                                                   |
| 39        | ITR / RDTR / RADV runtime tunables                       | Three `#[rseq::param]` knobs let an operator override moderation defaults at module load time (`module_param` on Linux) or build time (Kconfig on Zephyr) without recompiling the driver.                                                                                              |
| 41        | TX-hang watchdog                                         | A `#[rseq::timer]` periodic timer scans `TDH` versus `TDT`; if the head has not advanced in N ticks while the ring is non-empty, the body logs a warning and resets the TX engine. Catches lost TXDW interrupts and TX-side device hangs that would otherwise wedge the queue forever. |
| 42        | RXO recovery + dropped-packet accounting                 | When the ISR observes `ICR.RXO` (receive overrun), the body bumps `rx_dropped` and re-arms the RX engine if it has stopped. Without this a transient back-pressure burst can wedge RX silently.                                                                                        |

## Stage 3 — Performance E1000 (claim-bearing optimizations): NOT STARTED

Scope: every feature here is paired with a measured workload result on the comparison axes; without a speedup the row does not belong in this stage. Inherits all of Stage 1 + 2.

| #   | Feature                                    | What it does                                                                                                                                                                                                                                                                                                                                     |
| --- | ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 17  | TX hardware checksum offload               | `start_xmit` reads `NetPacket.checksum_intent` (set by the OS adapter from `skb->ip_summed` on Linux, `m_pkthdr.csum_flags` on FreeBSD); when offload is requested the body sets `TXD_CMD_IC` plus the descriptor's `cso` / `css` byte offsets, and the device computes the IP/TCP/UDP checksum during DMA — saving a per-packet CPU pass.       |
| 18  | TX cleanup batching with budget            | Instead of unbounded cleanup in the ISR, `clean_tx` takes a `budget` parameter and runs at most that many slot reclaims per call (NAPI-style). Bounds worst-case ISR latency under heavy bidirectional load and prevents one direction from starving the other.                                                                                  |
| 20  | RX hardware checksum offload               | `RXCSUM.IPOFL = 1` and `TUOFL = 1` instruct the device to compute the IP/TCP/UDP checksum during receive DMA. The descriptor's `csum` field carries the result and `STAT.IXSM/IPCS/TCPCS/UDPCS` flags drive `NetPacket.checksum_status`, which the OS stack consumes to skip its own software checksum — saving CPU on every received packet.    |
| 22  | Deferred RX servicing (NAPI / DPC / iflib) | `service_rx` is annotated as a deferred-work site; the compiler lowers it to NAPI poll on Linux, DPC on Windows, iflib group taskqueue on FreeBSD, and falls back to inline ISR servicing on Zephyr. Bounds work-per-IRQ, lets the host scheduler interleave RX processing with other work, and is the single largest throughput win of Stage 3. |
| 40  | Workload-driven moderation tuning          | ITR / RDTR / RADV defaults are no longer baked into the spec. The evaluation harness sweeps the moderation surface across `iperf3` (throughput), `ping` (latency), and a small-packet stress workload, and the spec records the operating-point recommendation as part of `e1000-experiment-methodology.md` — turning "tunable" into "tuned".    |
