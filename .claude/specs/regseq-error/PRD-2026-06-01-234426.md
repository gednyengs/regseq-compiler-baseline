# PRD — RegseqError (generic-C backend, Phase 2)

## Problem Statement

A Regseq driver spec needs an OS-agnostic way to express **authored *semantic*
failures** (`RegseqError`) and have them surface to the surrounding OS/host as a
**native error code** at the one place where authored code hands control back to OS
scaffolding.

Today, from each consumer's view:

- A **driver-spec author** can already write `RegseqError` and `Result<(), RegseqError>`
  and have them lower structurally (fieldless enum + niche `Result` emit for free), but
  there is **no mechanism that maps a returned error to a host-native code** — so the
  failure is invisible to whatever calls the driver.
- The **host/OS scaffolding** (in generic-C, the generated `int main(void)`) always
  returns `0`. An `Err(...)` returned from `regseq_main` is silently discarded; the
  process exit status cannot distinguish success from an authored failure.
- The **codegen-coverage runner** and **`cargo-regseq --emit bin`** have no oracle for a
  *specific* exit-code value (pass ⇒ exit 0; panic ⇒ non-zero with golden stderr but no
  specific code), so even if a mapping existed it could not be asserted end-to-end.

The roadmap (Phase 2) calls for the **first concrete instance of the per-target
error-mapping table**, proven on the host — not merely a type definition.

## Solution

Build a **real, end-to-end-exercised commit point** on the host target:

- At the **`regseq_main` → `main` crossing** (the one authored→host-scaffolding boundary
  in generic-C; a stand-in for the still-unbridged trait-callback boundary), the backend
  maps a returned `RegseqError` variant to a **libc `<errno.h>` symbolic constant** and
  **propagates it as the process exit code**. `Ok(())` → exit 0. Inside authored code,
  `RegseqError` stays an ordinary enum with no special handling.
- The error enum is identified **purely by the attribute**
  `#[rseq::framework_type("regseq-error")]`; the bridge records a new
  `AttrData::FrameworkType`; the **per-target errno table lives in the backend**, keyed
  by variant **name**.
- The harness gains a **symbolic `expected.exit`** oracle (e.g. `"ETIMEDOUT"`), resolved
  to a numeric on the fixture's **own libc** at run time — so the emitted `.c` stays
  symbolic/deterministic and there is no host-libc coupling in any manifest or golden.

The authoritative formal detail lives in the GRILL contracts **C01–C05**; this PRD is the
behavioral summary.

## Requirements

R01. As a **driver-spec author**, I want to write `fn regseq_main() -> Result<(),
RegseqError>` and have a returned `Err(variant)` surface to the OS as the corresponding
native error code, so the host scaffolding observes the authored failure. *(D02, D03,
C03)*

R02. As a **driver-spec author**, I want `RegseqError` used *inside* authored code
(construct / `?` / `match` / reclassify one variant to another / nested helpers) to lower
as ordinary MIR with **no special handling**, so only the boundary crossing is treated
specially; an error created and fully consumed inside authored code (function returns
`Ok`) is never mapped. *(D02, I01)*

R03. Given an entry `fn regseq_main() -> Result<(), RegseqError>`, when the TU is emitted,
the backend must emit a thin **adapter** that reads the `Result`/`RegseqError`
discriminant and returns the mapped errno, and the generated `main` must return that errno
as the process exit code. *(D09, C03)*

R04. Given an `Ok(())` return at the entry, the process must exit `0`. *(D03, C02, C03)*

R05. Given the existing unit-void entry `fn regseq_main() -> ()`, emission must remain
**byte-identical** to today (exits 0, current shim unchanged) — no regression to any
existing golden. *(D09, C03, I02)*

R06. As the **bridge**, I want to recognize `#[rseq::framework_type("regseq-error")]` on
an enum item and record `AttrData::FrameworkType(FrameworkType::RegseqError)` on that
item, so the backend can identify the error enum without path/crate coupling. *(D05, C05)*

R07. The backend must map each **known** `RegseqError` variant to its host errno **symbol**
by `VariantLayout.name` (declaration order is not load-bearing) per C02, emit the **symbolic**
constant in the C (`return EINVAL;`), and emit the `<errno.h>` include **demand-driven**
(only when the mapping is emitted). *(D04, D05, C02)*

R08. Given a RegseqError-marked enum carrying a variant **absent from the backend table**,
emission must **fail loud** (not silently degrade to `EIO`); the runtime adapter's
`default: EIO` exists only as defense against a corrupt/impossible discriminant. *(D05,
I05, C02)*

R09. Given an entry shape other than the two supported forms — i.e. non-unit `Ok`
(`Result<T,_>`, `T != ()`), an `Err` enum **not** marked `regseq-error`, an entry taking
arguments, or a manifest-custom `entry` combined with an error-returning signature —
emission must **fail loud at emit** with a clear diagnostic. *(D08, D09)*

R10. As the **codegen-coverage runner** and **`cargo-regseq --emit bin`**, I want an
optional **symbolic** `expected.exit` manifest field (a libc errno identifier, or `0`),
resolved to a numeric on the **same C toolchain/libc** used to compile and run the
fixture, asserted against the process exit code — so error mapping is verified end-to-end
without host-libc coupling. *(D03, C04)*

R11. For a **nonzero** expected exit, the oracle must require `exit_code ==
Some(resolved_numeric)` **AND empty stderr** (so a `panic=abort` SIGABRT cannot masquerade
as a clean errno return); `stdout` is still byte-compared to `expected.stdout`; pass-mode
generalizes from "exit == 0" to "exit == resolved(`expected.exit`)" with default `0`;
`expect = panic` is unchanged. *(D03, C04, R10)*

## Invariants & Contracts

I01. The mapping is applied **only** at the `regseq_main` → `main` crossing; inside
authored code `RegseqError` is an ordinary fieldless enum, and a `RegseqError` not crossing
the boundary is never mapped. *(D02)*

I02. Existing **unit-void** entry emission is byte-identical; every existing golden `.c`
stays unchanged. *(D09; see C03)*

I03. Emitted C error codes are **symbolic** libc constants; **no host-libc numeric** appears
in any emitted `.c`, any golden, or any manifest (numerics are resolved at run time on the
fixture's libc). *(D03, D04; see C04)*

I04. The variant→errno mapping is keyed by **variant name**, not declaration order. *(D05;
see C02)*

I05. A marked variant **not** present in the backend table is a **fail-loud emit error**;
the runtime `default: EIO` is defense-only and never a silent mapping for a
known-but-unmapped variant. *(D05; see C02)*

I06. `RegseqError` MUST NOT implement `std::error::Error` and MUST NOT depend on `Display`.
*(see C01)*

I07. The authored carrier is `core::result::Result<T, RegseqError>`; there is no custom
`RegseqResult<T>`. *(see C01)*

I08. `AttrData` remains **append-only** — the feature only adds `FrameworkType`. *(D05; see
C05)*

I09. The codegen-coverage **gate stays `pass`** and the determinism bar holds: goldens are
byte-stable and the emitted mapping is symbolic. *(O2; project memory
[[codegen-coverage-gate-pass]], [[golden-c-emit-process-determinism]])*

Exact formal contracts: type surface **C01**, backend errno table **C02**, boundary
emission shape **C03**, harness oracle **C04**, bridge recognition **C05** (GRILL is
authoritative).

## Implementation Decisions

**Model (`regseq-model`).** Append a new `AttrData::FrameworkType(FrameworkType)` variant
with `FrameworkType::RegseqError` (room for future framework types) to the append-only
`AttrData` enum. *(D05, C05)*

**Bridge (`regseq-driver`).** Add a recognizer for `#[rseq::framework_type("regseq-error")]`
on enum items — via `get_attrs_by_path(def_id, [rseq, framework_type])`, extract the
dash-form string, record the `AttrData` on the enum's `ItemId` (idempotent) — mirroring the
diag-log `record_log_intrinsic` recognition precedent. *(D05, C05)*

**Backend (`regseq-backends`, generic-C).** `emit_generic_c(model)` resolves the
default-suffix `regseq_main` entry from the model (existing `entry_c_symbol` suffix logic),
inspects its return type, and: for `Result<(), RegseqError>` emits the TU **adapter**
(reads the Result/RegseqError discriminant per §13, switches by `VariantLayout.name`,
returns the mapped errno) + a **demand-driven `<errno.h>`**; for unit-void uses the existing
void shim unchanged; for any other shape fails loud. `generate_main_c` is extended to emit
the int-returning shim (`int main(void){ return <entry>__regseq_exit(); }`) when the entry
is error-returning. The **per-target errno table lives in the backend** (C02), keyed by
variant name; an unknown marked variant is rejected at emit. *(D02, D04, D05, D08, D09, C02,
C03)*

**Harness (codegen-coverage runner + `cargo-regseq --emit bin`).** Add an optional symbolic
`expected.exit` field to `manifest.toml`; resolve the symbol to a numeric on the fixture's
own libc; assert the process exit code (with the empty-stderr guard for nonzero) while
still byte-comparing stdout. **Both** consumers of the entry shim apply C03/D09. *(D03, C04;
`crates/regseq-driver/src/emit.rs`)*

The C02 table mechanism is deliberately shaped so future Linux/Zephyr backends and the
eventual trait-callback lowering reuse it without changing this phase. *(D02, D05)*

## Failure & Recovery

- **Unknown marked variant** → the backend **fails at emit** (no C produced); the build
  surfaces a clear diagnostic. I05 holds: the runtime `default: EIO` never silently absorbs
  a known-but-unmapped variant. *(D05, R08)*
- **Unsupported entry shape** (non-unit `Ok`, unmarked `Err`, entry with args,
  custom-entry-with-error-return) → **fail loud at emit** with a diagnostic naming the
  rejected shape; no degraded code path. *(D08, D09, R09)*
- **Runtime corrupt/impossible discriminant** → the adapter's `default: EIO` is the only
  fallback, and exists solely as defense; it is unreachable for any known variant. *(D05,
  C03)*
- **`panic=abort` / SIGABRT at run time** → produces a non-zero exit **with stderr**; the
  oracle's empty-stderr requirement for a nonzero expected exit prevents a signal death from
  masquerading as a clean errno return. The `expect = panic` oracle is unchanged. *(D03,
  C04, R11)*

On every failure path, the determinism and gate invariants (I02, I03, I09) must still hold:
a feature change must not perturb existing goldens, and the gate must remain `pass`.

## Conformance

- **`docs/discussions/regseq-error/regseq-error-spec.md`** is the design baseline but is
  treated as **non-final / partly stale** (D06). Intended deviations: §8's "define
  `RegseqError` in the facade crate" mandate is **relaxed** — identity is purely the
  attribute, location-independent (D06); the spec's callback carrier
  `Result<(), RegseqError>` **is** honored (D08). §6 carries the dated **G01** addendum.
- **libc `<errno.h>`** of the host target governs the numeric resolution (D04). The variant→
  symbol table (C02) mirrors the seed taxonomy's Linux column
  (`current-synthesis.md:268-278`); all chosen symbols survive 8-bit exit masking (Codex-
  confirmed).

## Testing Decisions

- **Test external behavior**, not adapter internals: the **process exit code** and the
  **fail-loud diagnostics** are the behavioral oracles; the golden `.c` snapshot is the
  determinism oracle (byte-stable, symbolic).
- **Seams** (confirmed from the GRILL Context, not re-asked):
  - **Backend unit test** (pure function): exhaustive variant-name→errno table over all
    rows of C02 + entry-shape classification.
  - **Codegen-coverage e2e fixtures**: bridge → model → emit C → host `cc` → run → assert
    the symbolic `expected.exit` oracle (C04) + golden `.c`.
  - **Negative tests (required, D08)**: fail-loud diagnostics for each rejected entry shape
    and for the unknown-variant case.
- **Fixtures (D07):** `Ok → 0`; a couple of distinct `Err` variants (e.g. `EINVAL`,
  `ETIMEDOUT`); one weaving `?` propagation from a nested helper **and** a `match`/reclassify
  (one variant → another) before escaping. The full 9-variant table is covered by the unit
  test, not ~10 near-duplicate fixtures.
- **Modules under test:** `regseq-backends` (unit), the full pipeline via the
  codegen-coverage runner, and `regseq-driver` emit (`--emit bin`).
- **Verification methods:** run + assert exit code (+ empty-stderr guard); `--bless` then
  re-run for byte-stable goldens; gate stays `pass`; single-threaded test runs where the
  process-global interner matters.
- **Prior art:** diag-log recognition tests; the `b4_enums` fixture (all enum shapes); the
  isolated `corpus_e2e.rs` snapshot pattern (memory [[golden-c-emit-process-determinism]]);
  the codegen-coverage runner `--bless` flow; the demand-driven helper-block machinery
  (commit `21f7842`).

## Assumptions

- **A1.** The chosen errno symbols all survive 8-bit process-exit masking. `blocking: false`
  (Codex-confirmed).
- **A2.** The hosted generic-C target's libc provides `<errno.h>` with the C02 symbols.
  `blocking: false` (verified reality; roadmap "no *kernel* error space" ≠ no libc errno).
- **A3.** The §13 discriminant-read machinery can be reused or synthesized for the adapter
  (reusable expression helper vs synthesized model-level adapter body — **O3**).
  `blocking: false`.
- **A4.** `emit_generic_c` can resolve the default `regseq_main` entry instance from the
  model via the existing `entry_c_symbol` suffix logic (D09 confidence Medium-High).
  `blocking: false`.
- **A5.** Spec §8's facade-crate mandate is stale and may be relaxed (asserted by the user,
  D06). `blocking: false`.

An implementing agent should treat A3 and A4 as the items most likely to need adjustment.

## Out of Scope

- **Trait-callback bridging** (`Lifecycle`/`PowerManagement`/`Serial`) and true
  callback-exit lowering — Phase 3+; the entry is their stand-in for now.
- **Intrinsic-/construct-local error enums** (`ClockError`, `PollError`, …) and
  `From<Local> for RegseqError` — deferred; **G01** makes these (or native passthrough)
  mandatory for native-backed wrappers/intrinsics once bridged.
- **`#[derive(RegseqErrorMap)]`** helper macro — deferred.
- **Second fallible carrier / custom `RegseqResult<T>`** — rejected; baseline uses
  `core::result::Result`.
- **Wrapper native-failure boundary policy** (Models A/B/C) as a full resolution — deferred;
  **G01** fixes only the default direction (native/opaque) so no future phase can silently
  bake in a lossy collapse.
- **Linux/Zephyr per-target errno tables** — future per-target backends; C02 is their first
  precursor.
- **`Display` / `std::error::Error`** on `RegseqError` — explicitly excluded.
- **Non-unit `Ok`, entry arguments, non-RegseqError `Err` at the entry** — rejected (D08,
  fail-loud).
- **Manifest-custom `entry` for an error-returning entry** — deferred this phase (D09;
  default `regseq_main` suffix only).
- **Promoting `RegseqError` into the `regseq` facade crate** — not required (D06).

## Further Notes

*Non-normative context only.*

- **Forward guardrail G01** (GRILL §Architectural Guardrails) binds **Phase 3+**, not this
  entry-only phase: native-backed operational failures in wrappers/intrinsics must default
  to native/opaque propagation or construct-local error types that map upward, and must not
  be auto-collapsed into `RegseqError` unless the failure is an authored semantic condition.
  It is recorded redundantly in the roadmap (Phase 3+) and the spec §6 addendum. This phase
  bridges no wrappers/intrinsics/callbacks, so the lossy-collapse hazard is **not active**
  here.
- **Value framing (Axis-A debate, converged):** `RegseqError`'s portability value is a
  **common authored vocabulary + a uniform boundary/callback contract + a common diagnostic
  taxonomy**, *not* identical runtime behavior across OSes. Collapsing targets reduce variant
  distinctions to success/fail, keeping per-site info only for diagnostics (hence
  `GenericFailure` and `HardwareError` both → `EIO` is acceptable).
- **The entry is a stand-in** for the real (unbridged) trait-callback boundary; the C02
  table built here is the reusable piece future callback lowering + Linux/Zephyr backends
  plug into.
- **Non-blocking open items for to-plan** (all `blocking: false` in the GRILL): **O2**
  coverage-matrix row taxonomy + ledger wiring; **O3** adapter mechanism + symbol naming +
  symbol→numeric resolution method; **O4** home of the demand-driven `<errno.h>` include;
  **O5** a further bounded Codex review runs at the to-plan stage. None blocks this PRD.
