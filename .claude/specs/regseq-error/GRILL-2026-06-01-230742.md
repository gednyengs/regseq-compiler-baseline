# GRILL — RegseqError (generic-C backend, Phase 2)

## Context

### Problem & goal
Land **RegseqError** for the generic-C backend (roadmap Phase 2). RegseqError is
the OS-agnostic semantic error space for authored fallible Regseq code; its
purpose is to be **mapped to OS-specific error codes during lowering**. The goal
of this phase is to make that real and **exercised end-to-end on the host
target** — not merely a type definition.

### Decisive codebase reality (verified, not assumed)
This reframes the whole feature; every decision rests on it.

- **The type already lowers for free.** The generic-C backend has a complete enum
  lowering contract (`docs/discussions/regseq-model/generic-c-backend.md` §13,
  §9.8 fieldless `Direct`, §9.9/§13 niche). `RegseqError` is a fieldless enum and
  `Result<(),RegseqError>` is a niche enum — both already emit. Backend enum emit:
  `crates/regseq-backends/src/generic_c/enum_emit.rs:61`; discriminant read
  `body_emit.rs:856`; `SetDiscriminant` `body_emit.rs:1006`. Fixture `b4_enums`
  already exercises all enum shapes.
- **C-ABI admissibility is boundary-scoped.** `crates/regseq-driver/src/bridge/fnsig.rs:51`
  computes C-ABI lowering **only when `abi == FnAbi::C`**. Internal **Rust-ABI**
  functions are never checked — so a Rust-ABI fn returning `Result<(),RegseqError>`
  bridges and lowers today. Only an `extern "C"` fn would be rejected (Result is
  neither `repr(int)`-fieldless nor `repr(C)`).
- **Trait callbacks (the spec's only commit points) are NOT bridged.** The only
  bridged domain construct is diag-log (`AttrData::Intrinsic(IntrinsicKind::Log)`).
  So there is **no callback-exit commit point in the generic-C pipeline**; a
  stand-in boundary is required.
- **`framework_type` is not handled in the active pipeline.** No active crate
  references `RegseqError`/`framework_type`/`FrameworkType`. Fixtures self-declare
  the enum locally carrying `#[rseq::framework_type("regseq-error")]`; the active
  bridge silently ignores it. `domain_attr.rs:62` `AttrData` currently has the
  single variant `Intrinsic(IntrinsicKind)` (append-only).
- **Enum variant names ARE retained.** `crates/regseq-model/src/layout.rs:115`
  `VariantLayout { name: StringId, ... }` — so a mapping can be keyed by variant
  name (robust), not by declaration order.
- **The entry already has a documented exit-code extension point.**
  `crates/regseq-backends/src/generic_c/naming.rs:75` `generate_main_c` emits
  `int main(void){ entry(); return 0; }` over a `void(void)` entry, and its
  doc says: *"Unit-`void` form only; `{i,u}32` exit-code propagation is a deferred
  feature (it lands with the first entry whose return carries a code)."* The entry
  is resolved by emission-name suffix `regseq_main` (`entry_c_symbol`,
  `naming.rs:45`).
- **Codegen-coverage fixtures are single-file `input.rs`** that self-declare
  `mod regseq { ... }` inline (no facade dependency); diag-log is recognized by
  **attribute**, not path. `manifest.toml` schema (`manifest.rs:20`): `name`,
  `entry` (default `regseq_main`), `expect` (Run/Panic), with sibling
  `expected.stdout` / `expected.stderr`.
- **Harness oracle today** (`pipeline.rs`, `oracle.rs`): `expect = pass` requires
  **exit 0** then byte-compares **stdout**; `expect = panic` requires **non-zero
  exit + golden stderr** but **never asserts a specific exit-code value**.

### Consumers / actors
- Driver-spec authors (write `Result<(),RegseqError>` and `regseq_main`).
- The bridge (recognizes the attribute), the generic-C backend (applies the
  per-target mapping), the codegen-coverage runner + `cargo-regseq --emit bin`
  (consume the entry shim), future Linux/Zephyr backends (reuse the per-target
  table mechanism).

### Governing specs
- Authoritative design baseline: `docs/discussions/regseq-error/regseq-error-spec.md`
  (treated as **non-final / partly stale** per D06).
- IR→C mapping contract: `docs/discussions/regseq-model/generic-c-backend.md`.
- Phase arc: `docs/discussions/generic-c-backend/roadmap.md` (Phase 2 = RegseqError,
  "definition only; detail at P2 start"), `decisions-and-state.md`.

### Non-goals
See **Out of Scope**. In one line: no trait-callback bridging, no intrinsic-local
error enums, no derive macro, no second carrier, no Linux/Zephyr tables, no
`Display`/`std::error::Error`.

### Testing approach & seams
- **Backend unit test** (pure function): exhaustive variant-name→errno table.
- **Codegen-coverage e2e fixtures**: bridge → model → emit C → host `cc` → run →
  assert **process exit code** (new `expected.exit` oracle) + golden `.c` snapshot.
- Determinism bar (per project memory): goldens byte-stable; emitted mapping is
  **symbolic** (`return EINVAL;`) so the `.c` snapshot is deterministic.

## Decisions

### D01 — Scope: a real, end-to-end-exercised commit point (not "definition only")
**Decision.** Phase 2 builds an actual commit point where `RegseqError` is mapped
to a host code and the mapping is exercised end-to-end (run + asserted), plus the
host mapping table — going beyond a bare type definition.
**Rationale.** User chose the most ambitious scope; the type itself needs no work,
so the value is in proving the mapping mechanism on the host.
**Rejected.** (a) Type + structural-flow proof only (no mapping applied); (b) also
build the table mechanism but leave it unexercised.
**Evidence.** Codebase reality above; roadmap P2 breadcrumb ("first concrete
instance of the per-target error-mapping table").
**Confidence.** High. **Confirmed.**
**Impl impact.** Drives D02–D08. **Test impact.** Requires a runnable, asserted
end-to-end path (D03, D07).

### D02 — Commit point = the `regseq_main` exit (authored→host-scaffolding crossing)
**Decision.** The mapping is applied where authored code hands a `RegseqError`
across into OS/host scaffolding. In generic-C the one such crossing is **`regseq_main`
returning to the generated `main(void)` shim** (`main` = the host stand-in for
kernel/driver-framework glue). **Inside** authored code RegseqError stays a plain
enum with no special handling (create / `?` / `match` / reclassify / nested
helpers all lower as ordinary MIR). A `RegseqError` created and fully consumed
inside authored code (function returns `Ok`) **never crosses → never mapped**.
**Rationale.** The user's principle — "treat RegseqError specially only when it
crosses into OS scaffolding" — is exactly the spec's model (§4), and coincides
with the compiler mechanics: the only place the compiler is forced to act (the
extern-"C"/exit boundary) is the same boundary. The entry is a **stand-in** for
the real trait-callback boundary (unbridged); the table built here is the reusable
piece future callback lowering + Linux/Zephyr backends plug into.
**Rejected.** A bespoke `#[rseq::fallible_boundary]` attribute fn (invents
machinery that may not match the eventual trait-callback design); "any extern-C
crossing" as an abstract rule (collapses to the entry in practice today).
**Evidence.** `naming.rs:75` documented exit-code extension; `fnsig.rs:51`
boundary-scoped admissibility; spec §4.
**Confidence.** High. **Confirmed** (explicitly locked by the user).
**Impl impact.** Backend detects the error-returning entry and emits the mapping
at its exit; realizes the deferred exit-code-propagation feature.
**Test impact.** e2e fixtures drive `regseq_main`.

### D03 — Observe & assert via the process **exit code**
**Decision.** Generated `main` **returns** the mapped code (so it propagates as the
process exit status). The harness gains a per-fixture **`expected.exit`** oracle
asserting the exact exit code. Pass-mode becomes "exit == `expected_exit`
(default 0)"; stdout is still compared (empty golden for these fixtures).
**Rationale.** Faithful to "the OS reads the return code" and the literal deferred
feature; the alternatives observe the code via a print rather than via real
propagation. Current oracle can't assert a specific non-zero exit value, so a small
extension is required regardless.
**Rejected.** Print-to-stdout (zero harness change but not real propagation);
both channels (more cost for marginal cross-check).
**Evidence.** `pipeline.rs:178` (pass ⇒ exit 0), `oracle.rs:31` (panic ignores
specific value), `manifest.rs:20`.
**Confidence.** High. **Confirmed.**
**Impl impact.** New manifest field + pipeline assertion (see C04). **Test impact.**
Each error fixture declares `expected.exit`.

### D04 — Host code values = libc `<errno.h>` symbolic constants
**Decision.** Map per **C02**, using libc symbolic constants (hosted generic-C has
`<errno.h>`). `Ok(()) → 0`. Emitted C is **symbolic** (`return EINVAL;`); the
process exit code is the host libc numeric. The `<errno.h>` include is
**demand-driven** (emitted only when the mapping is emitted), consistent with the
prior de-clobber work ([[overflow-checks-harness-vs-production]] sibling theme).
**Rationale.** The roadmap said the host has no *kernel* error space, but hosted
userspace libc errno **is** available; using it is faithful, symbolic (the
discussion's stated preference), mirrors the seed table's Linux column, and makes
generic-C's table a genuine precursor for the Linux/Zephyr backends.
**Rejected.** Sequential `1..=9` (a formula, not a real table; no symbolic
emission); invented non-sequential host codes (arbitrary).
**Evidence.** Seed taxonomy table in `current-synthesis.md`; mapping discussion's
"lower to symbolic constants."
**Confidence.** High. **Confirmed.**
**Consequences (accepted).** `GenericFailure` and `HardwareError` both → `EIO`
(faithful to the seed table; indistinguishable by exit code — acceptable, both are
still unit-tested). `expected.exit` numeric is host-libc-dependent (see O1).
**Impl impact.** Backend errno table (C02) + demand-driven include. **Test impact.**
Exhaustive unit test over C02; e2e fixtures assert the numeric.

### D05 — Recognition: attribute marks the enum; backend maps by variant **name**
**Decision.** The bridge recognizes `#[rseq::framework_type("regseq-error")]` on an
enum item and records a new **`AttrData::FrameworkType`** entry on that ItemId
(mirroring the diag-log `IntrinsicKind` precedent). The **per-target errno table
lives in the backend**, keyed by `VariantLayout.name`. Variant **order is not
load-bearing**. An **unknown variant name** (e.g. a future `#[non_exhaustive]`
addition not in the table) maps to **`EIO`** (the `GenericFailure` fallback).
**Rationale.** Path/DefPath recognition can't see a self-declared fixture type;
the attribute already exists on fixtures and matches the diag-log mechanism.
Keying by name (names are retained) is robust to reordering. The per-target table
belongs in the target backend, not the target-agnostic model.
**Rejected.** Bridge records per-variant codes into the model (wrong home — a
per-target concern in a target-agnostic model); no-attribute structural detection
(mis-fires on any other Err enum; hard-couples backend to the name set).
**Evidence.** `domain_attr.rs:62` (`AttrData` append-only, single `Intrinsic`
variant); diag-log recognition `bridge/diag_log/recognition.rs:6`; `layout.rs:115`
(`VariantLayout.name`).
**Confidence.** High. **Confirmed.**
**Impl impact.** model: new `AttrData::FrameworkType` (append-only). bridge: a
`get_attrs_by_path(def_id, [rseq, framework_type])` recognizer on enum items →
record the AttrData. backend: at the entry, check the Err enum's ItemId for the
AttrData; map active variant by name. **Test impact.** Unit test for the table +
recognition; C05.

### D06 — No facade-crate requirement; identity is purely the attribute
**Decision.** `RegseqError` is identified **solely** by
`#[rseq::framework_type("regseq-error")]`, wherever declared. It need **not** live
in the `regseq` facade crate. The codegen-coverage fixture self-declares an inline
copy carrying the attribute. Spec §8's "define in the facade crate" mandate is
treated as **stale and relaxed**.
**Rationale.** User: the spec is old/non-final; since recognition is attribute-based
and location-independent, tying the feature to a particular crate is unnecessary.
**Rejected.** Promoting the canonical enum into the no_std facade this phase (spec
§8) — not required by the recognition mechanism and not consumed by the gate.
**Evidence.** Fixtures self-declare `mod regseq` inline (`b4_enums/input.rs`);
diag-log recognized by attribute not path.
**Confidence.** High. **Confirmed.**
**Impl impact.** No facade edit. **Test impact.** Fixture is self-contained.

### D07 — Coverage: a few e2e fixtures + an exhaustive backend unit test
**Decision.** End-to-end fixtures prove the pipeline + flow surface: (a) `Ok → 0`;
(b) a couple of distinct `Err` variants (e.g. `EINVAL`, `ETIMEDOUT`); (c) one
weaving `?` propagation from a nested helper **and** a `match`/reclassify (one
variant → another) before escaping. The **full 9-variant→errno table** is covered
exhaustively by a fast **backend unit test** over the mapping function.
**Rationale.** Each static fixture asserts exactly one exit code, so exhaustive e2e
coverage would mean ~10 near-identical fixtures; a unit test covers the table
exhaustively where it is cheap, and a handful of fixtures cover the pipeline/flow
where end-to-end matters. Keeps "no silent caps" (the table is fully verified)
without fixture bloat.
**Rejected.** Per-variant e2e fixtures (~10, near-duplicate); minimal mechanism-only
(leaves most of the table unverified).
**Evidence.** Static fixtures (no stdin); gate philosophy + memory
[[codegen-coverage-gate-pass]].
**Confidence.** High. **Confirmed.**
**Impl impact.** ~3–4 fixtures + 1 unit test. **Test impact.** see C04 manifests.

### D08 — Supported entry forms; all others fail loud at emit
**Decision.** The error-mapping path accepts **exactly** `fn regseq_main() ->
Result<(), RegseqError>` (unit `Ok`; `Err` is the attribute-marked `RegseqError`).
The existing `fn regseq_main() -> ()` **unit-void** form stays supported (exits 0,
current shim unchanged). **Every other shape is a fail-loud backend rejection at
emit**: non-unit `Ok` (`Result<T,_>`, `T != ()`), an `Err` enum **not** marked
`regseq-error`, or an entry taking arguments.
**Rationale.** Tightest, clearest contract; avoids silently dropping a success
payload or mis-mapping an unmarked enum. Matches the spec's callback shape
`Result<(), RegseqError>`.
**Rejected.** Allow non-unit `Ok` (silently discards `T`); allow any marked Err
enum (fuzzier, invites mis-marking).
**Evidence.** Spec §8 carrier `Result<(), RegseqError>`; `naming.rs` entry handling.
**Confidence.** High. **Confirmed.**
**Impl impact.** Backend rejects unsupported entry forms with a clear diagnostic.
**Test impact.** (Optional) a negative test that an unsupported entry is rejected.

## Formal Contracts

### C01 — `RegseqError` type definition (authored surface)
Self-declared by the fixture (and by any real spec), identified by the attribute.
```rust
#[rseq::framework_type("regseq-error")]
#[non_exhaustive]
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum RegseqError {
    InvalidParameter,
    OutOfMemory,
    HardwareError,
    Timeout,
    Unsupported,
    DeviceBusy,
    PermissionDenied,
    DeviceNotFound,
    GenericFailure,
}
```
- MUST NOT implement `std::error::Error`; MUST NOT depend on `Display`.
- Authored carrier is `core::result::Result<T, RegseqError>` (no custom
  `RegseqResult<T>`).
- Default repr (no `#[repr(int)]` needed): the type is internal/Rust-ABI; only the
  *mapped output* is an int.

### C02 — Generic-C host error-mapping table (per-target; lives in the backend)
Keyed by `VariantLayout.name`. Emitted **symbolically**; `<errno.h>` demand-driven.

| RegseqError variant | host code (symbol) | glibc numeric (exit code) |
|---|---|---|
| *(success)* `Ok(())` | `0` | 0 |
| `InvalidParameter`   | `EINVAL`     | 22 |
| `OutOfMemory`        | `ENOMEM`     | 12 |
| `HardwareError`      | `EIO`        | 5  |
| `Timeout`            | `ETIMEDOUT`  | 110 |
| `Unsupported`        | `EOPNOTSUPP` | 95 |
| `DeviceBusy`         | `EBUSY`      | 16 |
| `PermissionDenied`   | `EPERM`      | 1  |
| `DeviceNotFound`     | `ENODEV`     | 19 |
| `GenericFailure`     | `EIO`        | 5  |
| *(unknown variant name)* | `EIO`    | 5  |

Numerics are the Linux/glibc values (the harness host); they are NOT part of the
emitted `.c` (which is symbolic) and are asserted only at runtime (see O1).

### C03 — Emission shape at the entry boundary (golden-defining)
For an entry `fn regseq_main() -> Result<(), RegseqError>`:
- The entry is emitted **faithfully** as a Rust-ABI function returning the §13
  `Result<(),RegseqError>` C struct (no change to body emission).
- The backend emits a thin **adapter** in the TU (where §13 discriminant-read
  machinery + the demand-driven `<errno.h>` are available), shape:
  ```c
  /* demand-driven: */ #include <errno.h>
  int <entry>__regseq_exit(void) {
      <ResultStruct> __r = <entry>();
      /* read Result discriminant per §13 */
      if (/* __r is Ok */) return 0;
      /* read RegseqError variant of __r's Err payload per §13, by VariantLayout.name */
      switch (/* variant */) {
          case InvalidParameter: return EINVAL;
          /* ... C02 ... */
          default:               return EIO;   /* unknown / GenericFailure */
      }
  }
  ```
- The `main` shim (`generate_main_c`) becomes:
  ```c
  extern int <entry>__regseq_exit(void);
  int main(void) { return <entry>__regseq_exit(); }
  ```
- **Unit-void entries are unchanged**: `extern void <entry>(void); int main(void){
  <entry>(); return 0; }` (every existing golden stays byte-identical).
- Adapter symbol name + collision-proofing: impl detail (O3).

### C04 — Harness `expected.exit` oracle
- `manifest.toml` gains an optional integer field (e.g. `expected_exit`,
  default 0) **or** an `expected.exit` sibling file (to-plan picks one).
- `expect = pass` semantics change from "exit == 0" to "exit == `expected_exit`
  (default 0)"; **stdout is still byte-compared** to `expected.stdout` (empty for
  pure error fixtures). `expect = panic` unchanged.
- Both consumers of the entry shim apply C03: the **codegen-coverage runner** and
  **`cargo-regseq --emit bin`** (`crates/regseq-driver/src/emit.rs`).

### C05 — `AttrData::FrameworkType` bridge recognition
- model: append `AttrData::FrameworkType(FrameworkType)` to the append-only
  `AttrData` enum (`domain_attr.rs`), with `FrameworkType::RegseqError` (room for
  future framework types).
- bridge: recognize `#[rseq::framework_type("regseq-error")]` on enum items via
  `tcx.get_attrs_by_path(def_id, [Symbol("rseq"), Symbol("framework_type")])`,
  extract the dash-form string, and record the AttrData on the enum's `ItemId`
  (idempotent), mirroring `record_log_intrinsic` (`bridge/diag_log/recognition.rs`).
- backend reads `model.domain_attrs.item_attrs[err_enum_item]` to decide mapping.

## Open Items

- **O1 — `expected.exit` numerics are host-libc-dependent.** `EINVAL=22`, etc. are
  glibc values; authored against the harness host. If the harness ever runs on a
  libc with different errno numbering, those values need re-blessing. The emitted
  `.c` is symbolic and stays deterministic. `blocking: false` (host-validation
  harness; project runs Linux/glibc).
- **O2 — Doc-1 coverage-matrix row taxonomy.** Whether to add one combined
  "RegseqError boundary mapping + exit-code propagation" row or several, and the
  ledger wiring. A doc/tracking detail for to-plan; the gate MUST stay `pass` and
  existing goldens MUST be unchanged. `blocking: false`.
- **O3 — Adapter symbol naming + collision-proofing** (e.g. `<entry>__regseq_exit`).
  Impl detail for to-plan. `blocking: false`.
- **O4 — Home of the demand-driven `<errno.h>` include** (prelude bank vs adjacent
  to the adapter) and how it composes with the existing demand-driven helper-block
  machinery. Impl detail for to-plan. `blocking: false`.
- **O5 — External review.** Run a bounded Codex review at the **to-plan** stage
  (per the project loop and the to-plan skill), with attention to the exit-code
  oracle change and the libc-errno-as-exit-code determinism (O1). `blocking: false`.

## Out of Scope (deferred / rejected)

- **Trait-callback bridging** (`Lifecycle`/`PowerManagement`/`Serial`) and true
  callback-exit lowering — Phase 3+. The entry is their stand-in for now.
- **Intrinsic-/construct-local error enums** (`ClockError`, `PollError`, …) and
  `From<Local> for RegseqError` — spec §9, deferred.
- **`#[derive(RegseqErrorMap)]`** helper macro — spec §10, deferred.
- **Second fallible carrier** / custom `RegseqResult<T>` — rejected; baseline uses
  `core::result::Result`.
- **Wrapper native-failure boundary policy** (Models A/B/C) — deferred; no
  wrappers/intrinsics bridged.
- **Linux/Zephyr per-target errno tables** — future per-target backends; C02 is
  their first instance/precursor.
- **`Display` / `std::error::Error`** on `RegseqError` — explicitly excluded.
- **Non-unit `Ok`, entry arguments, non-RegseqError `Err` at the entry** — rejected
  (D08, fail-loud at emit).
- **Promoting `RegseqError` into the `regseq` facade crate** — not required (D06).
