# PLAN — RegseqError (generic-C backend, Phase 2)

> Drafted by the Plan architect (read-only, repo-grounded); hardened by a bounded Codex
> review (2 rounds). Round 1 raised 2 blocking findings (entry-aware API gap; the
> "synthesize a model-level adapter body" mechanism cannot emit symbolic errno constants)
> + 2 non-blocking; all folded in. See **Review Summary**.

## Overview

**Goal.** Make an authored `RegseqError` returned from `fn regseq_main() -> Result<(),
RegseqError>` surface to the OS as a host-native errno, **exercised end-to-end on the host
target** (run + asserted exit code), and ship the first concrete per-target error-mapping
table (C02). This is a real commit point, not a type definition (D01).

**Scope.** The single commit point is the `regseq_main → main` crossing (D02, I01).
Authored-internal `RegseqError` use (construct / `?` / `match` / reclassify / nested
helpers) lowers as ordinary MIR with no special handling (R02). The error enum is
identified purely by `#[rseq::framework_type("regseq-error")]` (D05/D06); the errno table
lives in the backend keyed by `VariantLayout.name` (C02/I04); an unknown marked variant ⇒
fail-emit (R08/I05). The harness gains a symbolic `expected.exit` oracle resolved on the
fixture's own libc (C04/R10/R11). Emitted C stays symbolic (`return EINVAL;`) with a
demand-driven `<errno.h>` (R07/I03). Existing unit-void emission stays byte-identical
(R05/I02). All unsupported entry shapes fail loud at emit with required negatives
(D08/R09).

**Out of scope (do not build):** trait-callback bridging, intrinsic/construct-local error
enums + `From`, the derive macro, a second carrier, Linux/Zephyr tables,
`Display`/`std::error::Error`, manifest-custom entry for error returns, facade-crate
promotion. **G01 binds Phase 3+ only** — no task here.

## Architecture & Components

Four components, strictly layered; the contract-level dependency DAG is linear:

```
[Model]   AttrData::FrameworkType            (C05; append-only I08)
   │  recorded by ▼
[Bridge]  framework_type recognizer + item-walk materializer
   │      writes model.domain_attrs.item_attrs[enum_item]   (C05, R06)
   │  read by ▼
[Backend] entry-aware emit API                (C02,C03,D08,D09; R03/R04/R07/R08/R09; I01/I02/I05)
   │   ├─ errno table (C02) — pure, name-keyed
   │   ├─ entry resolution + return-shape classifier  → returns shim shape (+ adapter symbol)
   │   ├─ hand-emitted in-TU adapter (reuses §13 discriminant extraction) + demand-driven <errno.h>
   │   └─ generate_main_c emits int shim for ErrResult / void shim otherwise
   │  shim shape consumed by ▼
[Harness] symbolic expected.exit oracle        (C04; R10/R11) — TWO consumers:
   ├── codegen-coverage-runner  (manifest + pipeline + oracle + toolchain)
   └── cargo-regseq --emit bin  (regseq-driver emit.rs)
```

**Inter-component contracts.**
- **Model→Bridge (C05, I08):** the new `AttrData::FrameworkType(FrameworkType::RegseqError)`
  variant + serialized-discriminant stability.
- **Bridge→Backend (C05):** the recorded attr lives at
  `model.domain_attrs.item_attrs[err_enum_item]`; the backend reads it exactly as
  `is_diag_log_instance` reads `AttrData::Intrinsic` today (`generic_c/mod.rs`).
- **Backend→Harness (C03, C04):** the backend is the **single source of truth** for both
  (i) the in-TU adapter `<entry>__regseq_exit` (emitted by the entry-aware emit API) and
  (ii) the **shim shape** that `generate_main_c` turns into `int main(void){ return
  <entry>__regseq_exit(); }` vs the void shim. **Neither consumer re-derives the shim
  shape** — it is returned from the backend (closes round-1 blocking #1).
- **Harness internal (C04):** the symbolic `expected.exit` → numeric resolution runs on the
  **same `cc`/libc** that compiles + runs the fixture.

**Key grounded facts that shape the design** (verified by the architect + Codex):
- `AttrData` (`regseq-model/src/domain_attr.rs`) is `#[repr(u8)]`, `Intrinsic = 0`,
  append-only.
- The diag-log recognizer is **call-driven** (fires at the Call terminator). `RegseqError`
  is a *type*, not a called fn, so recognition must be **item/type-driven** — a new
  materialization pass walking enum items, mirroring `materialise_log_intrinsics`. The
  model side table stores **`DefPathHash`, not `DefId`** (`bridge/assign.rs`), so the pass
  recovers the `DefId` via `model.item_def_paths[item]` → `tcx.def_path_hash_to_def_id`
  (the existing ADT path, `bridge/mod.rs`), skipping synthetic items (round-1 non-blocking
  #4).
- `Result<(), RegseqError>` is a **niche-encoded** enum; `RegseqError` is a fieldless
  **Direct** enum. The §13 discriminant readers are **`&self` methods on the body emitter**
  and the **niche read is assign-site/statement-only** today (a non-assign niche
  `Discriminant` rvalue currently rejects). This is the crux of O3/A3 (see Risks).
- **Model constants are numeric/bytes/relocs** — there is **no symbolic macro-constant
  representation** (`regseq-model/src/const_value.rs`), and lowered body returns emit
  `_0`/`return;`, **not** `return EINVAL;`. ⇒ The adapter **cannot** be a synthesized
  model-level body lowered through normal emission (it would emit numerics, violating
  I03/C03). The adapter is **hand-emitted backend C** that reuses §13 discriminant
  *extraction* for the reads only (round-1 blocking #2).
- `generate_main_c` is shared by the runner's `toolchain` main.c generator and
  `emit.rs::Bin`; its signature changes once and both call sites move in lock-step.

## Build Order & Milestones

**Smallest end-to-end vertical slice = M1.** A single-file fixture declaring
attribute-marked `RegseqError` (C01) and `fn regseq_main() -> Result<(), RegseqError> {
Err(RegseqError::InvalidParameter) }`, driven **author input → bridge (records
FrameworkType) → model → backend (adapter + `<errno.h>` + int main shim) → host `cc` → run
→ assert process exit == resolved(`EINVAL`) with empty stderr** via the new symbolic
`expected.exit` oracle. This forces every component into existence at once and surfaces the
O3/A3 discriminant-read risk on day one.

- **M0 — Prep / guards.** T01 (byte-identical unit-void baseline guard) · T06 (O3
  discriminant-extraction mechanism spike — retire the highest risk before the adapter).
- **M1 — Smallest e2e Err slice.** T02 · T03 · T04 (model + bridge) · T05 (errno table) ·
  T07 (entry-aware API + classifier) · T08 (hand-emitted adapter + int shim) · T09 (harness
  oracle). End state: the `EINVAL` fixture runs and asserts its exit code; gate stays
  `pass`.
- **M2 — Coverage breadth.** T10 (exhaustive C02 unit test) · T11 (`Ok→0` fixture) · T12
  (`?`/`match`-reclassify weaving fixture).
- **M3 — Fail-loud negatives.** T13 (unknown variant fails emit) · T14 (every rejected
  entry shape, incl. custom-entry+error-return).
- **M4 — Cross-cutting close-out.** T15 (`--emit bin` second-consumer parity) · T16 (O2
  ledger/matrix-row wiring + docs conformance note).

### T04 — Bridge: materialize `FrameworkType` onto enum ItemIds (item-walk pass)
- **Scope.** `regseq-driver` bridge: a materialization pass (mirroring
  `materialise_log_intrinsics`, invoked from `assign.rs`) that walks **enum items**, and
  for each recovers its `DefId` from `model.item_def_paths[item]` via
  `tcx.def_path_hash_to_def_id` (the existing ADT-resolution path), **skipping synthetic /
  non-source items**, runs T03 recognition, and idempotently records
  `AttrData::FrameworkType(FrameworkType::RegseqError)` into
  `model.domain_attrs.item_attrs[item]`.
- **Depends-on.** T03 (→ T02).
- **Acceptance criteria.** A marked enum's ItemId carries exactly one `FrameworkType` attr;
  recording idempotent; unmarked enums carry none (**C05**, **R06**, **I08**). Recognition
  is type/item-driven so it fires when `RegseqError` appears **only** as the entry's return
  type (preserving the **R02** boundary distinction — authored-internal use is never
  marked). `DefId` is recovered via `item_def_paths`/`def_path_hash_to_def_id`; synthetic
  items are skipped (no panic / no mis-attribution).
- **Test.** Seam: bridge integration (hand-driven model or `bridge_smoke` pattern). Method:
  bridge a minimal fixture; assert the attr lands on the enum item and nowhere else; assert
  a synthetic/non-source item is skipped.
- **Size.** M. **Risks.** Medium. Item-walk timing vs ItemId assignment; the `DefPathHash`→
  `DefId` recovery must match the existing ADT path. Confirm enum items are populated in
  `model.items` at materialization time.

### T05 — Backend: C02 errno table (pure, name-keyed) + unknown-variant fail-emit

- **Depends-on.** —
- **Acceptance criteria.** Every C02 row maps to its exact symbol by name, order-independent
  (**C02**, **I04**); an unknown name ⇒ `None`, and the caller turns that into a fail-loud
  emit error, **never `EIO`** (**R08**, **I05**); `Ok → 0`; no host-libc numeric appears

- **Test.** Seam: regseq-backends unit. Method: exhaustive assert over all 9 rows + a bogus
  name ⇒ `None`.
- **Size.** S. **Risks.** Low. Keep standalone/pure so T10's exhaustive test is fast.

### T07 — Backend: entry-aware emit API + return-shape classifier (+ threaded shim shape)
- **Scope.** Introduce an **entry-aware emit API** (e.g. `emit_generic_c_for_entry(model,
  entry_suffix)`) that resolves the named entry from `model.instances` (reusing the
  `entry_c_symbol` suffix logic), reads its `FnSig.output`, classifies into `{UnitVoid,
  ErrResult(err_enum_ty), Reject(reason)}`, and **returns the shim shape (+ adapter symbol
  name) alongside the TU** so consumers no longer re-derive it. `ErrResult` requires
  `Result<(), E>` with `()` Ok and `E` an enum carrying the `FrameworkType` attr (read
  `model.domain_attrs.item_attrs`, mirroring `is_diag_log_instance`). Update **both**
  consumers (codegen-coverage runner; `regseq-driver emit.rs`) to consume the returned shim
  shape. (Closes round-1 blocking #1.)
- **Depends-on.** T02 (variant exists), T04 (attr recorded).
- **Acceptance criteria.** Unit-void ⇒ `UnitVoid`, emission byte-identical (**R05/I02**);
  `Result<(), RegseqError-marked>` ⇒ `ErrResult` (**R03/R07**); non-unit `Ok`
  (`Result<T,_>`, `T≠()`), unmarked `Err` enum, entry with args, **and a manifest-custom
  entry combined with an error-returning signature** ⇒ `Reject` with a diagnostic naming the
  shape (**D08/D09/R09**). The backend is the **single decision point**; both consumers take
  the shim shape from it, none re-derive (**C04**). For Phase 2 both consumers pass the
  default `regseq_main` suffix on the error path (**D09**).
- **Test.** Seam: regseq-backends unit over hand-built models (`mod_tests.rs` pattern) +
  both call-site compile checks. Method: assert classification + reject diagnostics; assert
  unit-void path returns the void shim shape unchanged.
- **Size.** M. **Risks.** Medium (A4): entry resolution assumes a single suffix match;
  ambiguous/absent `regseq_main` must fail loud, not panic. Detecting `Result<(),E>`
  structurally (niche two-variant + `()` Ok payload + enum Err payload) needs care — prefer
  layout-shape matching, then the attr check.

### T08 — Backend: hand-emitted adapter + symbolic errno switch + int main shim (golden-defining)
- **Scope.** When T07 yields `ErrResult`, **hand-emit** in the TU the adapter
  `<entry>__regseq_exit(void)` that: (a) calls the faithful Rust-ABI entry returning the
  §13 `Result` struct; (b) reads the `Result` (niche) discriminant and, on Err, the inner
  `RegseqError` (Direct) discriminant — via the T06 backend-local helper; (c) emits a
  **symbolic** `switch` → `return <ERRNO_SYMBOL>;` for every known variant (from T05),
  `default: return EIO;` as **corrupt-discriminant defense only**; (d) `return 0;` for Ok;
  (e) emits a **demand-driven `<errno.h>`**. Extend `generate_main_c` to emit `int
  main(void){ return <entry>__regseq_exit(); }` for `ErrResult` and the unchanged void shim
  otherwise.
- **Depends-on.** T05 (table), T06 (read mechanism), T07 (classifier + API + err enum ty).
- **Acceptance criteria.** Adapter + shim match **C03** byte-for-byte in the golden; `main`
  returns the adapter errno (**R03**); `Ok` ⇒ returns 0, process exits 0 (**R04**); emitted
  codes are **symbolic** (`return EINVAL;`), no host numeric in the `.c` (**I03**);
  `default: EIO` is unreachable for known variants and never a silent map for a
  known-but-unmapped one (**I05/R08**, **C02**); `<errno.h>` is demand-driven, emitted only
  with the adapter (**R07**). **Unit-void entries emit byte-identically — existing
  golden(s) unchanged** (**I02/R05**); assert this explicitly. Adapter reads use §13 / the
  T06 helper, no new layout logic (**A3**).
- **Test.** Seam: golden snapshot (determinism oracle) + M1 e2e run (behavioral oracle).
  Method: `--bless` then re-run for byte-stability; assert unit-void golden diff empty.
- **Size.** L. **Risks.** High (O3/A3) — retired by T06; residual risk is golden churn,
  mitigated by T01's guard.

## Cross-cutting Workstreams

- **Diagnostics / fail-loud (D05/D08/D09/R08/R09).** Every reject — unknown variant (T13),
  unsupported/rejected entry shapes incl. custom-entry+error-return (T14) — is a **backend
  `EmitError`** naming the offending variant/shape, surfaced identically by both consumers.
  The **backend is the single enforcement point** (the entry-aware API, T07), so the runner
  and `--emit bin` cannot diverge.

## Risks & Assumptions

- **O3 / A3 (highest) — adapter discriminant-read mechanism.** The §13 readers exist but are
  `&self` body-emitter methods and the niche `Result` read is assign-site/statement-only; a
  non-assign niche `Discriminant` rvalue rejects today. **Recommendation (revised after
  round 1): hand-emit the adapter's symbolic errno switch in backend C and reuse §13
  discriminant extraction via a backend-local, statement-producing helper.** *Rejected:* (a)
  **synthesize a model-level adapter body** lowered through normal emission — **infeasible**:
  model constants are numeric/bytes/relocs (`const_value.rs`) and body returns emit
  `_0`/`return;`, so it cannot emit `return EINVAL;` (violates I03/C03); (b) a **pure
  expression helper** — insufficient because the niche read is statement-shaped. T06 retires
  this risk with a compile/run proof before T08.
- **O4 — home of `<errno.h>`.** *Recommendation:* route through the existing demand-driven
  `HelperUsage`/`helper_block` machinery (commit `21f7842`) so the include lands in the bank
  on demand and output stays byte-stable. *Rejected (risk):* an include adjacent to the
  adapter — breaks the "all includes in bank 1" convention, risks golden churn.
- **A4 (likely-to-be-wrong) — entry resolution.** D09 confidence Medium-High. The
  entry-aware API assumes a single `regseq_main` suffix match and a `FnSig.output` that
  structurally reveals `Result<(),E>`. *Mitigation:* T07 fails loud (never panics) on
  ambiguous/absent/unexpected shapes; classify by the niche two-variant layout + `()` Ok
  payload + enum Err payload, then the attr check.
- **A3 (likely-to-be-wrong) — discriminant-read reuse.** Same root as O3; surfaced on day
  one by making M1 first and retired by T06.
- **T04 timing.** The item-walk materializer must run when enum ItemIds are bound and
  `model.items` is populated, and recover `DefId` via `item_def_paths`/
  `def_path_hash_to_def_id` (no exact scan-all-enums precedent — diag-log is call-cache
  driven). *Mitigation:* verify enum items are present at materialization; skip synthetic
  items.
- **Non-task items (recorded, not dropped).** **G01** binds Phase 3+ only — out of scope, no
