# PRD — backend/zephyr-c-e1000

## Problem Statement

The regseq compiler's 2×2 device/OS matrix (PL011+E1000 × Linux+Zephyr) has
one open cell: a PCIe device on Zephyr. The `zephyr_c` backend today rejects
`bus = "pci"` with `UnsupportedInUnit` scheduled to exactly this unit, so the
single converged `e1000-composed` spec — already feeding generic_c and
linux_c — cannot emit for Zephyr. Consumers of that cell are: the
codegen-coverage runner (needs zephyr goldens/conformance for both e1000
fixtures), the eval campaign (needs runnable L1/L2/L3 evidence on a Zephyr
x86 QEMU target), and the project's born-converged claim itself (ONE
`input.rs`, three backends — the acceptance shape; a sibling fixture is a
charter failure).

A hidden blocker was surfaced and resolved during grilling: the fixture's
`on_init` performs a width-1 config write, which the ledger's B-3 disposition
would have rejected at emit — the charter could not complete without the
ratified sub-word RMW lift (GRILL D05).

## Solution

Extend `zephyr_c` with the PCIe path: the DEVICE_PCIE instantiation scaffold,
the BRM preamble in the ratified per-OS order with runtime failure rungs,
config-space read/write lowering over the live-verified `pcie.h` pins
(including the ratified width-1/2 write RMW and the word-0 ID cache), and
mixed-match consumption of each fixture's new `Devicetree` entry while
audit-ignoring its Pci rows. Bless the full per-OS artifact set for
`e1000-composed` and `e1000-initfail` (zephyr goldens, binding yaml,
conformance, and the zephyr-leg generic_c oracle pair under the F-1
sole-binary exception), prove the frozen artifacts unchanged unblessed-first,
and stand up the eval-side `e1000/zephyr/campaign/` L1/L2/L3 legs including
the amendment-8 whitelist entries. The unit is left unmerged at its gate.

## Requirements

R01. Given a driver model with `bus = "pci"` and ≥1 native `Devicetree` match
entry, when `zephyr_c` emits, the backend must produce a complete PCIe TU —
`<zephyr/drivers/pcie/pcie.h>` include, `struct pcie_dev *pcie` data field,
`DEVICE_PCIE_INST_DECLARE(n)` + `DEVICE_PCIE_INST_INIT(n, pcie)` in the
instantiation block — instead of the current `UnsupportedInUnit` rejection;
all other unsupported buses keep their existing rejections. (S01; D02, D12;
design-intended)

R02. Given the PCIe arm, the emitted init fn must execute the preamble of
GRILL `C01` before the authored body: BDF-none rung, TU-static
`__rseq_pcie` install, `pcie_get_mbar(bdf, effective_bar)` handle probe with
failure rung, claim zero-call elision callout, `pcie_set_cmd(MEM)` enable,
`device_map` into the TU-static base — in the ratified probe → enable → map
order, rendered with the deviation audit comment, never silently. (S01, S03;
D02, D04, D11; design-intended on code-confirmed witness)

R03. Given a config-space READ of width 1/2/4, the lowering must follow GRILL
`C03`: reads whose containing word is word 0 are served from
`dev->pcie->id` with zero bus traffic (covers both `vendor@0x00` and
`device@0x02`); all other offsets issue one real `pcie_conf_read`; sub-word
results are extracted by shift/mask. (S02; D06; spec-derived A-4, scope
ratified)

R04. Given a config-space WRITE of width 1/2, the lowering must follow GRILL
`C02`: a containing-word RMW (`pcie_conf_read` → lane merge →
`pcie_conf_write`) with the RSEQ-RMW audit comment at the emit site; width-4
writes are a single native `pcie_conf_write`. Width-8 ops, 64-bit ops, and
misaligned sub-word accesses must keep the D.2 fail-loud emit rejection.
(S02; D05; design-intended)

R05. Given each fixture's converged match set per GRILL `C04`, zephyr_c must
consume the `Devicetree` entry natively (DT_DRV_COMPAT `regseq_e1000` /
`regseq_e1000fail`) and triple-render-audit each Pci row
(RSEQ-IGNORED-MATCH C block + conformance `ignored_match_entries` row +
binding-yaml section); linux_c must symmetrically audit-ignore the new
Devicetree entry. Both fixtures' match sets gain their Devicetree entry
appended LAST, Pci rows first. (S04, S06; D01; design-intended on
code-confirmed machinery)

R06. Given the composed fixture's authored `on_surprise_remove` under
`TargetOs::Zephyr` with queried bus "pci", the emitter must resolve
CAP-ZEPHYR-DT-SURPRISE-1 via the existing `bus_family = "any"` wildcard
(registration form unchanged: StaticDevicetree) and perform auditable
non-emission exactly as on the platform path — RSEQ-ABSENT-SLOT block,
conformance row with row ID + full citation, body still fully legality-checked.
No sibling capability row is added. (S05; D03; code-confirmed)

R07. The unit must bless the artifact sets of GRILL `C05`: for
`e1000-composed` — `platform.zephyr.toml` (board qemu_x86, `bar = 0` live,
base/size dead literals), `golden.zephyr.c`, `golden.zephyr.binding.yaml`
(includes `pcie-device.yaml`, vendor-id/device-id, no reg),
`golden.zephyr-oracle.c`, `expected.zephyr.stdout`, `conformance.zephyr.json`
(delivered = on_init/on_deinit/on_init_failure; absent =
on_surprise_remove:CAP-ZEPHYR-DT-SURPRISE-1; ignored = both Pci rows); for
`e1000-initfail` — `platform.zephyr.toml`, `golden.zephyr.c`,
`conformance.zephyr.json`, no oracle pair. `platform.toml` is renamed

R08. Before ANY zephyr bless, the runner must be executed unblessed and prove
`golden.c` + `expected.stdout` byte-identical and
`golden.linux.c`/`conformance.linux.json` changed ONLY by the licensed audit

R09. Compiler-side tests must cover the new arms at L0 (PCIe scaffold

## Invariants & Contracts

I01. generic_c SOURCE is never modified (F-1); the new zephyr-leg blesses are
the established sole-binary exception. `golden.c` and `expected.stdout` stay
byte-identical for both fixtures.

I02. Linux-leg artifacts (`golden.linux.c`, `conformance.linux.json`, all
archived campaign evidence) change at most by the cited audit lines of GRILL
`C04` — nothing else.

I03. Born-converged: ONE `input.rs` per fixture serves all three backends; no
sibling fixture is ever created — a wall triggers a gate-report instead.

I04. D.2 fail-loud default: every input shape without a ratified Zephyr
lowering contract (width-8/64-bit/misaligned config ops, BarType::Io,
non-Generic ClassTag, deferred match families, …) is rejected at emit time —
never silently emitted, never silently omitted.

I05. Never-synthesize: no transport-equivalent match entry, periphid table,
or DT property is invented; every emission traces to an authored entry or a
ratified scaffold rule.

I06. Citation discipline: every absent-slot artifact (C audit block,
conformance row, test-log line, L3 whitelist entry) cites the capability row
ID + its citation — row IDs, never prose.

I07. The emitted `BUILD_ASSERT(DT_NUM_INST_STATUS_OKAY(DT_DRV_COMPAT) == 1)`
guard covers BOTH TU-statics (mm_reg_t base and `__rseq_pcie`); multi-instance
devicetrees fail at C compile time.

I08. The platform/Amba preamble stays strictly canonical; the probe → enable
→ map permutation exists ONLY on the Zephyr-PCIe arm and ONLY with its audit
rendering (GRILL `C01`).

I09. The two-channel error rule: native preamble failures return unwrapped
negative errnos; authored-body failures return the wrapped negated-errno
adapter values. The C-5 uint8_t `init_res` clamp semantics hold (ENODEV=19,
EIO=5 across all three libcs).

I10. Eval-repo commits touch `e1000/zephyr/` by explicit path only; the unit
branch stays unmerged at the gate; no AI attribution in commit messages.

Formal contracts: preamble = GRILL `C01`; config writes = GRILL `C02`;
config reads = GRILL `C03`; match sets/dispositions = GRILL `C04`; artifact
sets = GRILL `C05`.

## Implementation Decisions

- **zephyr_c backend**: lift the `BusType::Pci` `UnsupportedInUnit` arm;
  add the PCIe scaffold per the scaffold doc's Pci-only blocks (include,
  data field, DECLARE/INIT macros) (D02, GRILL S01); add the TU-static
  `struct pcie_dev *` carrier installed post-BDF-rung pre-body (D12); emit
  the C01 preamble with rungs returning `-ENODEV` (D11); keep the A-15
  POST_KERNEL + default-priority hardcode unchanged (D07 — PCIe scan runs at
  PRE_KERNEL, no ordering pressure).
- **Config lowering**: per C02/C03 — word-0 cache from `dev->pcie->id`
  (D06), width-1/2 write RMW with audit comment (D05), `pcie_get_mbar` with
  the platform-toml BAR number as `effective_bar` (D04). The five `pcie.h`
  pins are closed as live-verified (D04).
- **Match machinery**: exercise the existing D03(a)/C06 audit path for Pci
  rows on zephyr_c and the Devicetree row on linux_c; generated binding yaml
  includes `pcie-device.yaml` with vendor-id/device-id and no reg (D01, D10).
- **Capability**: no code change to the lookup — the wildcard row covers the
  PCIe query; conformance assembly carries the absent row as on the platform
  path (D03).
- **Fixtures**: both gain their Devicetree entry appended last; per-OS
  platform file rename + new zephyr tomls (D01, D10).
- **Eval**: new `campaign/` subtree mirroring pl011/zephyr; smoke + bind +
  trace-diff scripts; capture spike first in the L2/L3 milestone (D08, D09,
  D13).

## Failure & Recovery

- **Device not enumerated / BAR absent at runtime**: the C01 rungs return
  `-ENODEV` unwrapped (native channel); the authored body never runs;
  `device_is_ready()` is false with `init_res=19` — distinguishable from the
  authored-Err legs (`init_res=5`). I09 holds.
- **Authored on_init Err (initfail leg)**: the existing negated-errno adapter
  path; `on_init_failure` hook runs; L2 asserts the three-outcome shape
  (FAIL + SKIP teardown).
- **Kconfig silent-drop hazard**: `CONFIG_DEVICE_DEINIT_SUPPORT=y` is pinned
  in every campaign/gate prj.conf (the known `Z_DEVICE_OPS` silent
  `deinit_fn` drop); a missing pin surfaces as the designed loud `-ENOTSUP`
  at L2, never silently.
- **Unblessed-first proof fails** (frozen artifact would change beyond
  licensed audit lines): stop and gate-report — the fixture/oracle contract
  is the wall, per I01–I03.
- **L3 capture spike fails**: escalate with options recorded; L2 proceeds
  (blocking: false, L3-gating: true).
- **Disk pressure**: below ~20G free on /home at a chunk close → stop and
  gate-report.
- **Emit-time rejections** (I04 shapes): EmitError with the D.2 wording;
  never partial TUs.

## Conformance

Governing internal specs: the Zephyr lowering spec
(`docs/discussions/zephyr-backend/`, esp. the open-questions ledger §B.4
marshalling — GRILL `C03` is spec-derived from it), the
os-capability-disposition rule + amendments (amendment 8 is this unit's
binding delivery), and the D03(a) mixed-match rule. External grounding: the
pinned Zephyr v4.4.0 source (684c9e8f32e4) — all five §C.1 `pcie.h` pins
live-verified (D04, code-confirmed) — and PCI configuration-space semantics
(the C02 RMW's adjacent-byte rewrite benignity). **Intended deviation**: the
Zephyr-PCIe preamble order (probe → enable → map) deviates from the model's
canonical enable → handle order — ratified as THE single recorded per-OS
deviation, rendered with an audit comment and a ledger row (D02); no other
deviation is licensed.

## Testing Decisions

Test external behavior at the established seams (from the GRILL context):

- **L0 (compiler)**: `zephyr_c/mod_tests.rs` structure tests + match-audit/
  capability tests; corpus snapshot suites in isolated test binaries (the
  corpus_e2e.rs process-determinism pattern). Good tests assert emitted-C
  structure and rejection wording, not emitter internals. Prior art: the
  pl011 zephyr arms and linux_c PCI tests.
- **Unblessed-first runner diffs** (R08): the byte-identity proof for frozen
  artifacts precedes every bless — the spec-convergence-pl011 method.
- **L1**: compiler-staged west build gate (zephyr_build.rs app, PCIe variant)
  and the eval bind oracle (DT_INST macro check — bind-leak prior art in
  pl011/zephyr `15-build-generated-image.sh`).
- **L2**: QEMU smoke with the RSEQ-SMOKE three-outcome markers (prior art:
  pl011/zephyr `40-smoke-gate.sh` + main.c skeleton); both legs (composed,
  initfail).
- **L3**: trace-diff over QEMU built-in tracepoints with the whitelist
  format (prior art: e1000/linux + pl011/zephyr `tools/trace-diff/`),
  preceded by the D09 spike; containment expectations honor D05 (CLS byte
  write = word read+write pair) and D06 (no word-0 read traffic).
- **Cadence verification**: `cargo test` green per commit; Codex review per
  chunk close; gate-report at decision points.

## Assumptions

The GRILL carries no decision tagged `assumed` — every decision is
code-confirmed, spec-derived, or design-intended on cited witnesses. The
least-settled items are the non-blocking Open items (board final and capture
mechanism, both owned by the D09 spike; amendment-8 entry wording, owned by
the L3 task; PCIe Kconfig set, discovered fail-loud at first build). None is
blocking.

## Out of Scope

A functioning NIC (DMA, IRQ, net iface, data path); `BarType::Io` (B-2);
width-8/64-bit config ops (B-3 remainder); multi-region / DEVICE_MMIO_NAMED
(B-10); non-Generic `ClassTag` / class API wrappers (B-9);
`on_system_shutdown` trigger resolution (C-4/A-18); per-device pointer
threading (container-morph seam); `poll_until` (B-1); the eval-refinement
campaign tree under `e1000/zephyr/{scripts,baseline,refined,…}`; merging the
unit; any generic_c source change.

## Further Notes

The fixture's BRM acquisition ops are scaffold-driven from the MMIO binding
declaration (the authored body contains only config intrinsics + MMIO/log
ops), and this driver authors no `set_bus_master` — so only the MEM gate
fires in C01 step 5 and the ratified separable-calls/fusion-peephole policy
goes unexercised here. The vendored eth_e1000 (single fused
`pcie_set_cmd(MEM|MASTER)`) remains the witness that the peephole form is
legal if a future fixture authors both ops.
