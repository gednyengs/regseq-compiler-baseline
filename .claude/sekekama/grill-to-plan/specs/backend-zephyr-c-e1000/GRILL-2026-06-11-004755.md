## Decisions

**D01 — Match form: each fixture gains a `Devicetree` entry appended LAST;
Pci rows stay first and are audited-ignored on zephyr_c.**
`e1000-composed` gains `Devicetree { compatible = "regseq,e1000" }`;
`e1000-initfail` gains `Devicetree { compatible = "regseq,e1000fail" }`
(mirrors its `e1000fail` module name; distinct DT_DRV_COMPAT keeps both DUTs
bindable side by side). zephyr_c consumes the DT entry natively (ratified
static-DT form) and triple-render-audits the Pci rows (RSEQ-IGNORED-MATCH C
block + conformance `ignored_match_entries` + binding-yaml section); linux_c
symmetrically audits the new DT entry — its goldens/conformance change ONLY by
those licensed audit lines; generic_c traces only the FIRST entry, so the
frozen oracle pair stays byte-identical, **proven unblessed-first before any
zephyr bless** (exact pl011 D09 precedent). Rejected: deriving a compatible
from the Pci entry (synthesizes a transport-equivalent entry —
never-synthesize violation); escalating as a model gap (the D03(a) machinery
already licenses exactly this shape). Evidence: qemu_x86.dts:71-81 PCIe-over-DT
form; match_audit.rs native_on; pl011-composed input.rs:375-386.
Provenance: design-intended on code-confirmed machinery. Confidence: high.
Impact: fixture edits + zephyr_c Pci-audit arm exercise + linux/generic
unblessed-first proof. Test: L0 audit-render tests; runner unblessed diff
clean on golden.c/expected.stdout/golden.linux.c body (audit lines only).
Surfaces: S04, S06.

**D02 — BRM preamble order: adopt the reference order (probe → enable → map)
as THE single recorded per-OS deviation; never silent.**
Witness eth_e1000.c:219-224 (`pcie_probe_mbar` → `pcie_set_cmd(MEM|MASTER)` →
`device_map`): BAR sizing with memory decode off is the architecturally safe
PCI bring-up. Op mapping: `get_resource_handle` = `pcie_get_mbar` (hoisted
before enable — the deviation); `claim_regions` = zero-call elision
(called-out comment + oracle-side whitelist, the ratified zephyr claim
disposition); `enable_device` = `pcie_set_cmd(PCIE_CONF_CMDSTAT_MEM, true)`
(this fixture authors no `set_bus_master`, so only the MEM gate fires; the
separable-calls + single-call-fusion-peephole policy stands unexercised);
`map_region` = `device_map(..., K_MEM_CACHE_NONE)`. Rendered explicitly:
audit comment at the emit site + ledger/doc row; the platform/Amba path stays
strictly canonical. Rejected: canonical order on PCIe (unwitnessed sequence);
model escalation (blocks the unit for no design gain). Provenance:
spec-derived (ledger A-3 position) ratified here. Confidence: high.
Impact: zephyr_c PCIe preamble emission + docs row. Test: golden.zephyr.c
snapshot; L3 oracle-side whitelist entries absorb the BUS-marker differences
(config/bus markers are excluded-with-containment on the capture side, so no
reorder license is expected to be needed — confirmed at L3 task). Surfaces:
S01, S03, S12.

**D06 — Offset-0 cache at containing-word granularity.**
Any config READ whose containing word is word 0 (byte offsets 0x00–0x03 —
both `vendor@0x00` and `device@0x02`) is served from `dev->pcie->id` with the
§B.4 shift/mask marshalling — zero bus traffic; all other offsets
(`revision@0x08`, `BAR0@0x10`, the D05 RMW read) issue real
`pcie_conf_read` calls. Matches the host PCI-ID-caching semantics
(prelude.rs:260-288; `struct pcie_dev` carries the full 32-bit VID|DID). The
L3 capture-side containment expectation carries this (no word-0 traffic).
Rejected: literal offset-0x00-only cache (diverges from the host rule for the
device-id half). Provenance: spec-derived (A-4) with scope ratified here.
Confidence: high. Impact: config-read lowering + whitelist wording. Test: L0
emit tests (word-0 read compiles to id extraction); L3 containment. Surfaces:
S02, S11.

## Formal Contracts

**C01 — Zephyr-PCIe preamble (order, rungs, op mapping).**
[design-intended; ratified deviation per D02; witness eth_e1000.c:208-262]

```
Init fn body, PCIe arm, in emission order (before the authored on_init body):

  1. BDF rung:        if (data->pcie->bdf == PCIE_BDF_NONE) return -ENODEV;   /* native channel, unwrapped */
  2. install carrier: __rseq_pcie = data->pcie;                                /* D12; TU-static struct pcie_dev * */
  3. get_handle:      struct pcie_bar mbar;
                      if (!pcie_get_mbar(data->pcie->bdf, <effective_bar>, &mbar))
                          return -ENODEV;                                      /* native channel, unwrapped */
                      /* RSEQ-DEVIATION: get_resource_handle hoisted before enable_device —
                         the single ratified per-OS preamble deviation (this GRILL D02);
                         BAR sizing with memory decode off, witness eth_e1000.c:219-224 */
  4. claim_regions:   /* zero-call elision, called-out comment (ratified zephyr claim disposition) */
  5. enable_device:   pcie_set_cmd(data->pcie->bdf, PCIE_CONF_CMDSTAT_MEM, true);
                      /* op-per-op gating; set_bus_master (PCIE_CONF_CMDSTAT_MASTER) only when
                         that op is authored; single-call fusion permitted as peephole when both
                         gates fire (ratified policy, unexercised by this fixture) */
  6. map_region:      device_map(&<tu_static_base>, mbar.phys_addr, mbar.size, K_MEM_CACHE_NONE);
                      /* TU-static mm_reg_t base carrier (A-2) + the mandatory
                         BUILD_ASSERT(DT_NUM_INST_STATUS_OKAY(DT_DRV_COMPAT) == 1, ...) guard
                         covering BOTH TU-statics (base + __rseq_pcie) */

effective_bar := platform.<os>.toml [mmio.<id>] `bar` value (a BAR NUMBER) → pcie_get_mbar
                 (never pcie_probe_mbar's memory-BAR ordinal). [D04]
Platform/Amba path: strictly canonical, unchanged.
```

**C02 — Sub-word config WRITE lowering (width 1/2) — the ratified B-3 lift.**
[design-intended per D05; widths 4 native; widths 8 and 64-bit writes remain
D.2 rejections]

```
write_config::<u8|u16>(off, val) lowers to (containing-word RMW, bus-observable):

  unsigned int  __w   = (off) >> 2;                        /* pcie word index ("not address", pcie.h:187) */
  uint32_t      __cur = pcie_conf_read(__rseq_pcie->bdf, __w);
  uint32_t      __sh  = ((off) & 0x3u) * 8u;               /* byte lane */
  uint32_t      __msk = (width==1 ? 0xFFu : 0xFFFFu) << __sh;
  /* width==2 requires (off & 0x1) == 0; misaligned halfword = emit-time reject (D.2) */
  pcie_conf_write(__rseq_pcie->bdf, __w, (__cur & ~__msk) | (((uint32_t)(val) << __sh) & __msk));

  /* RSEQ-RMW audit comment at the emit site: one extra word read; adjacent bytes
     rewritten with read-back values (benign per PCI config semantics; QEMU
     e1000_write_config reacts only to PCI_COMMAND, hw/net/e1000.c:1624). */

L3 consequence: a width-1/2 authored config write appears in capture as one
pci_cfg_read + one pci_cfg_write of the containing word (containment wording).

Rejections kept (D.2/B-3): write_config width 8 (two-word split undesigned);
read_config width 8; 64-bit anything; misaligned sub-word.
```

**C03 — Config READ lowering + word-0 cache.** [spec-derived §B.4 + D06]

```
read_config::<T>(off), width w ∈ {1,2,4}:
  word index __w = off >> 2; shift __sh = (off & 0x3)*8; (alignment: off % w == 0, else emit-time reject)

  source word :=
    if __w == 0:  __rseq_pcie->id          /* VID|DID, zero bus traffic — covers vendor@0x00 AND device@0x02 */
    else:         pcie_conf_read(__rseq_pcie->bdf, __w)

  result := (T)((source >> __sh) & width_mask(w))

The D05 RMW's internal read always issues a real pcie_conf_read (its target
words are never word 0 — and if an author wrote a sub-word write to word 0,
the RMW still reads the LIVE word, never the cache).
L3 containment expectation: NO config bus traffic for word-0 reads.
```
