## Context

**Problem.** The shipped `linux_c` backend (merge `cb40658`, PL011 first light) lowers AMBA platform drivers only. Three fail-loud seams name `backend/linux-c-e1000` as their delivering unit: the PCI-bus rejection (`crates/regseq-backends/src/linux_c/mod.rs:144-149`), the `on_surprise_remove` rejection (`mod.rs:445-455`), and the TU-path Config-intrinsic rejection (`body.rs:646-649`). The config-space body lowering itself already exists at the `LowerCx::emit_config` seam (`body.rs:1459`, ratified A-11 `(void)`-discard shape) and needs the device pointer threaded.

**Goal.** Extend `linux_c` along the device-complexity axis: PCI scaffold (pci_driver, probe/remove/shutdown, pci_device_id table), PCI bus-resource management (managed enable → request regions → BAR map), and config-space lowering activated by device-pointer threading — validated by a composed E1000 fixture through the full L0–L3 ladder against the QEMU 82540EM.

**Consumers/actors.** The compiler pipeline (emit_linux_c callers), the eval campaign harness (generated-module DUT swap), the Zephyr parallel unit (merge-discipline counterparty), the thesis evaluation (device-complexity evidence).

**Non-goals.** A functioning NIC (no DMA/IRQ/netdev constructs exist); the eval W1 ping band; >1 simultaneously resolved regions (B-5); B-11/B-12 resolution; `BarType::Io`; width-8 config; ethtool/WoL/VLAN/AER surfaces; any generic_c modification.

**Hard constraints (fixed, not relitigated).** F-1 independent lowering with generic_c as frozen oracle (D12/I01 of the prior unit); ratified A-3 (lexical-scope `dev_*`, `pr_*` in lowered bodies), A-10(a) (literal L2 `base`/`size` trigger, fail-loud `UnresolvedBinding`), A-11 (explicit `(void)` status discard, reads and writes), A-12 (width-8 MMIO = `CONFIG_64BIT`-gated); D04 emission shape (one TU + Kbuild fragment, Linux-native ordering); the L0–L3 validation-ladder pattern; C04 whitelist-cites-ratified-decisions discipline.

## Decisions

**D01 — Composed fixture scope: full five constructs + config ops.** The composed E1000 fixture is the PCI mirror of the PL011 composed fixture: E1000 MMIO bring-up patterns (CTRL RMW, ICR read-clear, TDBAL/TDBAH high-then-low split, register arrays with runtime indices — per `tests/fixtures/regaccess-e1000/src/lib.rs`) + standard-header config ops + lifecycle scenarios + diagnostics-logging + RegseqError. It is explicitly an MMIO bring-up slice, not a functioning NIC; the gap to the eval W1 band (needs DMA/IRQ/netdev constructs that don't exist) is ratified and recorded.
*Rationale:* maximizes composition evidence on the device-complexity axis. *Rejected:* lean three-construct fixture (weaker eval artifact); blocking on unbuilt constructs. *Provenance:* design-intended. *Confidence:* high. *Test impact:* oracle trace via generic_c (M1-mirror), `golden.linux.c` snapshot, L2/L3 subject. *Surfaces:* S05, S07.

**D02 — Single resolved region (BAR0), scaffold-ready; B-5 is its own later unit.** First light maps exactly one resolved region. The PCI scaffold is written per-region-shaped (`effective_bar` drives request/map) so additional regions are mechanical later, but no >1-region surface is claimed or tested this unit; `linux_c` keeps the fail-loud rejection for >1 resolved region, naming B-5. "Multi-region BRM" in the unit charter means the PCI region machinery, not simultaneous mappings.
*Rationale:* the >1-region rejection lives in the frozen oracle (`generic_c/mod.rs:248` → `body_emit.rs:5072`); a two-region fixture cannot have an oracle trace without violating F-1/D12. B-5 requires a model+oracle extension — a unit of its own. *Rejected:* backend-only multi-region (unvalidatable at L3); blocking on B-5. *Provenance:* code-confirmed (the forcing fact) + design-intended (the scaffold shape). *Confidence:* high. *Test impact:* L0 structure test asserting the >1-region fail-loud names B-5. *Surfaces:* S01, S02, S15.

**D03 — B-11 deferred via the dead-literals precedent.** The composed fixture's platform.toml carries semantically-dead L2 `base`/`size` literals (the `brm-e1000-keystone` precedent) satisfying ratified A-10(a) unchanged; the literals are visibly commented as dead. B-11 (per-OS mappable predicate) stays escalated to the construct owner, to be designed after both OS backends exist.
*Rationale:* respects the ledger's explicit sequencing (Zephyr only just staged) and the short-branch preference; zero model change. *Rejected:* resolving B-11 now (grows the unit into model-surface territory, front-runs Zephyr's input). *Provenance:* spec-derived (ledger A-10/B-11) + design-intended. *Confidence:* high. *Test impact:* covered by the existing A-10 gate test; fixture comment review. *Surfaces:* S05.

**D04 — Config-space device-pointer threading: container recovery, per-site, driver-receiver only.** At each config-op site, the emitter materializes the device expression INSIDE that op's own braces block via `container_of(<receiver>, struct <drv>_priv, inner)->pdev` (shape pinned in C01; the write shape gains a braces block to carry it). The recovery is strictly per-site: no function-scope `pdev` local is introduced, so no lowered body ever has a device pointer in scope outside a config-op block — which is what keeps A-3 intact. `container_of` is compile-time pointer arithmetic; repeating it per site costs nothing. A config intrinsic is legal ONLY in a body whose receiver is the driver type; in any other body it fails loud naming the restriction. Additionally (I06 corollary): a config intrinsic in a TU whose driver is non-PCI fails loud at emit in `linux_c` — a backend-local guard that does not wait for the model-level BRM-001 diagnostic. **A-3 is not loosened:** logging in lowered bodies remains `pr_*`.
*Rationale:* sound because the scaffold is the sole instantiation site (every `&<drv>` points into a priv container, code-confirmed in the AMBA scaffold; preserved in the PCI scaffold); mirrors real drivers' `adapter->pdev` idiom (witness: `e1000_main.c:961` `adapter->pdev = pdev`); the ledger's C-4 already anticipates `container_of` morph recovery. *Rejected:* once-per-body function-scope recovery (would put a device pointer in body scope, weakening the A-3 story, and the block-scoped variant of it doesn't compile across sibling blocks); signature threading (changes lowered signatures, call-graph analysis, the option A-3 rejected for logging); scaffold-sites-only restriction (guts the deliverable). *Known risk:* bakes an aliasing assumption that holds by scaffold construction; any future construct materializing a driver value outside priv must revisit this. *Provenance:* design-intended (recovery), code-confirmed (single-instantiation premise). *Confidence:* high. *Test impact:* L0 snapshot shows the per-site recovery; structure tests for the driver-receiver restriction rejection and the non-PCI rejection; existing `emit_config` seam tests updated to the bracketed write shape. *Surfaces:* S03, S02.

## Formal Contracts

**C01 — Config-op emission contract (activates the existing `emit_config` seam).** *Provenance: design-intended (read-shape discard code-confirmed at `body.rs:1474-1484`; write shape amended to bracketed form).*

Legality: `IntrinsicKind::Config(op)` in the TU call-interception path is legal iff (a) the TU's driver has `bus_type == Pci`, and (b) the enclosing body's receiver type is the driver type. Violations are `EmitError::Unsupported` naming the precise restriction (non-PCI driver; non-driver receiver).

At each legal site, the device expression is recovered **inside that op's own braces block** — strictly per-site, never hoisted to function scope (no lowered body ever holds a device pointer outside a config-op block; this is what keeps A-3 intact). `container_of` is compile-time pointer arithmetic; per-site repetition has zero runtime cost.

- Read (widths 1/2/4; width-8 = fail-loud per B-3):
```c
{
        struct <drv>_priv *__rseq_priv = container_of(<receiver>, struct <drv>_priv, inner);
        <carrier> __cv;
        (void)pci_read_config_<byte|word|dword>(__rseq_priv->pdev, (int)(<off>), &__cv);
        <dst> = (<dst_cty>)__cv;
}
```
- Write (widths 1/2/4):
```c
{
        struct <drv>_priv *__rseq_priv = container_of(<receiver>, struct <drv>_priv, inner);
        (void)pci_write_config_<byte|word|dword>(__rseq_priv->pdev, (int)(<off>), (<carrier>)(<val>));
}
```

The `(void)` discard is the ratified A-11 shape, both directions, never silent. Includes: `<linux/pci.h>` (and the kernel's `container_of` via `<linux/container_of.h>`/`<linux/kernel.h>` per campaign-tree convention) recorded via the helper-usage mechanism. The PCI priv container places `struct pci_dev *pdev;` as the kernel back-pointer member (PCI analogue of the AMBA `adev`), and `inner` remains the embedded spec driver, so `container_of` recovery is well-defined for every lifecycle-driven invocation (sole instantiation site = scaffold).

**C03 — L2 definition for the PCI NIC.** *Provenance: design-intended (runbook mechanics spec-derived from `05-linux-native-pilot-runbook.md`).*
Topology: q35 VM, campaign kernel, DUT `-device e1000` (82540EM, 8086:100e) at a pinned slot (deterministic BDF), stock `e1000` blacklisted at boot (`modprobe.blacklist=e1000`), management NIC separate.
Happy path: insmod the generated module by path → `driver_override` → bind → probe returns 0 (dmesg) → MMIO bring-up executed against the device model → unbind/rmmod → no oops, no devres leak warnings. The generated module registers no netdev; "bind" = driver-core bind + probe success.
Induced failure (D07): the failure-variant module's probe must fail with the expected negated errno visible in dmesg, run `on_init_failure`, leave no oops and no leaked resources (devres unwind), and the device must remain bindable afterward (e.g., by the happy-path module).

**C04 — Composed-fixture platform.toml shape.** *Provenance: design-intended (precedent code-confirmed in `brm-e1000-keystone/platform.toml`).*

```toml
version = "1"

[platform]

board = "qemu-pc"

```
