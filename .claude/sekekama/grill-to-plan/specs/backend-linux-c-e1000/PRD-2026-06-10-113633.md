# PRD — backend/linux-c-e1000 (PCI scaffold, config space, E1000 keystone)

## Problem Statement

The `linux_c` backend lowers AMBA platform drivers only. A consumer presenting a PCI-bus RegseqModel — the E1000 device spec being the motivating case — is rejected at three fail-loud seams that name `backend/linux-c-e1000` as their delivering unit: the PCI bus dispatch, the `on_surprise_remove` path, and config-space intrinsics in lowered TUs. The thesis evaluation needs the device-complexity axis demonstrated: a PCI device with bus-managed resources and config-space access, lowered from the same model that the frozen `generic_c` oracle lowers, validated behaviorally against the QEMU 82540EM. Separately, the errno-adapter error machinery shipped in the first unit has never executed at runtime — its first witness is owed.

## Solution

Extend `linux_c` with a PCI scaffold (pci_driver registration, probe/remove/shutdown callbacks, multi-row device-id table), PCI bus-resource acquisition (enable → request regions → map BAR0, managed teardown), and activated config-space lowering (per-site container recovery threads the device pointer to the existing A-11 discard shapes). Prove it with a composed E1000 fixture (all five built constructs + config ops — an MMIO bring-up slice, explicitly not a functioning NIC) through the full L0–L3 ladder: snapshot + structure tests, kbuild, QEMU bind/teardown including an induced-failure run, and trace-diff against the committed oracle trace. Single resolved region (BAR0) this unit; the scaffold is per-region-shaped so B-5 (true multi-region) lands later as its own model+oracle unit.

## Requirements

R01. As the compiler pipeline, I want `emit_linux_c` to lower a single-driver PCI-bus model to one kernel-idiomatic TU + Kbuild fragment, so that the existing public API serves PCI without new entry points. (GRILL D02/D06/D09; S01. Provenance: design-intended on a code-confirmed dispatch seam.)

R02. Given a PCI-bus model, when the scaffold is emitted, it must produce: a per-device priv container with a `struct pci_dev *pdev` back-pointer and the embedded spec driver; `.probe` with the canonical order create → associate → preamble → on_init and the relocated negated-errno adapter; `.remove`; `.shutdown` only when `on_system_shutdown` is overridden. (D06; S02.)

R03. The probe preamble must follow the witnessed acquisition shape — enable device → `pci_request_selected_regions(pdev, 1<<effective_bar, <name>)` → map BAR0 — in the managed (`pcim_*`/devres) variant ratified by A-2, with no explicit release ladder in `.remove`. The exact devres cascade and the map-call choice (`pci_iomap` vs `pci_ioremap_bar` vs `pcim_iomap`) are pinned by the scaffold task per GRILL O3 (load-bearing: no in-corpus managed-PCI witness exists) before the emission shape is snapshot-locked. (D06(2); S02.)

R04. Given a driver overriding `on_surprise_remove`, the emitted `.remove` must be one `void` function branching on `pci_device_is_present(pdev)` — orderly arm runs `on_deinit`, surprise arm runs `on_surprise_remove` with no MMIO-touching releases; the surprise arm is verified at L0 snapshot only. (D06(3); S02.)

R05. The match-table emission must read the FULL `match_set` into a multi-row `pci_device_id[]` with zero sentinel plus `MODULE_DEVICE_TABLE(pci, ...)`. (D06(4), B-6 rule; S04.)

R06. Given a config intrinsic at a legal site (PCI driver, driver-type receiver), the emitter must lower it per GRILL C01: per-site `container_of` recovery inside the op's own braces block, width-selected `pci_{read,write}_config_*` with the ratified A-11 explicit `(void)` discard in both directions. No lowered body holds a device pointer outside a config-op block. (D04, C01; S03.)

R07. Given any surface outside this unit's ratified scope, emission must fail loud with a named diagnostic: config intrinsic on a non-PCI driver; config intrinsic in a non-driver-receiver body; >1 resolved region (naming B-5); width-8 config (B-3); unresolved MMIO binding (ratified A-10). Nothing silently truncates. (D02/D04; S01, S03.)

R08. As the eval campaign, I want a composed E1000 fixture exercising all five constructs + config ops — E1000 MMIO bring-up patterns (CTRL RMW, ICR read-clear, TDBAL/TDBAH split, register arrays with runtime indices), standard-header config reads + one benign config write, lifecycle scenarios, logging, RegseqError — with a platform file per GRILL C04 (bar + dead literals, visibly commented), so that the device-complexity composition has an oracle trace and a generated Linux driver from one source. (D01/D03/D10, C04; S05. Note: D10's config-write target is provenance `assumed`.)

R09. As the error-machinery witness, I want an induced-failure fixture variant whose `on_init` deterministically returns `Err` against the QEMU device model, so that authored Err → `on_init_failure` → negated errno → visible probe failure is exercised at runtime for the first time. (D07; S06.)

R10. Given the new emission paths, the L0 suite must lock them: `golden.linux.c` snapshots (sole-binary BLESS) plus named structure tests for the PCI scaffold shape, the ≥2-row id table + sentinel + `MODULE_DEVICE_TABLE`, the per-site recovery expression, both config rejections, the >1-region rejection naming B-5, and the surprise-arm present predicate. (D05, C02 item 1; S07.)

R11. Given `RSEQ_LINUX_KDIR` set to the campaign tree, `linux_kbuild_e2e` must compile the generated driver(s) with zero errors (warnings recorded, not gating); unset must skip visibly, never silently pass. (D05, C02 item 2; S08.)

R12. As the eval harness, I want the generated module to bind the QEMU 82540EM per GRILL C03 — driver_override bind, probe returns 0, MMIO bring-up executes, clean unbind without oops — and the failure-variant module to fail probe with the expected errno, no oops, no leaked resources, device still bindable afterward. (D05/D07, C03; S09.)

R13. Given L2 passes, L3 must run `trace-diff` against the committed oracle trace with zero unwhitelisted deviations, every whitelist entry citing a ratified decision. The capture mechanism is an O1-style spike, mandated as the FIRST task of the L2/L3 milestone; the spike determines config-space observability (uncapturable ⇒ cited whitelist exclusion of config events). (D05, C02 item 4; S10, S11.)

R14. The unit merges only when GRILL C02 items 1–5 all hold; if the parallel Zephyr unit merges first, this branch rebases onto the new main and re-runs the full gate before merging. (D05/D08.)

## Invariants & Contracts

I01. `generic_c` is the frozen behavioral oracle; backend work never mutates it. Composition bugs are fixed in bridge/model/recognition; a proven oracle fault stops work and escalates. (F-1/D12 carryover.)

I02. The ratified A-items hold unchanged: A-3 (`dev_*` only where lexically in scope in scaffold-synthesized statements; `pr_*` in all lowered bodies — NOT loosened by the config recovery), A-10(a) (literal trigger + fail-loud), A-11 (visible `(void)` discard), A-12 (width-8 `CONFIG_64BIT` gate).

I03. Every unsupported path is a loud, named diagnostic — naming the delivering unit or ledger item where one is scheduled; no silent truncation anywhere.

I04. Committed snapshots and the oracle trace are byte-exact regression locks, re-blessable only via their sole binaries; the tree is green at every commit.

I05. Cross-repo coupling stays at exactly two seams: the `RSEQ_LINUX_KDIR` env contract and the committed oracle-trace artifact; eval-side scripts/tools/whitelist live in the eval repo on eval main.

I06. Exactly one resolved region per driver this unit; the scaffold remains per-region-shaped (no >1-region surface claimed).

Formal contracts (authoritative in the GRILL): **C01** config-op emission (legality + per-site recovery + discard shapes), **C02** merge gate, **C03** L2 definition (topology, happy path, induced failure), **C04** composed-fixture platform.toml shape.

## Implementation Decisions

- Extend the existing `linux_c` backend module in place: replace the PCI arm of the bus dispatch, add the PCI scaffold alongside the AMBA scaffold, activate the existing `emit_config` seam from the TU call-interception path. No new public API; no `BackendOptions` extension (D09, provenance `assumed` — revisit only if a real knob emerges).
- Device-pointer threading is per-site container recovery, driver-receiver only (D04/C01) — chosen over signature threading and over scaffold-sites-only restriction. Its soundness premise (scaffold is the sole driver instantiation site) is code-confirmed.
- B-11 deferred via dead literals in the platform file (D03, C04); B-12 stays escalated with the interim discard shipping; B-5 deferred with a fail-loud naming it (D02).
- PCI lowering pins per D06: `readl`/`writel` family accessors; managed acquisition (shape witnessed in the vendored e1000, managed variant from ratified A-2 — see GRILL O3, load-bearing); present-predicate `.remove`; full-match-set id table.
- New composed + failure-variant fixtures live in the coverage-runner fixture tree; `tests/fixtures/regaccess-e1000/` is untouched (negative space, S13).
- Eval-side work extends the existing e1000 harness on eval main, adapting the PL011-pattern script pair (D08).
- Process: commit per task close, Codex chunk-close reviews via codex-runner, gate-report at decision points (D08).

## Failure & Recovery

- **Emission failures** are loud, named errors (R07); the named-unit convention continues for surfaces scheduled beyond this unit. I02/I03 hold on every failure path.
- **Authored on_init failure** (now runtime-witnessed, R09): goto ladder runs `on_init_failure`, the adapter returns the negated errno, devres unwinds all managed acquisitions, the device remains bindable. Native preamble failures propagate their kernel status directly, never wrapped (two-channel rule).
- **kbuild failures** surface compiler stderr verbatim; missing `RSEQ_LINUX_KDIR` is a visible skip.
- **Capture-spike failure** (GRILL O1): blocks only merge-gate item 4; escalate with options rather than weakening the gate.
- **L3 mismatches** fail the gate; the only deviation channel is the cited whitelist.
- **Oracle-suspect bugs**: stop and escalate per I01.

## Testing Decisions

- Test external behavior at the established seams: L0 byte snapshots + named structure tests (prior art: the PL011 unit's `linux_pl011_e2e` + structure module; sole-binary BLESS discipline), L1 env-gated kbuild e2e, L2/L3 in the eval harness per C03/C02.
