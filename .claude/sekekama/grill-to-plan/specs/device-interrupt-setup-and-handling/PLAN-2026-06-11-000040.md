# PLAN — device-interrupt-setup-and-handling (construct #6, first slice)

## Overview

This plan implements the first slice of the `device-interrupt-setup-and-handling` construct (#6) in the regseq compiler (`regseq-compiler-asplos`, planned against `main` @ 119fa65): a typed `Interrupt` driver-struct field (`#[rseq::interrupt(id = "...")]`), a bound handler (`#[rseq::isr]` -> `IrqResult`), a fully compiler-managed line lifecycle on one cross-OS placement (register-disabled in the init preamble after all other resource preambles; enable only after `on_init` returns `Ok`; disable->deregister in the deinit postamble — contract C01), the `[interrupt.<id>]` L2 tenant (C03), the generic_c synchronous-fire host harness whose golden trace *is* the placement contract (C05/D07), linux_c lowering via the manual `request_irq(IRQF_NO_AUTOEN)`/`free_irq` pair (D09), and zephyr_c static `IRQ_CONNECT` lowering whose structurally-absent deregister is dispositioned through a **new capability-table row kind** — the table's first non-lifecycle row (C02/R07, an explicit task).

**Sequencing gate (hard precondition — M0):** NO implementation task starts until compiler units `unit/spec-convergence-pl011` and `backend/zephyr-c-e1000` have landed on `main` (GRILL hard constraint; PRD Implementation Decisions). Every task T01–T14 hard-depends on M0. Pre-gate activity is limited to non-code reconnaissance (reading the landed units' shapes, confirming the T05/T10 splice points). The DAG's internal ordering additionally notes which tasks sit closest to the gated units' surfaces (T10 same-crate as the zephyr unit; T11/T12-zephyr/T13 consume their landed shapes directly) — that is collision *analysis*, not permission to start early. Should the user later explicitly relax the gate, T01–T08 are the lowest-collision set to pull forward; absent that relaxation, the gate binds all tasks.

**Contract discipline:** every formal rule a task relies on cites a GRILL C01–C06/D01–D14 or PRD R01–R18/I01–I08 item. Open items O1–O5 are all non-blocking and harness-owned; where a task mints one of them (O1 trace spelling, O3 diagnostic IDs, O5 disposition-kind name), the task says so. Nothing else is invented.

**Milestone M1 is a true vertical slice:** the smallest valid spec (one `Interrupt` + one bare `#[rseq::isr]` returning `Handled`/`NotHandled`) flows attr recognition -> model -> L2 join -> generic_c emission -> compiled harness run -> the C01 golden trace asserted in `codegen-coverage-runner`. linux_c and zephyr_c are later milestones.

## Architecture & Components

### Components (all under `crates/` in the compiler repo)

1. **`regseq-model`** — `domain_attr.rs` gains `AttrData::InterruptResource { id, form }` (field attr, `field_attrs` table) and `AttrData::IsrBinding { field?, array_bind }` (method attr, `item_attrs` table), plus `FrameworkType::IrqResult`, all appended after the existing `Intrinsic = 0` / `FrameworkType = 1` discriminants per the append-only discipline (I06, S10). No new `IntrinsicKind` — first attribute-only resource construct. Also carries the per-resource/per-handler IR facts of design §4 (id, form, field path, bound method, `IrqResult` arm reachability).
2. **`regseq-config`** — `platform.rs` `PlatformBindings` (today mmio-only) gains structural, serde-only parsing of `[interrupt.<id>]` (C03 keys: `irq_number`, `trigger_type`, `trigger_polarity`, `priority`, `shared`). No semantics here (existing producer->model split: semantic checks live in `regseq-l2`).
3. **`regseq-driver/src/bridge/interrupt/`** — new recognition module (patterns: `bridge/device_lifecycle/recognition.rs`, `bridge/diag_log/validation.rs`, `bridge/framework_type.rs`) for `["rseq","interrupt"]` + `["rseq","isr"]`, the C06 check set, and Phase-4 materialisation joining handler <-> resource <-> L2 id.
4. **`regseq-l2`** — new `interrupt` tenant module + one `REGISTRY` entry (the registry was built for this), implementing C03 parsing/validation and per-target line-identity resolution (R10).
5. **Ordering-facts source** — the single queryable representation of the D14/D02/D09 placement facts (interrupt preamble last among resource preambles; enable after `on_init` Ok; disable->deregister in deinit postamble) that **all three backends consume identically** (R17; representation harness-owned, O2).
6. **`regseq-backends`** — `generic_c/` (prelude hook bank + reserved-ident list + wrapper + lifecycle placement at the `body_emit.rs` keystone seam), `linux_c/`, `zephyr_c/`, and `capability.rs` (schema extension: new disposition kind + non-lifecycle slot domain).
7. **`codegen-coverage-runner`** — fixtures/goldens/conformance/matrix wiring (patterns: `fixtures/_lifecycle/*`, `fixtures/_composed/pl011-absentslot-zephyr/`, `src/conformance.rs`).
8. **`tests/fixtures/pl011-full-spec`** — the aspirational fixture already authoring the surface; converges once the pipeline accepts it.

### Inter-component contracts

- bridge -> model: the recognized facts land only as appended `AttrData`/`FrameworkType` variants and interrupt tables with stable discriminants (I06, S10).
- config -> L2: raw `[interrupt.<id>]` sections pass structurally; the L2 tenant owns canonical-spelling validation and the join (C03, R10, R12).
- L2 -> backends: resolved per-target line identity (generic-c `irq_number` literal; linux-AMBA `dev->irq[0]`; linux-PCI `pdev->irq`; zephyr `DT_INST_IRQN(n)` with `irq_number` advisory) plus `shared` as single-source board truth (C03, D05, I08).
- ordering-facts source -> all backends: one queryable source for preamble position / safe point / teardown order (R17, D14); its observable form is the C01 grammar (I07).
- backends -> OS/trace: emission order equals C01 on every backend; `IrqResult` maps per C04 (`NotHandled` -> `IRQ_NONE` never suppressed, R08); generic_c speaks the C05 hook family; the wrapper acquires no locks (R18, C04).
- zephyr_c -> capability table: the absent deregister renders all four audit artifacts from its C02 row (I04); non-emission is never silent.
- frontend: the C06 diagnostic set is the complete reject/warn surface (R13); phase limitations surface only as loud emit-stage errors (I05, R02, R09).

## Build Order & Milestones

- **M0 — Gate (hard).** Precondition for ALL tasks: `unit/spec-convergence-pl011` and `backend/zephyr-c-e1000` merged to `main`. - **M2 — Frontend completeness, T08.** Full C06 diagnostic set, Option/array recognition fixtures, negative corpus, shared-discipline warning.

- **M4 — Capability schema + zephyr_c, T10–T12 (zephyr tasks gated).** New disposition kind, first non-lifecycle row, `IRQ_CONNECT` lowering with enable split, four audit artifacts.

## Tasks

**T01 — Model: interrupt attribute payloads + `IrqResult` framework type** (`regseq-model`)
- Scope: Append `AttrData::InterruptResource { id, form }` (form: single/option/array-N) and `AttrData::IsrBinding { field: Option<…>, array_bind: bool }` to `domain_attr.rs` with stable discriminants 2 and 3; append `FrameworkType::IrqResult = 1` after `RegseqError = 0`. Exact shape harness-owned within the discipline (S10).
- Depends on: M0 gate.
- Acceptance: new variants serialize/deserialize round-trip with prior-construct models unaffected (I06, S10); the three resource forms and three `IrqResult` arms are representable whole (I05); arm-reachability facts present for R09/R11 consumers and **strong enough to drive the R11 warning's reachable-`NotHandled` semantics (warn-on-unknown direction — see T08)**.
- Test seam: `regseq-model` unit tests: discriminant-stability + serde round-trip + old-model deserialization.
- Size: M. Risks: sibling-table shape is design-intended (S10 "considered"), not code-confirmed; keep it minimal so O2 (T05) doesn't constrain it.
