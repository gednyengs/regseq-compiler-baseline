# PRD — device-interrupt-setup-and-handling (construct #6, first slice)

## Problem Statement

A Regseq spec author writing a device driver (PL011 UART, E1000 NIC) has no way to declare the
device's interrupt line or bind a handler to it: the compiler pipeline has zero interrupt support
(no model variant, no bridge recognition, no backend lowering), so no generated driver can react to
the device. The consumers are (a) the spec author, who needs an OS-invariant way to say "this device
has a line; this method services it"; (b) the three backends, which need one placement/ordering
contract to lower against (Linux registers at runtime, Zephyr connects at build time); and (c) the
eval Tier-2 campaigns, which need the generated behavior to be traceable, conformance-reported, and
deliberately whitelisted where it deviates from stock drivers.

## Solution

Implement the frozen taxonomy surface for this construct, first slice: a typed `Interrupt`
driver-struct field (`#[rseq::interrupt(id = "...")]`) plus a bound handler (`#[rseq::isr]` →
`IrqResult`) — the only two author-facing elements — with the entire line lifecycle compiler-managed
on one cross-OS placement: register line-disabled in the init preamble, enable after `on_init`
succeeds, disable→deregister in the deinit postamble. L2 `[interrupt.<id>]` platform entries carry
line identity + the four line properties. Zephyr's structurally-absent deregister is dispositioned
through a new audited capability-table row kind. generic-c gets a synchronous-fire host harness whose
golden trace *is* the placement contract.

## Requirements

R01. As a spec author, I want to declare `#[rseq::interrupt(id = "...")] irq: Interrupt` on my driver
struct, so that the compiler emits the full line lifecycle for that line. `id` is **mandatory on every
resource** (D08, deviation noted in Conformance). [S01; design-intended]

R02. Given the `Option<Interrupt>` and `[Interrupt; N]` forms, when a spec declares them, the bridge
must recognize them and run all frontend checks, and any attempt to *lower* them this phase must fail
with a loud `EmitError`; the recognized surface is never silently narrowed. (D06) [S01]

R03. As a spec author, I want `#[rseq::isr]` (bare when exactly one resource; `field = "..."`
otherwise; array-bind carrying `index: usize`) on a `&mut self` method returning `IrqResult`, so that
my authored body — pure register-access composition — services the line. Signature and per-target
return mapping: GRILL C04. [S02; spec-derived]

R04. Given a driver with an `Interrupt` resource, when the device-lifecycle init preamble runs, the
compiler must register the handler with the line **disabled** (Linux `request_irq` with
`IRQF_NO_AUTOEN`; Zephyr `IRQ_CONNECT` without immediate `irq_enable`), ordered **after** all other
resource preambles (bus ops, `map_region`). (D01, D14, C01) [S04]

R05. Given a successful `on_init`, the compiler must then — and only then — enable the line; on
`on_init` → `Err`, enable must never run. (D02, C01) [S04]

R06. Given orderly teardown, the deinit postamble must emit line `disable` then deregister; linux_c
uses the explicit `free_irq` pair (no devm). (D09, C01) [S04]

R07. Given the Zephyr static-connect target, where deregistration is structurally absent, the backend
must route the deregister slot through a **new** capability-disposition kind ("operation structurally
absent on this registration form" — not lifecycle `AbsentDispatch`) rendering all four audit
artifacts, must still emit `irq_disable`, and must state the post-deinit "connected-but-masked" state
in the conformance report. This **extends the capability table's schema beyond lifecycle slots** —
an explicit work item of this feature. (D03, C02) [S06]

R08. Given a handler returning `NotHandled` on Linux, the synthesized wrapper must deliver `IRQ_NONE`
to the OS verbatim (never suppressed); `Handled` → `IRQ_HANDLED`; on Zephyr the value is discarded
(void ISR convention); on generic-c it is traced. (C04) [S03]

R09. Given a spec whose handler can return `DeferWork`, emission on any backend without deferred-work
lowering must fail with a loud `EmitError` naming `deferred-work-item-scheduling`; frontend and IR
accept the arm. (D04) [S03]

R10. Given a `[interrupt.<id>]` platform-file section (schema: GRILL C03), the L2 binder must join it
to the resource by `id` and resolve line identity per target (generic-c `irq_number` literal;
linux-AMBA `dev->irq[0]`; linux-PCI `pdev->irq`; zephyr `DT_INST_IRQN(n)` macros with `irq_number`
advisory). A missing section for a non-`Option` resource is a frontend error. (C03, D13) [S05]

R11. Given L2 `shared`, linux_c must emit `IRQF_SHARED` **iff** `shared = true` (board truth; wrong
`false` fails loudly at `request_irq`), and the frontend must warn when `shared = true` and the bound
handler has no reachable `NotHandled` arm. (D05) [S05, S08]

R12. Given L2 `trigger_type`/`trigger_polarity`/`priority`, the binder must accept only the canonical
spellings (C03), generic-c must trace them, and **no backend emits trigger flags this slice**
(validation-first; DT is authoritative on both current targets; `priority` lowers only as the Zephyr
`IRQ_CONNECT` argument). (D10) [S05]

R13. Given extraction, the frontend must enforce the full check set with the taxonomy diagnostic IDs
— bare-ISR ambiguity, array-bind signature, duplicate handler, **zero handlers on a non-optional
resource**, unknown `isr(field)`, missing `id`, excluded-primitive rejection, driver-callable line
control — per GRILL C06. (D13) [S08; spec-derived IDs]

R14. Given the generic-c backend, it must emit the `regseq_irq_*` hook calls (C05) and the synthesized
wrapper such that a harness-driven **synchronous** `regseq_irq_fire` produces the deterministic golden
trace of GRILL C01; fire on a disabled/unregistered line is inert and traced. (D07) [S07]

R15. Given Tier-2 campaigns, the eval whitelists must carry (a) the probe-to-remove line-hold delta vs
stock Linux and (b) the Zephyr CAP-row citation, so neither deviation passes silently. (D01, D03)
[S09]

R16. Given a `request_irq` failure in the preamble, init must fail before `on_init` (so
`on_init_failure` is not invoked) and already-acquired preambles must unwind in reverse, per the
existing lifecycle preamble-failure contract. (D12) [S04]

R17. Given the placement/ordering facts (preamble position, safe point, teardown order), all backends
must consume them from **one** queryable source; the representation is harness-owned (GRILL O2).
(D14) [S04]

R18. Given the absence of the Synchronization construct, the wrapper must acquire **no** locks
(bound-handler discipline), and the known ISR↔mainline race is accepted as a documented phase
limitation: Tier-2 campaigns are pinned single-vCPU, fixtures keep ISR-shared state minimal, and the
obligation is recorded against the Synchronization construct's arrival. (D11) [S02, S04, S09]

## Invariants & Contracts

I01. The line is never enabled before `on_init` has returned `Ok`, on any backend. (C01)
I02. No driver-callable line-control surface exists — not as rejected calls but as unwritable API
     (`Interrupt` is methodless); reintroductions are frontend errors. (C06; boundary B3)
I03. The construct adds zero in-handler primitives; all device-source operations (mask/cause/ack)
     remain Register Access ops. (boundary B2; S14 negative space)
I04. Non-emission is never silent: every structurally-absent op renders all four audit artifacts from
     its capability row. (C02)
I05. The frozen surface stays whole and visible: 3 `IrqResult` arms, 3 resource forms — phase
     limitations exist only as loud emit-stage errors. (D04, D06)
I06. Model additions are append-only with stable discriminants (`AttrData`, `FrameworkType`). (S10)
I07. The emitted lifecycle order on every backend equals the C01 grammar; generic-c's golden trace is
     its observable form.
I08. L2 `shared` is single-source board truth: it drives both flag emission and the discipline check.
     (D05)

Formal contracts (authoritative in the GRILL): **C01** lifecycle placement/trace grammar · **C02**
Zephyr capability row · **C03** `[interrupt.<id>]` L2 schema · **C04** `IrqResult` mapping · **C05**
generic-c hook family · **C06** diagnostics set.

## Implementation Decisions

- **Model (`regseq-model`):** append `AttrData::InterruptResource` (field attr: `{id, form}`) and
  `AttrData::IsrBinding` (method attr: `{field?, array_bind}`); `FrameworkType::IrqResult`. No new
  `IntrinsicKind` — this is the first attribute-only resource construct. (dsl-surface §6; S10
  representation harness-owned within the append-only discipline.)
- **Bridge (`regseq-driver`):** new `bridge/interrupt/` recognition for `["rseq","interrupt"]` +
  `["rseq","isr"]`, the C06 validations, Phase-4 materialisation joining handler ↔ resource ↔ L2 id.
- **L2 (`regseq-l2`):** the `interrupt` `L2Binder` tenant parsing C03, with per-target identity
  resolution (R10).
- **Backends (`regseq-backends`):** generic_c hook family + wrapper + trace markers (oracle prelude
  bank, C05); linux_c probe-side `request_irq(IRQF_NO_AUTOEN | flags)` / `enable_irq` /
  `disable_irq` / `free_irq` + `irqreturn_t` wrapper; zephyr_c `IRQ_CONNECT` table emission with the
  enable split out of the config func, plus the **capability-table schema extension** (new disposition
  kind, first non-lifecycle row) and conformance wiring. (D01–D03, D09, C01–C02, C04–C05)
- **Lifecycle integration:** interrupt preamble/postamble slots into the existing
  register→create→associate→preambles→`on_init` synthesis, ordered last among resource preambles;
  enable is a new post-`on_init` emission point. (D14, D02)
- **Sequencing gate:** compiler work starts only after `unit/spec-convergence-pl011` and
  `backend/zephyr-c-e1000` land (zephyr_c scaffold collisions). [hard constraint from GRILL context]

## Failure & Recovery

- **Registration failure (Linux runtime):** init fails pre-`on_init`; reverse unwind of acquired
  preambles; `on_init_failure` not invoked; I01 holds trivially. (R16)
- **`on_init` → `Err`:** enable never runs (I01); unwind includes line unregister (Linux) /
  the capability-row disposition (Zephyr).
- **Wrong platform file (`shared = false` on a genuinely shared line):** loud `-EBUSY` at
  `request_irq` — treated as correct surfacing of a wrong L2, not masked. (R11)
- **Unsupported-this-phase reach (`DeferWork`, Option/array lowering):** loud `EmitError` naming the
  blocker; never partial emission. (R02, R09; I05)
- **Zephyr deinit:** handler remains connected-but-masked after `irq_disable` — stated in conformance
  + whitelist, never silent. (R07; I04)
- **Early/spurious firing window (post-enable, pre-open; shared lines):** handler contract is total
  over the quiescent device — cause-register read shows zero ⇒ `NotHandled`. (R08; model §5)

## Conformance

Governing spec: the **frozen taxonomy surface** (organized spec, Step-11 `verified` 2026-05-19) —
`spec-derived` items: the 6-op/1-L1/4-L2 surface, the three resource forms, `#[rseq::isr]` forms and
signatures, `IrqResult` arms, the C06 diagnostic IDs, boundaries B1–B4, the "exactly one handler"
invariant (D13), and the preamble-ordering invariant (D14). **Intended deviations:** (1) `id` always
required (D08 — tightening; taxonomy requires it only for multi-resource) and (2) `IRQF_NO_AUTOEN` as
the default Linux registration shape (generalizing the taxonomy's G-INT-04 init-probe escape) — both
recorded as taxonomy feedback notes, not applied to the frozen pages.

## Testing Decisions

Seams (from GRILL context, confirmed): **Tier-1 generic-c** — (a) golden-trace fixtures
(`codegen-coverage-runner`): the `irq-pl011` fixture's `expected.stdout` asserts the full C01
interleaving including fire-before-enable inert, masked-`NotHandled`, cause-`Handled` (with the
ICR-ack visible in the MMIO trace), post-deinit inert; (b) bridge unit tests for recognition + the §C06
check set; (c) the negative/reject set (every C06 row). Prior art: `regaccess-*` fixtures, lifecycle
`LC` trace scenarios, conformance JSON serialization. **Tier-2 QEMU** — pl011-linux and pl011-zephyr
campaign legs (single-vCPU pin per D11/R18): registration-window check (`/proc/interrupts`),
whitelisted deltas (R15), conformance artifacts (R07); e1000-linux follows on the same surface. Good
tests assert *observable order and OS-visible behavior* (traces, conformance JSON, `/proc` state),
never internal representation (the D14/O2 representation is free to change under them).

## Assumptions

The GRILL carries **no `assumed`-provenance decisions**. The least-settled items are its non-blocking
opens, all harness-owned and none load-bearing: O1 inert-fire trace spelling (blocking: false) ·
O2 ordering-facts representation (blocking: false; constrained by R17) · O3 three new diagnostic IDs
(blocking: false; `IRQ-ERR-*` family) · O4 `Interrupt`/`IrqResult` home crate (blocking: false) ·
O5 the new disposition kind's enum name (blocking: false; minted during the capability-schema
extension, R07).

## Out of Scope
