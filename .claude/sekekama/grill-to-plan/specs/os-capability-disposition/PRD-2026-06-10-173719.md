# PRD — os-capability-disposition

## Problem Statement

A Regseq spec author writes one driver spec with all four lifecycle callbacks
and expects it to lower on every supported OS backend. Today that is
impossible: the composed E1000 spec authors `on_surprise_remove`, linux_c
delivers it (present-predicate dispatch in `.remove`), and zephyr_c rejects
the whole spec at emit time per the D.2 fail-loud discipline — because
Zephyr's static-DT device model structurally cannot deliver a surprise-removal
event, and unlike deinit no future API is coming. The author's only options
are to fork the spec per OS (defeating the single-file thesis) or for the
backend to silently drop the callback (violating the no-silent-truncation
rule). The compiler needs a third disposition: *auditable non-emission* — but
only under guardrails that keep it from becoming a free-form D.2 escape
hatch.

## Solution

A closed, ratified, per-OS **capability table** (a backend-crate concern; the
DSL surface is untouched) amends D.2 with exactly one new mechanism: a
lifecycle slot whose dispatch condition provably cannot occur on a pinned
target OS may carry a ratified `AbsentDispatch` row, and ONLY then may the
backend non-emit the authored callback — leaving a named audit comment block
in the generated C, a row in a per-target conformance report artifact, and a
test-log line, with the callback body still fully checked by the complete
body-lowering pipeline. Everything not in a ratified `AbsentDispatch` row
keeps its existing fail-loud behavior. The table is version-pinned and
evolution-audited: re-pinning the OS without re-reviewing each row is a test
failure. This makes the thesis wording true by mechanism: differences between
OS lowerings are explicit, cited, and machine-checked — never silent (GRILL
C07).

## Requirements

R01. As a spec author, I want a spec that authors `on_surprise_remove` to
emit successfully under `TargetOs::Zephyr` (static-DT registration), so that
one spec file serves both Linux and Zephyr. The zephyr_c emitter consults the
capability table and, finding `CAP-ZEPHYR-DT-SURPRISE-1` (disposition
`AbsentDispatch`), non-emits the callback instead of rejecting. [D14, C03;
S03]

R02. Given an `AbsentDispatch` slot, when zephyr_c emits the TU, it must
place exactly one named audit comment block (grammar: GRILL C04) at the
position the callback's lowered code would have occupied — slot name,
disposition, ratified row ID, and the row's citation, generated from the same
table const the report cites. [D10, C04; S04]

R03. Given an `AbsentDispatch` slot, when the emitter processes the authored
callback body, it must run the COMPLETE zephyr_c body-lowering pipeline over
it and discard the output: any construct the backend would reject in a
delivered body is still rejected (a D.2 `EmitError`), and the discarded
lowering has no observable effect on the TU beyond the audit block. [D06;
S03, S10]

R04. Given a successful emit, both OS backends (`zephyr_c`, `linux_c`) must
return a `ConformanceReport` on their emit-result structs enumerating
delivered, absent-dispatch, and rejected slots with row IDs/citations
(schema: GRILL C05). The coverage runner serializes it to deterministic JSON
next to the emitted C; all composed fixtures' OS-target runs commit it as a
golden. [D08, D16, C05; S05, S06, S14]

R05. Given a fixture run that produces a conformance report, the test log
must print a delivered-vs-absent slot line derived from the same report
struct (single source — no independently computed list). [D08; S16]

R06. Given any emitter claim of dispatch-impossibility, the claim must be
expressed ONLY as a reference to a ratified `CapabilityRow` const (row-ID
grammar: GRILL C02); free-form prose claims are unrepresentable by
construction. [D03, D04, C01, C02; S01]

R07. Given the capability table in code and its ratified markdown mirror,
when either changes, a unit test must fail unless every code row's (ID, key
fields, disposition, pin, citation) appears verbatim in the doc and no doc
row lacks a code row; the failure names the first diverging field. [D03,
C08; S01, S02]

R08. Given a Zephyr OS-version re-pin (editing the single `ZEPHYR_PIN`
const), every Zephyr `AbsentDispatch`/`DesignedScheduled` row whose
`os_version_pin` no longer matches must fail the capability-table audit test,
naming each stale row ID, until each row is re-verified on the new pin and
its pin+citation updated (doc mirror forced by R07). [D12, C08; S01]

R09. Given the slots `on_init` and `on_init_failure` (`NEVER_ABSENT`), no
capability-table row may ever pair them with `AbsentDispatch` on any OS; a
test enforces this structurally. [D14, C01, C08; S01]

R10. Given the existing zephyr_c scheduling rejections (`on_deinit`,
`on_system_shutdown`), their diagnostics must gain the corresponding
`DesignedScheduled` row IDs (`CAP-ZEPHYR-DT-DEINIT-1`,
`CAP-ZEPHYR-DT-SHUTDOWN-1`) while preserving the existing wording guarantees:
the messages still name `device_deinit()`/`spec-convergence-pl011`/"designed
and scheduled per A-18" and still never contain "unsupported". [D14, C03;
S03, S10]

R11. Given the new mechanism, a dedicated on-disk zephyr fixture (indicative
name `pl011-absentslot-zephyr`, patterned on the initfail-variant precedent)
must author `on_surprise_remove` with a log-only body and commit
`golden.zephyr.c` (audit block visible) plus its conformance JSON, exercised
by a sole-binary e2e test (clean-process determinism rule). Its manifest
`covers` a new coverage-matrix row for the absent-slot mechanism, so the
ledger treats the absent slot as covered only via that explicitly marked row
and the existing drift-gate semantics are unchanged. [D13; S07, S08]

R12. Given the ratified rule, the spec docs must record it: the ratified
amendment texts (GRILL C06) and thesis wording (GRILL C07) in a ratified-rule
doc plus the capability-table mirror under the unit's discussion directory;
`zephyr-open-questions.md` §D.2's surprise row re-cited to
`CAP-ZEPHYR-DT-SURPRISE-1`, B-7 annotated resolved-by-row, A-12 annotated
superseded-by-the-rule. [D15, D17 (assumed); S02, S09]

R13. Given the trace-whitelist coupling rule (amendment 8), the ratified-rule
doc must record it as binding on `backend/zephyr-c-e1000`: any whitelist
entry licensing an absent slot's missing oracle markers must cite the same
CAP row ID + citation as the audit block, report, and test log. No eval-side
edits in this unit. [D11; S11]

R14. Given the required-callback policy (amendment 5), the ratified-rule doc
must record its semantics (required + `AbsentDispatch` row ⇒ emit-time
rejection; default `best_effort`) and name the successor unit
`callback-requirement-marker` that delivers the DSL marker. No
model/macro/bridge changes in this unit. [D07; S12]

## Invariants & Contracts

I01. D.2 remains the default: every legal-but-unlowered shape NOT covered by
a ratified `AbsentDispatch` row keeps fail-loud rejection at emit time. This
unit narrows the rejection space by exactly one mechanism.

I02. Only `Disposition::AbsentDispatch` may non-emit an authored callback;
the disposition enum is closed (GRILL C01). `DesignedScheduled` remains a
reject-at-emit scheduling diagnostic.

I03. Cross-artifact row-ID consistency is by construction: the C audit
block, conformance report, diagnostics, and (later) trace-whitelist entries
for one absent slot all derive from the same `CapabilityRow` const.

I04. Every `AbsentDispatch` row carries a non-empty citation containing the
pinned OS version (incl. commit) and ≥1 source anchor in the pinned local
checkout or vendored reference (the D05 bar; the L3 empty-ratified rule).

I05. All committed artifacts (golden C, conformance JSON, doc mirror) are
byte-stable — no wall-clock, fixed field order, deterministic slot order;
composed zephyr snapshots run in clean processes.

I06. `generic_c` source paths show an empty `git diff` at merge (F-1); the
oracle emits no conformance report (exempt, GRILL D09).

I07. `rejected_slots` is structurally empty in any committed conformance
report (rejection aborts the build); the field is retained per amendment 6.

I08. The coverage ledger's drift-gate semantics (`covered_without_green`,
`green_without_covered`, verdict rules) are unchanged; the absent-slot
mechanism enters coverage only via its explicitly marked matrix row.

I09. `NEVER_ABSENT` slots can never acquire an `AbsentDispatch` row, on any
OS, enforced by test (GRILL C08).

Formal contracts (authoritative in the GRILL): **C01** capability-table
types; **C02** row-ID grammar; **C03** initial rows + NEVER_ABSENT; **C04**
audit-block grammar; **C05** ConformanceReport schema; **C06** the nine
ratified amendment texts; **C07** thesis wording; **C08** audit-test suite.

## Implementation Decisions

- New `capability` module at the `regseq-backends` crate root (outside
  generic_c paths): closed enums, `CapabilityRow`, `ZEPHYR_PIN`,
  `NEVER_ABSENT`, the static `CAPABILITY_TABLE`, and row consts. Backend
  concerns stay in backend crates; regseq-model/macros/bridge untouched —
  the model already carries `TargetOs` and the lifecycle slots; the backend
  defines its own slot-name enum. [D03, C01]
- Source of truth = the typed Rust table; human ratification record = the
  markdown mirror; a sync test binds them (identity.rs first-divergence
  discipline). [D03, C08]
- zephyr_c surprise-remove path transitions from `Err(Rejected(B-7 prose))`
  to table-consulted non-emission (audit block + report row); the two
  scheduling rejections become table-cited without weakening their wording
  tests. [D06, D10, D14]
- Body-checked guarantee via full-lowering-discard, not a separate legality
  scan — checks cannot drift from the delivered path. [D06]
- `ZephyrEmit`/`LinuxEmit` gain `conformance: ConformanceReport`; the
  coverage runner owns serialization and file I/O (backends stay pure).
  generic_c is exempt with rationale recorded. [D08, D09, D16]
- Witness = dedicated absent-slot fixture + new matrix row; identity-locked
  fixtures untouched; linux conformance goldens added on existing composed
  fixtures. [D13]
- Initial table population: the four C03 rows; final citation file:line
  anchors verified against the pinned checkouts at implementation time per
  the D05 bar. [D14]
- Amendment 5 delivery and eval-side whitelist entries are successor-unit
  scope, recorded by name in the ratified-rule doc. [D07, D11]

## Failure & Recovery

- **Unsupported construct inside an absent body**: emit fails with the
  existing D.2 `EmitError` — non-emission never masks a body-legality
  failure (R03). The build aborts; no artifacts are produced.
- **Authored slot with no table row for (os, form, slot)**: the existing
  fail-loud rejection path runs unchanged (I01).
- **Table/doc drift, stale pin, NEVER_ABSENT violation, malformed row ID,
  empty citation**: unit tests fail naming the offending row/field (C08);
  the failure is a CI stop, not a runtime behavior.
- **Conformance JSON or golden C drift**: byte-exact snapshot tests fail in
  the sole-binary e2e (the established bless workflow applies).
- **Emit rejection (DesignedScheduled or D.2 default)**: no TU, no report,
  no audit block — rejection aborts the build before any artifact exists
  (hence I07).
- On every failure path, I01–I09 hold: there is no partial state in which a
  callback is silently absent without its ratified row, audit block, and
  report entry.

## Conformance

The governing record is the founding stress-test document
(`docs/discussions/os-capability-disposition/codex-stress-test-2026-06-10.md`):
Codex's verdict "adopt with amendments, not as drafted". The nine amendments
are adopted as ratified in GRILL C06 — amendments 1 and 3 deviate from
Codex's literal text by ratified amendment (the 5-variant enum adding
`DesignedScheduled`; the pin+source-anchor citation bar), amendment 5's
delivery is deferred to a named successor, and amendment 8's entries are
deferred to `backend/zephyr-c-e1000`. The thesis wording (GRILL C07,
spec-derived from Codex) is adopted verbatim. The existing ratified
disciplines being composed with — D.2 fail-loud, F-1 frozen core, the L3
empty-ratified rule, clean-process snapshot determinism, ledger drift gates
— are all preserved, not relaxed.

## Testing Decisions

Test external behavior at the established seams:

- **Emit-level (`zephyr_c/mod_tests.rs`)**: the existing
  `on_surprise_remove_is_rejected_citing_b7` test is REPLACED by: (a) legal
  body ⇒ successful emit with exactly one C04 audit block and the report row;
  (b) body containing a construct zephyr body-lowering rejects ⇒ `EmitError`
  (closes the Codex-found hole — the old test only proved slot rejection
  fired first); (c) scheduling rejections still carry their wording
  guarantees plus row IDs (R10). Prior art: the existing D06/A-18 negative
  tests in the same file.
- **Capability-module unit tests**: the C08 suite (doc-sync, pin staleness,
  citation bar, NEVER_ABSENT, ID grammar/uniqueness). Prior art:
  `identity.rs` tests for citation mechanics and first-divergence naming.
- **On-disk e2e (sole binary)**: the new absent-slot fixture byte-locks
  golden C + conformance JSON and prints the R05 log line. Prior art: the
  initfail-variant fixtures and `corpus_e2e.rs` clean-process discipline.
  Determinism check: run the producer twice (established assessment
  practice).
- **Ledger**: the new matrix row covered by the green fixture keeps the
  verdict machinery untouched — assert no drift entries appear.
- Verify behavior, not implementation: tests assert on emitted text, report
  JSON, diagnostics, and test exit status — never on internal lowering
  state.

## Out of Scope

- Any DSL-surface change (model/macro/bridge) — successor
  `callback-requirement-marker` (R14 records the policy only).
- Eval-side trace-whitelist entries — `backend/zephyr-c-e1000` (R13 records
  the rule only).
- Non-slot D.2 rejections (port-I/O, ClassTag, config-write widths,
  UserData, multi-region, multi-compatible) — remain prose-ledger; the
  table's domain is lifecycle slots this unit.
- suspend/resume — belongs to the separate PM construct; absence is decided
  there, never by lifecycle-callback analogy.
- generic_c changes of any kind (F-1).
- The west-gate live-workspace version assert (offered and not taken at
  GRILL D12).
- `spec-convergence-pl011` scope (deinit delivery, mixed-match consumption).
