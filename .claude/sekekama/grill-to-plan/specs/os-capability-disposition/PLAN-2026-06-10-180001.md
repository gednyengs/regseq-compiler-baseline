# PLAN — os-capability-disposition

## Overview

Deliver the ratified OS-capability-disposition mechanism (PRD `F-os-capability-disposition`, sourced from GRILL-2026-06-10-173356 and the founding Codex stress-test doc): a closed, version-pinned, evolution-audited per-OS capability table in `regseq-backends` that amends D.2 with exactly one new disposition — `AbsentDispatch` — under which zephyr_c auditably non-emits an authored `on_surprise_remove` (named `RSEQ-ABSENT-SLOT` audit block in the C, a `ConformanceReport` row, a test-log line) while still running the complete body-lowering pipeline over the discarded body. Both OS backends (`zephyr_c`, `linux_c`) gain `conformance: ConformanceReport`; the coverage runner serializes it to deterministic JSON goldens beside the emitted C; a dedicated absent-slot fixture plus a new coverage-matrix row witness the mechanism end-to-end; the rule, table mirror, amendment texts, thesis wording, and successor registry are recorded in docs. Everything not in a ratified `AbsentDispatch` row keeps fail-loud rejection (I01). `generic_c` is frozen and exempt (F-1, I06, D09). No DSL-surface or eval-side changes (S11, S12).

Scope note on R01: the in-unit Zephyr witness is the static-DT absent-slot fixture and the in-crate emit tests. The composed E1000 spec itself still hits zephyr_c's PCIe `UnsupportedInUnit` gate (`zephyr_c/mod.rs:144-149`) — the one-spec-three-backends E1000 emit is `backend/zephyr-c-e1000` scope, which consumes `CAP-ZEPHYR-DT-SURPRISE-1` from this unit.

## Architecture & Components

**Component 1 — `capability` module** (`crates/regseq-backends/src/capability.rs`, NEW, crate root, outside frozen `generic_c/` paths; S01).
Owns the C01 types verbatim (`Disposition` 5-variant closed enum, `RegistrationForm`, `LifecycleSlot`, `CapabilityRow`), `ZEPHYR_PIN`, `NEVER_ABSENT`, the four C03 row consts + `CAPABILITY_TABLE`, a keyed lookup helper (`bus_family == "any"` is a wildcard over the D02 key), and the C05 `ConformanceReport`/`SlotEntry` structs plus a `summary_line()` renderer (the single source for the R05 log line). **Component 2 — zephyr_c transition** (`crates/regseq-backends/src/zephyr_c/mod.rs`, rejection sites :224-250; S03, S04, S05-zephyr).
- `on_surprise_remove` (:232) changes from `Err(Rejected(B-7 prose))` to: look up `(Zephyr, ZEPHYR_PIN, bus, StaticDevicetree, OnSurpriseRemove)`; on `AbsentDispatch` row → run the COMPLETE body-lowering pipeline (resolve the callback root, `reachable_closure`, `scan_closure_ops` at :1026, `body::fn_head`/`body::emit_fn`) over the absent closure **in a throwaway `body::LowerCx`** and discard the output, then emit exactly one C04 audit block at the position the callback's lowered definition would have occupied in the bodies bank, and push the report row. The throwaway context is load-bearing: `LowerCx` accumulates `extra_includes`, `uses_log`, `width8_used`, `fn_symbols`, which feed `emit_tu` (:1145) — sharing it would let the discarded lowering perturb the TU, violating D06's "no observable effect beyond the audit block".
- The two scheduling rejections (`on_deinit` :224, `on_system_shutdown` :240) become table-cited: messages gain `CAP-ZEPHYR-DT-DEINIT-1` / `CAP-ZEPHYR-DT-SHUTDOWN-1` (rendered from the row consts' `id` fields, never literals) while preserving every existing wording guarantee (R10, C03).
- `ZephyrEmit` gains `conformance: ConformanceReport` (target `"zephyr_c"`, pin = `ZEPHYR_PIN`, slots in `LifecycleOps` declaration order; `rejected_slots` structurally empty — rejection returns `Err` before any struct exists, I07).
