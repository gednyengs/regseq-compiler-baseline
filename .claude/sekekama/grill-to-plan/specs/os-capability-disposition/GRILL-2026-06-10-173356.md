# GRILL — os-capability-disposition

## Context

**Problem.** The composed E1000 spec authors all four lifecycle callbacks,
including `on_surprise_remove` (`e1000-composed/input.rs:510`). linux_c lowers
it (present-predicate dispatch, `golden.linux.c:370`); zephyr_c REJECTS it
(`zephyr_c/mod.rs:232`) per the ratified D.2 fail-loud discipline
(`zephyr-open-questions.md` §D.2). Zephyr's static-DT device model structurally
cannot deliver a surprise-removal event and — unlike deinit — no upcoming API
exists. A single-file E1000 spec consumable by both backends is impossible
while the rejection stands.

**Goal.** Amend D.2 with a table-driven OS-absent-slot disposition: an authored
lifecycle callback whose dispatch condition structurally cannot occur on a
target OS may be *auditably non-emitted* (named audit block in the generated C
+ conformance-report row + test-log line) instead of rejected, with the body
still fully checked. This unit ratifies the nine Codex amendments (founding
doc: `docs/discussions/os-capability-disposition/codex-stress-test-2026-06-10.md`,
committed at `df7b000`) and delivers the mechanism.

**Consumers.** `spec-convergence-pl011` (next unit, edits the same
`zephyr_c/mod.rs`); `backend/zephyr-c-e1000` (born-converged; consumes
CAP-ZEPHYR-DT-SURPRISE-1 and lands the eval-side whitelist entries); the
thesis text.

**Non-goals.** No DSL-surface change (amendment 5 delivery is a named
successor). No eval-side edits. No softening of D.2 for anything outside a
ratified `AbsentDispatch` row. The capability table covers **lifecycle slots
only** this unit — non-slot D.2 rejections (`BarType::Io`, `ClassTag`,
config-write widths, …) remain prose-ledger entries.

**Hard constraints (fixed, not relitigated).**
- F-1: `generic_c` frozen — at merge, `git diff` over generic_c source paths
  must be empty.
- D.2 remains the default for everything not in a ratified `AbsentDispatch`
  row; this unit narrows the rejection space by exactly one mechanism.
- Unit ordering: this → `spec-convergence-pl011` → `backend/zephyr-c-e1000`,
  serial.
- Determinism: all committed artifacts byte-stable, no wall-clock; composed
  zephyr snapshots run in clean processes (sole-binary e2e).
- Baseline `cargo test` green at every commit (2334 passed at kickoff).

**Testing approach & seams.** In-crate `zephyr_c/mod_tests.rs` emit-level
assertions; new `capability` module unit tests (doc-sync, pin staleness,
NEVER_ABSENT, citation non-emptiness); a dedicated on-disk fixture with
sole-binary e2e byte-locking golden C + conformance JSON; coverage-matrix row
+ ledger drift gates (`ledger.rs:230`) unchanged in semantics.

## Decisions

- **D01 — Amendment 1 ratified AS AMENDED: closed capability table with a
  5-variant disposition enum.** `{Delivered, AbsentDispatch, DesignedScheduled,
  NeedsNewSurface, RejectedUnsupported}`. `DesignedScheduled` (added beyond
  Codex's four) = slot witnessed/designed, emission scheduled behind a named
  pin or successor unit; behaves as reject-at-emit with the scheduling
  diagnostic. Rationale: the repo's existing dispositions (`on_system_shutdown`
  "designed and scheduled per A-18", `on_deinit` "delivered by
  spec-convergence-pl011") are scheduling statements whose tests assert the
  diagnostic does NOT say "unsupported" (D12 discipline); Codex's four-variant
  enum would mislabel them. Rejected: Codex's 4 verbatim; 4 + scheduling
  metadata. Provenance: design-intended (user-ratified). Confidence: high.
  Impact: C01; S01. Test: enum is closed (no free-form), variants exercised by
  table tests.
- **D02 — Row key ratified verbatim:** `(target_os, os_version_pin,
  bus_family, registration_form, slot)`. Rationale: defeats the soundness
  attack — the zephyr E1000 is PCIe but registered via static DT, so
  registration_form carries the impossibility claim and bus_family
  disambiguates future dynamic-bus rows. Rejected: dropping bus_family.
  Provenance: spec-derived (Codex guardrail 2) + user-ratified. Confidence:
  high. Impact: C01; S01.
- **D03 — Table home: Rust static + doc mirror, sync-tested.** Source of truth
  = typed static table in `regseq-backends/src/capability.rs` (crate root;
  F-1-safe); emitters reference row consts so free-form claims are
  unrepresentable. Human ratification record = markdown table under
  `docs/discussions/os-capability-disposition/`, kept honest by a unit test
  asserting every code row's (ID, key fields, disposition, pin, citation)
  appears verbatim in the doc and no doc row lacks a code row; failure names
  the first diverging field (identity.rs `first_divergence` discipline).
  Boundary rule (Gedeon): backend concerns live ONLY in backend crates —
  regseq-model/macros/bridge untouched (verified: `TargetOs` and lifecycle
  slots already exist model-side; the backend defines its own slot-name enum).
  Rejected: doc-only (stringly-typed, no compiler enforcement); TOML/JSON data
  file (parsers for a ratification-time-only table). Provenance:
  design-intended (user-ratified). Confidence: high. Impact: S01, S02; C01.
  Test: the sync test + compile-time typing.
- **D04 — Amendment 2 ratified with row-ID grammar
  `CAP-<OS>-<FORM>-<SLOT>-<N>`.** Emitters may cite only table row IDs, never
  prose claims — structural via D03 (only ratified `CapabilityRow` consts are
  pushable). IDs are self-describing in diagnostics/C comments; trailing `-N`
  versions re-ratifications; IDs are append-only and never renamed. Rejected:
  opaque serials; doc-anchor style (B-7.1 — couples to one OS doc's
  namespace). Provenance: design-intended (user-ratified). Confidence: high.
  Impact: C02; S01–S06, S11.
- **D05 — Amendment 3 ratified with the pin+source-anchor citation bar.**
  Every `AbsentDispatch` row must carry (a) the pinned OS version incl. commit
  (`v4.4.0 (684c9e8f32e4)`) and (b) ≥1 source anchor in the pinned local
  checkout or vendored reference (file:line or named API absence), doc URLs
  optional supplements; and must name the bus/registration form (carried by
  the key, D02). Precedent: the C-5/C-9 v4.4.0 verification notes
  (zephyr-open-questions.md:369). Empty citation = error (the L3
  empty-ratified rule, ported — identity.rs precedent). Rejected: doc-URL-only
  bar; unspecified bar. Provenance: spec-derived + user-ratified. Confidence:
  high. Impact: C01, C03; S01, S02.
- **D06 — Amendment 4 ratified with the full-lowering-discard mechanism.**

### C01 — Capability table types (design-intended; D01, D02, D03, D05)

```rust
// regseq-backends/src/capability.rs — crate root, outside generic_c paths.

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Disposition {
    Delivered,
    AbsentDispatch,      // ONLY this variant may non-emit an authored callback
    DesignedScheduled,   // slot witnessed/designed; emission scheduled behind a
                         // named pin or successor; reject-at-emit with the
                         // scheduling diagnostic (never the word "unsupported")
    NeedsNewSurface,     // model/fixture gap; escalate, blocks
    RejectedUnsupported, // fail-loud D.2 default
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum RegistrationForm {
    StaticDevicetree, // Zephyr DEVICE_DT_INST_DEFINE family
    PciDynamic,       // Linux PCI probe/remove registration
}

/// Backend-side slot names for `regseq_model::LifecycleOps` fields.
/// (Backend concern: defined HERE, not in regseq-model.)
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum LifecycleSlot {
    OnInit,
    OnInitFailure,
    OnDeinit,
    OnSurpriseRemove,
    OnSystemShutdown,
}

pub struct CapabilityRow {
    /// Stable ratified ID per the C02 grammar. Append-only; never renamed.
    pub id: &'static str,
    pub target_os: regseq_model::TargetOs,
    /// Pinned OS version incl. commit, e.g. "v4.4.0 (684c9e8f32e4)" (D05).
    pub os_version_pin: &'static str,
    pub bus_family: &'static str,
    pub registration_form: RegistrationForm,
    pub slot: LifecycleSlot,
    pub disposition: Disposition,
    /// Non-empty; must contain the pin + >=1 source anchor in the pinned
    /// local checkout or vendored reference (D05; L3 empty-ratified rule).
    pub citation: &'static str,
}

/// Single authoritative current pin (D12) — the one place a re-pin edits.
pub const ZEPHYR_PIN: &str = "v4.4.0 (684c9e8f32e4)";

/// Slots that may NEVER carry Disposition::AbsentDispatch, on any OS (D14).
pub const NEVER_ABSENT: &[LifecycleSlot] =
    &[LifecycleSlot::OnInit, LifecycleSlot::OnInitFailure];

/// Every ratified row, in table order (C03).
pub const CAPABILITY_TABLE: &[&CapabilityRow] = &[ /* C03 rows */ ];
```

Key = `(target_os, os_version_pin, bus_family, registration_form, slot)`;
unique per table; emitters may reference rows only via these consts
(amendment 2 made structural).

### C02 — Row-ID grammar (design-intended; D04)

```
CAP-<OS>-<FORM>-<SLOT>-<N>
  <OS>   ∈ {ZEPHYR, LINUX, ...}           (target OS, upper-case)
  <FORM> ∈ {DT, PCI, ...}                  (registration-form shorthand)
  <SLOT> ∈ {SURPRISE, SHUTDOWN, DEINIT, INIT, INITFAIL}
  <N>    = positive integer; re-ratification that changes substance mints N+1.
IDs are append-only and never renamed; a retired ID stays in doc history.
```

### C04 — Generated-C audit block grammar (design-intended; D10)

```c
/* RSEQ-ABSENT-SLOT: <slot_name>
 * disposition: AbsentDispatch row: <ROW-ID>
 * [ratified: <row citation, verbatim from the CapabilityRow const>]
 * body checked, not delivered: dispatch cannot occur on this target. */
```

- Emitted at the position the callback's lowered code would have occupied.
- Exactly one block per absent slot; zero when no slot is absent.
- Marker prefix `RSEQ-ABSENT-SLOT:` is stable and greppable.
- Generated from the same `CapabilityRow` const as the report row (single
  source); the `[ratified: ...]` payload is non-empty by construction.

### C05 — ConformanceReport schema (design-intended; D08, D16)

Rust struct (on `ZephyrEmit` and `LinuxEmit`):

```rust
pub struct ConformanceReport {
    pub target: &'static str,            // "zephyr_c" | "linux_c"
    pub os_version_pin: &'static str,
    pub delivered_slots: Vec<SlotEntry>, // row: Some(id) iff a ratified row exists
    pub absent_dispatch_slots: Vec<SlotEntry>, // row: always Some; citation carried
    pub rejected_slots: Vec<SlotEntry>,  // structurally empty on successful emit
}
pub struct SlotEntry {
    pub slot: String,            // model slot name, e.g. "on_surprise_remove"
    pub row: Option<String>,     // CAP row ID
    pub citation: Option<String> // present for absent_dispatch entries
}
```

Serialized JSON (committed golden; deterministic — fixed field order, slots in
declaration order, no wall-clock):

```json
{
  "target": "zephyr_c",
  "os_version_pin": "v4.4.0 (684c9e8f32e4)",
  "delivered_slots": [{"slot": "on_init", "row": null}],
  "absent_dispatch_slots": [
    {"slot": "on_surprise_remove", "row": "CAP-ZEPHYR-DT-SURPRISE-1",
     "citation": "<row citation>"}
  ],
  "rejected_slots": []
}
```

Invariants: `rejected_slots == []` on any successful emit (rejection aborts
the build; field retained per amendment 6 verbatim for the required-marker
successor). ALL composed fixtures' OS-target runs commit one (zephyr + linux).
generic_c emits none (D09).

### C06 — The ratified amendments (authoritative text, as ratified 2026-06-10)

1. **Closed Capability Table** *(as amended — 5-variant enum)*. D.2 gains a
   companion per-OS capability table. "OS-absent slot" is legal only for rows
   explicitly ratified as `AbsentDispatch`. Dispositions form the closed enum
   `{Delivered, AbsentDispatch, DesignedScheduled, NeedsNewSurface,
   RejectedUnsupported}`; rows are keyed by `(target_os, os_version_pin,
   bus_family, registration_form, slot)`. Only `AbsentDispatch` may non-emit
   an authored callback; `DesignedScheduled` records witnessed/designed slots
   whose emission is scheduled behind a named pin or successor and remains a
   reject-at-emit scheduling diagnostic.
2. **No Free-Form Proofs** *(verbatim + grammar)*. Emitters may cite only
   table row IDs (grammar C02), not prose claims. Structurally enforced: the
   emitter can only push ratified `CapabilityRow` consts.
3. **Version-Bound Citations** *(as amended — citation bar)*. Each
   `AbsentDispatch` row cites the pinned OS version incl. commit AND ≥1 source
   anchor in the pinned local checkout or vendored reference; doc URLs are
   optional supplements; the bus/registration form is named by the row key.
   Empty citations are errors.
4. **Body Still Checked** *(verbatim + mechanism)*. The callback body remains
   part of `RegseqModel`; under `AbsentDispatch` the body runs the complete
   body-lowering pipeline and the output is discarded — all body-lowering
   legality checks run by construction; unsupported constructs inside the
   body remain D.2 rejections. The discarded lowering has no observable
   effect on the TU beyond the audit block.
5. **Required Callback Override** *(policy ratified; delivery deferred)*. If
   the DSL marks a callback `required`, `AbsentDispatch` becomes an emit-time
   rejection; default is `best_effort`. DSL delivery (model+macro+bridge) is
   the named successor unit `callback-requirement-marker`.
6. **Conformance Artifact** *(verbatim + schema)*. Every OS-backend build
   emits a per-target report (C05): delivered/absent_dispatch/rejected slots
   with citation IDs. generic_c (the oracle) is exempt: conformance is
   measured against it; a self-report is vacuous.
7. **Generated C Audit Block** *(verbatim + grammar)*. Non-emission leaves a
   named generated comment block (C04) with slot, reason, and ratified row ID.
8. **Trace Whitelist Coupling** *(verbatim; entries deferred)*. Any oracle
   marker omission uses the same row ID/citation as the artifact and test
   log. Binding on `backend/zephyr-c-e1000`, which lands the entries.
9. **Evolution Audit** *(verbatim + mechanics)*. On OS-version re-pin, every
   `AbsentDispatch` row is re-reviewed; stale rows fail the capability-table
   audit. Mechanics: single `ZEPHYR_PIN` const; staleness test compares every
   Zephyr `AbsentDispatch`/`DesignedScheduled` row's pin and fails naming
   each stale row; re-review = re-verify on the new pin + update row
   pin/citation (+ doc mirror via the sync test).

### C07 — Ratified thesis wording (spec-derived, Codex verbatim; D15)

> One Regseq spec can be lowered by multiple OS backends, with each backend
> producing a compile-time conformance report that enumerates which authored
> lifecycle slots are delivered, absent by OS dispatch model, or rejected.
> Differences are explicit, cited, and machine-checked — never silent.

"Silently different behavioral envelopes" is forbidden phrasing.
