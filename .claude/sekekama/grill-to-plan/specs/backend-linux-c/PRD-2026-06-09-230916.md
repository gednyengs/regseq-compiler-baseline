# PRD — backend-linux-c (PL011 first-light unit)

## Problem Statement

The Regseq compiler can lower a driver spec's `RegseqModel` only through `generic_c`,
a host-runnable behavioral oracle that traces device access but is not an OS driver.
The thesis claim — one spec, lowered per-OS — has no Linux realization: no backend
emits a loadable, idiomatic Linux kernel module from a `RegseqModel`. Downstream
consumers blocked by this: the eval validation pipeline (nothing real to validate on
Linux), the Zephyr backend track (its launch trigger is this unit's merge), and the
E1000/PCI unit that follows.

## Solution

A new `linux_c` backend in `regseq-backends` that lowers `RegseqModel` directly into a
single idiomatic Linux kernel-module translation unit plus a Kbuild fragment, under the
ratified F-1 independent-lowering contract (generic_c = reference + frozen oracle, not
a shared core). The unit is proven end-to-end on one composed PL011 spec — five
constructs (register-access, BRM, device-lifecycle, diagnostics-logging, RegseqError) in
one fixture — climbing the validation ladder: emission snapshot (L0), real kbuild
compile (L1), QEMU probe in the eval harness (L2), and a trace differential against the
generic_c oracle with a ratified-deviation whitelist (L3). The branch merges at first
light (GRILL `C01`).

## Requirements

R01. As the test harness (and any future driver of the compiler), I want a public
`regseq_backends::emit_linux_c(model) -> Result<LinuxEmit, EmitError>` function family
(variants added only as needed), so that the Linux backend is invoked exactly like
`generic_c` — by function call; the function API is the backend-selection surface.
*(GRILL D01; S01, S02 — code-confirmed convention)*

R02. Given any supported `RegseqModel`, when `emit_linux_c` runs, it must produce one
kernel-idiomatic TU `<driver>.c` (Linux-native ordering: includes → register/bitfield
consts → driver state → lowered bodies → lifecycle callbacks → match table → driver
struct → module macros) plus a Kbuild fragment (`obj-m += <driver>.o`) — backend-owned
emission shape, not generic_c's five-bank order. *(D04; S09 — spec-derived)*

R03. Given the four ratified gates, emitted C must observably honor each: `dev_*`
logging only in scaffold-synthesized statements where a `struct device *` is lexically
in scope, `pr_*` (with `pr_fmt`) in all lowered bodies (A-3); a TU containing MMIO ops
whose binding is not resolved is a hard emit-time error naming the missing L2 literals
(A-10); config-space intrinsic lowerings carry explicit `(void)` status discards for
reads and writes (A-11); any TU containing a width-8 MMIO op carries the
`#ifndef CONFIG_64BIT` / `#error` guard (A-12). *(S10 — spec-derived)*

R04. Given this unit's scope, when a spec exercises a path outside it (PCI config
space, non-AMBA buses, any unsupported construct surface), `emit_linux_c` must fail
loud with a diagnostic naming the unsupported path and the unit that will deliver it —
never emit wrong or silently truncated code. *(D02; S10)*

R05. As a spec author, I want `regseq::log::{debug,info,warn,error}!` macros that
expand to the already-recognized canonical intrinsic form, so that logging is writable
in the refined surface; the existing `log-intrinsic-smoke` fixture rewritten through
the macros must produce identical emitted C. Facade only — no recognition or lowering
changes. *(D10; S06)*

R06. Given the five in-scope constructs, there must be a `pl011-composed` proof fixture
(AMBA selector, PL011 register block via `register_bitfields!`, `impl Lifecycle`
init/deinit from the Form-A donor's device facts, log calls, `RegseqError` on
validation failure; no IRQ/clock/pinctrl, no `poll::until` — bounded spin loop instead)
that passes the existing generic_c 6-stage pipeline; its blessed `expected.stdout` is
the canonical PL011 oracle trace, committed to the repo. *(D06, D08; S03)*

R07. Given the `pl011-composed` fixture, the linux_c emission must be locked by a
byte-exact snapshot `golden.linux.c`, driven by a dedicated clean-process sole-binary
e2e with the established `BLESS=1` flow (interner-isolation rationale as the existing
sole binaries). *(D05, D06; S04; pipeline shape: GRILL C02)*

R08. Given the spec baseline, L0 must also include targeted structure tests derived
from the Linux traceability matrix and the four gates (probe-ladder order, discards,
guard presence, log-accessor placement), so regressions are named, not just
byte-diffed. *(D05; S14)*

R09. Given `RSEQ_LINUX_KDIR`, the `linux_kbuild_e2e` test must kbuild the emitted
driver + fragment per the env contract (GRILL `C03`): unset ⇒ skip with one visible
notice; set-but-invalid ⇒ fail; compile error ⇒ fail with `make` stderr verbatim.
*(D03; S05)*

R10. As the eval-harness operator, I want the generated PL011 driver to swap into the
eval DUT slot and pass the L2 campaign path — module builds via the script-15 variant
(which is the canonical `RSEQ_LINUX_KDIR` exporter), boots in the QEMU VM, binds to the
PL011 AMBA device through the smoke gate, and tears down without oops. *(D11; S07)*

R11. Given the committed oracle trace and a QEMU-side MMIO capture of the generated
driver, the `trace-diff` comparator must normalize both to ordered event streams and
fail on any deviation not licensed by a whitelist entry per GRILL `C04` — every entry
citing a ratified decision. *(D07; S08)*

R12. Given the branch, when GRILL `C01` items 1–5 all hold (cargo-test suite incl. new
e2es; kbuild gate; QEMU probe; zero unwhitelisted L3 deviations; final Codex review
clean), the unit merges to compiler `main`, which is also the Zephyr-track launch
trigger. *(D02, D09)*

## Invariants & Contracts

I01. `generic_c` is frozen: no commit in this unit modifies its sources or goldens,
except blessing the new `pl011-composed` outputs. A proven generic_c bug escalates to
the owner before any oracle change. *(D12; S13)*

I02. `cargo test` is green at every commit, including on machines with no kernel tree
(the kbuild gate skips visibly, never silently passes, never fails for absence). *(C03)*

I03. The compiler repo embeds no eval-repo paths; cross-repo coupling is exactly the
`RSEQ_LINUX_KDIR` env contract plus the committed oracle-trace artifact. *(D11)*

I04. Snapshots (`golden.c`, `golden.linux.c`, `expected.stdout`) are byte-exact
regression locks, re-blessed only via their sole-binary tests. *(D06)*

I05. Every L3 whitelist entry cites a ratified decision; `trace-diff` fails on
citation-less entries. *(C04)*

I06. No silent truncation anywhere in emission: unsupported = loud diagnostic (R04),
unresolved binding = hard error (A-10), unrepresentable width = compile-time guard
(A-12).

Formal contracts: first-light exit criteria — GRILL `C01`; pipeline stages — GRILL
`C02`; `RSEQ_LINUX_KDIR` — GRILL `C03`; whitelist format — GRILL `C04`.

## Implementation Decisions

- `linux_c` as a sibling module of `generic_c` inside `regseq-backends`, public surface
  re-exported from the crate root mirroring the existing naming family; no
  trait/registry, no CLI (D01; S12 deferred as negative space).
- linux_c fixture pipeline = bridge → emit → snapshot (+ env-gated kbuild); no host
  cc/run stages (D05, C02).
- Fixture and test conventions follow the existing proof-fixture corpus: fixture beside
  the others in the coverage-runner fixtures tree; two new sole-binary e2es
  (generic_c composed run; linux_c snapshot) (D06).
- In-unit chunk order: C1 log facade → C2 composed fixture + oracle trace (flushes the
  composition risks R1/R2 from the GRILL context) → C3 linux_c emission to L0 → C4
  kbuild gate + eval KDIR wiring → C5 L2 swap + capture spike + L3 comparator → C01
  gate → merge. Codex review per chunk (D08).
- Cross-repo split: comparator, whitelist, script variants, DUT swap live in the eval
  repo's PL011 harness area; compiler ships only the backend, tests, and the committed
  oracle trace (D11 — *assumed* placement, see Assumptions).
- Next unit after merge: `backend/linux-c-e1000` (PCI scaffold, config space, E1000
  keystone, campaign validation) (D09).

## Failure & Recovery

- **Emission failures** are diagnostics, never wrong code: unsupported path (R04),
  unresolved binding (R03/A-10). I06 holds on every failure path.
- **kbuild failures** surface `make` stderr verbatim in the test verdict; a
  misconfigured `RSEQ_LINUX_KDIR` fails rather than skips (C03), so a broken
  environment cannot masquerade as coverage.
- **Composition bugs flushed by C2** (first five-construct spec ever bridged) are fixed
  in bridge/model/recognition layers; if the fault is provably in generic_c lowering,
  work stops on that item and escalates (I01) — the oracle is never quietly patched.
- **L3 mismatches** fail the gate; the only recovery paths are (a) fix the backend, or
  (b) add a whitelist entry citing a ratified decision — an uncited deviation cannot be
  waved through (I05). Whitelist additions are reviewed changes.
- **QEMU capture spike (O1) failure mode:** if no workable MMIO capture mechanism is
  found in the C5 spike, first light is blocked at C01.4 and the issue escalates to the
  owner with options; chunks C1–C4 and their merges of record are unaffected.

## Conformance

Governing artifacts, all in-repo at `a32f81d`: the green-gated spec baseline
(`docs/discussions/backend-lowering/` input contract; `docs/discussions/linux-backend/`
scaffold §8 checklist, per-construct lowering, traceability matrix) and the ratified
decision set (§F.1; ratification sheet; gates A-3/A-10/A-11/A-12 — GRILL decisions
tagged spec-derived: D04, D12, R03's gate set). Target kernel: the eval campaign 6.6
LTS line (C03). Intended deviations from the oracle's behavior are exactly the L3
whitelist's cited entries — there is no other sanctioned deviation channel.

## Testing Decisions

Test external behavior at the ladder's seams, never lowering internals:
- **L0 (cargo test):** byte snapshots + structure assertions sourced from the
  traceability matrix and gates. Prior art: the 6-stage pipeline and sole-binary
  pattern in the coverage-runner crate (`bus_keystone_e2e` et al.); BLESS flow as-is.
- **L1 (cargo test, env-gated):** real kbuild against the campaign kernel — the only
  compile proof that counts for kernel code; skip semantics per C03.
- **L2 (eval harness):** the existing campaign scripts (build module → launch VM →
  smoke gate → collect), with the generated driver in the DUT slot.
- **L3 (eval harness):** `trace-diff` ordered-event comparison, oracle trace from the
  R06 fixture as the canonical reference; whitelist per C04.
- The R05 equivalence test (macro facade produces identical emitted C) is the guard
  against facade scope creep.

## Assumptions

- **A1 (from GRILL D11, blocking: false):** eval-side harness changes land directly on
  eval `main` (no construct worktree). Owner may prefer a small eval branch — process
  preference only (GRILL O2).
- **A2 (from GRILL D07, blocking: false):** a workable QEMU MMIO capture mechanism
  exists among instrumented device-model tracing / `-trace` events / memory-region
  logging. Resolved by the mandatory C5 spike (GRILL O1); contract C04 is
  mechanism-independent.

## Out of Scope

E1000/PCI lowering beyond fail-loud diagnostics; the Zephyr backend; CLI/backend
registry (negative space per GRILL S12); interrupts, DMA, clock/reset/pinctrl;
`poll::until` lowering; any `generic_c` modification; kernels outside the 6.6 LTS
campaign line; module signing/packaging; checkpatch as a gate. `BackendOptions`
extensions (GRILL S11) — explicitly no decision in this unit.

## Further Notes

The composed fixture (R06) is independently valuable beyond this backend: it is the
first time the five refined construct surfaces are exercised together through the real
compiler — the "first-light pilot" the three-repo reconciliation called for. If C2
flushes bridge bugs, that is the chunk doing its job, not schedule slippage.
