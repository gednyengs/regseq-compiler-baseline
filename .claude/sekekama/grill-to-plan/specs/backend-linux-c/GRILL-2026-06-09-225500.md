# GRILL — backend-linux-c

## Context

**Problem.** The Regseq compiler has one backend (`generic_c`, the behavioral oracle).
The thesis requires OS-specific backends; Linux is first. The green-gated spec baseline
(`docs/discussions/{backend-lowering,linux-backend}/`, merged at `a32f81d`) specifies the
lowering; this feature implements it.

**Goal.** A `linux_c` backend that lowers `RegseqModel` directly to an idiomatic Linux
kernel-module C driver, opening with the **PL011 composed-spec first-light chunk**, and
validated by the L0–L3 ladder. **Unit ends (merges) at PL011 first light** (D02/C01).

**Consumers/actors.** The implementer agent (sessions inside this worktree); Codex review
gates per repo cadence; Gedeon as ratifier; downstream: the Zephyr backend track (launch
trigger = this unit's merge) and `backend/linux-c-e1000` (next unit).

**Non-goals.** E1000/PCI-path coverage beyond fail-loud diagnostics (next unit); any
user-facing CLI for backend selection; interrupts/DMA/clock/pinctrl constructs;
`poll::until` lowering (recognized_not_lowered, ledger B-1); modifying `generic_c`
(frozen oracle); the Zephyr backend.

**Hard constraints (all spec-derived, ratified 2026-06-09 — do NOT relitigate):**
- **F-1 contract** (`linux-backend/linux-open-questions.md` §F.1): independent lowering
  of RegseqModel; generic_c = authoritative reference + frozen oracle; backend-owned
  emission shape; no seam refactor.
- **Gates:** A-3 (`dev_*` only where `struct device*` lexically in scope as-built —
  scaffold-synthesized statements; `pr_*` + `pr_fmt` elsewhere), A-10 (literal
  `is_resolved()` preamble gate + emit-time fail-loud diagnostic for MMIO-bearing TUs
  with unresolved bindings), A-11 (explicit `(void)` discard on config read/write
  status), A-12 (width-8 → `readq`/`writeq` + `#ifndef CONFIG_64BIT` `#error` guard).
- Non-gating A-items stand as recommended (`backend-lowering/_RATIFICATION-SHEET.md`).
- Repo cadence: plan → Codex plan review → implement+tests → Codex impl review → commit.
- `cargo test` green baseline at every commit.

**Testing approach & seams.** The validation ladder (D03/C01/C02): L0 emission-structure
(snapshot, in cargo test) · L1 kbuild gate (env-gated, in cargo test when
`RSEQ_LINUX_KDIR` set) · L2 QEMU probe (eval-repo harness, DUT slot) · L3 trace
differential vs the generic_c oracle trace with a ratified-deviation whitelist.

**Grounding sources.** Spec baseline at `a32f81d` (spec-derived); compiler audit
2026-06-09 (code-confirmed): backends are a function-API surface
(`regseq_backends::emit_generic_c*`, `crates/regseq-backends/src/lib.rs`), 6-stage
fixture pipeline (`crates/codegen-coverage-runner/src/pipeline.rs`), trace hooks
compiled+run today (`generic_c/prelude.rs:87-250`), largest composition =
`brm-e1000-keystone` (BRM+lifecycle+regaccess), `regseq::log` facade deferred
(recognition exists, `diag_log/recognition.rs`), `pl011-full-spec` fixture orphaned
Form-A (device-facts donor only); eval-repo harness (code-confirmed):
`pl011/linux/scripts/{15-build-dut-module,30-launch-vm,40-smoke-gate,50-collect}.sh`,
DUT slot `pl011/linux/dut/regseq-pl011-amba-probe/`.

## Decisions

- **D01 — Backend placement & API shape.** `linux_c` is a sibling module of `generic_c`:
  `crates/regseq-backends/src/linux_c/`, public surface re-exported from `lib.rs`
  mirroring the existing family: `emit_linux_c(model) -> Result<LinuxEmit, EmitError>`
  (+ `_with`/`_for_entry` variants only as actually needed — do not pre-build the full
  generic_c variant family speculatively). `LinuxEmit` carries the artifact set per D04.
  No trait/registry; the function API *is* backend selection (S12 deferred).
  *Provenance:* code-confirmed convention (`lib.rs` re-export pattern). *Confidence:*
  high. *Test impact:* unit-level API tests + pipeline integration (D05). *Surfaces:*
  S01, S02.

- **D02 — Unit scope / merge criteria (USER).** Branch `backend/linux-c` merges to main
  at **PL011 first light** (C01). E1000/PCI coverage is the next unit
  (`backend/linux-c-e1000`); within this unit, PCI-only paths emit fail-loud
  "unsupported in this unit" diagnostics rather than wrong code. Merge == Zephyr launch
  trigger. *Provenance:* user-ratified (this grill). *Confidence:* high. *Surfaces:* all.

- **D03 — L1 kbuild gate home (USER).** An env-gated test in `codegen-coverage-runner`
  (`linux_kbuild_e2e`): when `RSEQ_LINUX_KDIR` is set, run
  `make -C $RSEQ_LINUX_KDIR M=<staged-dir>` over the emitted driver + generated Kbuild
  fragment and fail on any compile error (stderr surfaced in the test failure); when
  unset, **skip with a visible notice** (never a silent pass). The eval repo's script-15
  variant exports KDIR from the buildroot tree and is wired into every L2 campaign run
  (rot mitigation). Kernel expectation: the campaign tree's 6.6 LTS line (record actual
  version in the test notice). *Provenance:* user-ratified (this grill). *Confidence:*
  high. *Surfaces:* S05, S07.

- **D04 — Emission shape.** One kernel-idiomatic TU per driver: `<driver>.c` (single-file
  module, the `amba-pl011.c` precedent and scaffold-doc shape), plus a generated Kbuild
  fragment (`obj-m += <driver>.o`). No generated headers in v1; includes per
  `linux-scaffold-and-dispatch.md`. Emission ordering follows Linux-native convention
  (includes → register/bitfield consts → driver state → lowered bodies → lifecycle
  callbacks → match table → driver struct → module macros), NOT generic_c's five-bank
  order — §F.1 backend-owned shape. *Provenance:* spec-derived (scaffold doc + F-1).
  *Confidence:* high. *Test impact:* L0 snapshot is the shape's regression lock.
  *Surfaces:* S09, S04.

- **D05 — linux_c L0 pipeline shape.** For linux_c the fixture pipeline is stages 1–3
  only: bridge → `emit_linux_c` → byte-exact snapshot vs committed `golden.linux.c`.
  No host cc/run/stdout stages (kernel code cannot host-run; compile proof is L1).
  L0 assertions beyond the snapshot: targeted structure tests derived from the
  traceability matrix and the four gates (devm probe ladder order, `(void)` config
  discards, `#error` guard presence in width-8 TUs, `pr_*`/`dev_*` placement).
  *Provenance:* design-intended (derived from C02 + audit facts). *Confidence:* high.
  *Surfaces:* S04, S10, S14.

- **D06 — Fixture & BLESS conventions.** `pl011-composed` lives with the other proof
  fixtures (`crates/codegen-coverage-runner/fixtures/`); generic_c run gets its own
  dedicated clean-process sole-binary e2e (`pl011_composed_e2e.rs`, the
  `bus_keystone_e2e.rs` pattern, BLESS=1 writes `golden.c` + `expected.stdout`); the
  linux_c snapshot gets a separate sole-binary e2e (`linux_pl011_e2e.rs`, BLESS=1 writes
  `golden.linux.c`) — same interner-isolation rationale as the existing sole binaries.
  `expected.stdout` from the generic_c run **is** the D4 canonical oracle trace,
  committed in the compiler repo. *Provenance:* code-confirmed pattern, design-intended
  extension. *Confidence:* high. *Surfaces:* S03, S04.

- **D07 — L3 comparator design.** Eval-side tool (`pl011/linux/tools/trace-diff/`),
  inputs: (a) the committed oracle trace (D4 artifact), (b) a QEMU-side MMIO event
  capture of the generated driver probing/running in the L2 VM. Both normalize to an
  event stream `(op R|W, width, offset-relative-to-mapped-base, value)` plus lifecycle
  markers; comparison is order-sensitive on MMIO events. Deviations allowed only via a
  versioned whitelist file (TOML, beside the tool) whose entries cite ratified decisions
  (e.g. no literal `map_region` event on Linux — probe-time enumeration per spec;
  devres-elided postamble per A-2). Unmatched deviation = failure. The QEMU capture
  mechanism (instrumented PL011 device-model tracing vs `-trace` events vs memory-region
  logging) is implementation discovery — **Open O1, spike-first in the plan**.
  *Provenance:* design-intended. *Confidence:* medium (mechanism), high (contract).
  *Surfaces:* S08.

- **D08 — In-unit chunk sequencing.** C1: `regseq::log` facade (D10) →
  C2: `pl011-composed` fixture through generic_c (D6 conventions; flush composition bugs
  R1/R2; produces the oracle trace) → C3: `linux_c` scaffold + emission to L0 green →
  C4: L1 gate + eval KDIR wiring → C5: L2 DUT swap + O1 spike + L3 comparator →
  first-light gate (C01) → merge. Codex review per chunk. *Provenance:* design-intended.
  *Confidence:* high. *Surfaces:* all.

- **D09 — Post-unit sequencing.** Next unit `backend/linux-c-e1000` (PCI scaffold,
  config space, E1000 keystone at L0/L1, eval campaign validation); Zephyr track
  launches at this unit's merge, in its own worktree/session, inheriting the L3
  comparator contract. *Provenance:* user-ratified (D02 selection). *Confidence:* high.

- **D10 — Logging facade scope (R3 guard).** `regseq::log::{debug,info,warn,error}!`
  macros expanding to the already-recognized canonical intrinsic form — facade ONLY, no
  recognition changes, no new lowering. `log-intrinsic-smoke` is rewritten through the
  macros (proves equivalence: identical emitted C / golden). A short surface note lands
  in `docs/discussions/logging-and-printing/`. *Provenance:* design-intended (audit:
  recognition exists). *Confidence:* high. *Surfaces:* S06.

- **D11 — Cross-repo harness changes.** L2/L3 additions (script-15 variant for generated
  drivers, DUT slot swap, trace-diff tool, whitelist) land in the **eval repo** under
  `pl011/linux/{scripts,tools}/`, committed on eval `main` directly (small,
  harness-scoped — consistent with prior harness work; no construct worktree needed).
  The compiler repo never embeds eval paths: the only coupling is the
  `RSEQ_LINUX_KDIR` env contract (D03) and the committed oracle-trace artifact (D06).
  *Provenance:* assumed (Gedeon may prefer an eval branch; nonblocking — Open O2).
  *Confidence:* medium. *Surfaces:* S07, S08.

- **D12 — Frozen-oracle invariant.** No commit in this unit modifies
  `crates/regseq-backends/src/generic_c/` (or its goldens) except the BLESS of the new
  `pl011-composed` fixture outputs. Composition bugs found in C2 are fixed in the
  bridge/model/recognition layers or — if a generic_c lowering bug is proven — escalated
  to Gedeon before touching the oracle. *Provenance:* spec-derived (F-1 frozen-oracle
  clause). *Confidence:* high. *Surfaces:* S13.

## Formal Contracts

- **C01 — First-light exit criteria (= merge gate for backend/linux-c)** *(design-intended,
  user-ratified)*:
  1. `cargo test` green, including: the rewritten `log-intrinsic-smoke` (D10);
     `pl011_composed_e2e` (generic_c 6-stage pass; BLESS'd `golden.c` +
     `expected.stdout` committed); `linux_pl011_e2e` (linux_c snapshot vs
     `golden.linux.c`); the L0 structure tests (D05).
  2. With `RSEQ_LINUX_KDIR` set to the eval buildroot kernel tree:
     `linux_kbuild_e2e` passes — the generated PL011 driver compiles as an
     out-of-tree module with zero errors (warnings recorded, not gating in v1).
  3. L2: the generated module, swapped into the eval DUT slot, boots in the QEMU
     campaign VM, **binds to the PL011 AMBA device** (probe success visible in the
     smoke gate), and survives unbind/teardown without oops.
  4. L3: `trace-diff` between the committed oracle trace and the captured QEMU MMIO
     stream reports **zero unwhitelisted deviations**; every whitelist entry cites a
     ratified decision.
  5. Codex impl review of the final chunk: CLEAN (or findings dispositioned + re-review
     pass), per repo cadence.

- **C02 — linux_c fixture-pipeline stage contract** *(design-intended)*:
  ```
  generic_c (existing, unchanged):  bridge → emit_generic_c → snapshot(golden.c)
                                    → cc compile → run → stdout oracle(expected.stdout)
  linux_c   (new):                  bridge → emit_linux_c  → snapshot(golden.linux.c)
                                    → [iff RSEQ_LINUX_KDIR] kbuild compile gate
  ```
  Stage failure semantics follow the existing `FixtureVerdict::{Pass, Fail{stage,detail}}`;
  the kbuild stage surfaces `make` stderr verbatim in `detail`. BLESS=1 writes the
  snapshot(s) for the invoking binary only.

- **C03 — `RSEQ_LINUX_KDIR` env contract** *(design-intended)*: absolute path to a
  configured Linux kernel build tree (the eval buildroot output; 6.6 LTS line).
  Unset ⇒ `linux_kbuild_e2e` skips, emitting a single visible notice line naming the
  variable. Set-but-invalid (no `Makefile`, or `make` not runnable) ⇒ test **fails**
  (misconfiguration is never a skip). The eval script variant of
  `pl011/linux/scripts/15-build-dut-module.sh` is the canonical exporter.

- **C04 — L3 deviation-whitelist entry format** *(design-intended)*: TOML array of
  tables, versioned beside `trace-diff`:
  ```toml
  [[deviation]]
  id        = "no-literal-map-region"     # stable kebab id
  matches   = "oracle"                    # which side carries the extra/different event: "oracle" | "linux"
  pattern   = "BUS map_region *"          # event pattern the entry licenses
  ratified  = "linux-open-questions.md A-10 / spec §A.5"   # citation, REQUIRED
  note      = "Linux discards L2 literals; mapping comes from probe-time enumeration"
  ```
  `trace-diff` fails on any deviation lacking a matching entry AND on any entry whose
  `ratified` field is empty. Whitelist changes are reviewed (they are spec deviations).
