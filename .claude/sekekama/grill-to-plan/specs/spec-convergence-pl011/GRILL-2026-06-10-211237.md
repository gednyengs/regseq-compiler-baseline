# GRILL — spec-convergence-pl011 (one PL011 spec, two OS backends)

## Context

**Problem.** The PL011 cross-OS proof rests on a fixture PAIR (`pl011-composed`
linux + `pl011-composed-zephyr` sibling) kept honest by the identity test, which
licenses exactly two cited differences: (i) the match-transport entries, (ii) the
deinit block. The dissertation claim is therefore "same spec, two files,
differences cited and machine-checked" — not the literal one-spec-two-OSes
headline.

**Goal.** Eliminate both licensed differences and retire the pair: one
`input.rs` consumed by linux_c AND zephyr_c (generic_c oracling both bindings),
via (1) the pre-ratified D03(a) mixed-match-set rule implemented in both
backends, (2) the Zephyr deinit lowering on the v4.4.0 pin (ZE-OQ2 resolved),
(3) the fixture collapse + identity-test retirement, (4) eval-side Zephyr L2/L3
teardown legs — the first teardown behavioral evidence on a second OS — and
(5) the optional model-equivalence strengthener.

**Consumers/actors.** Implementer agent (worktree
`~/regseq-compiler-worktrees/spec-convergence-pl011`, branch
`unit/spec-convergence-pl011` off `main` @ `119fa65`); Codex chunk-close
reviews; Gedeon as ratifier; successor `backend/zephyr-c-e1000` consumes the
mixed-match work to be born-converged. Eval-side work under `pl011/zephyr/` on
eval `main` (precedent).

**Non-goals.** E1000/PCIe lowering; `on_system_shutdown` delivery (A-18 policy
stands, C-4 unresolved); `poll_until`; multi-`compatible` rendering in
generic_c (PLAN SCOPE-1 stands); an of_match_table for linux_c; the
`callback-requirement-marker` successor; the A-19 citation sweep.

**Hard constraints (pre-ratified, NOT relitigated here):**
- **F-1**: generic_c SOURCE frozen; new blessed outputs for the converged
  fixture are the T03-pattern exception (sole binaries only); linux_c/zephyr_c
  stay independent lowerings.
- **D03(a) rule text verbatim** (backend-zephyr-c GRILL): a backend must
  consume every native-transport match entry; may ignore recognized
  foreign-transport identity entries only when ≥1 native entry exists; must
  make the omission auditable in output or test log; must reject
  native-but-unsupported entries; must never synthesize transport-equivalent
  entries.
- **v4.4.0 pin** (D05, commit `684c9e8f32e4`); capability row-citation
  discipline (cite row IDs, never prose); the D.2 fail-loud default for
  everything not explicitly licensed.
- Repo cadence: commit per task close; Codex review per chunk close;
  `cargo test` green at every commit (baseline 2353); no AI attribution.

**Testing approach & seams.** L0 snapshot + structure + audit-positive tests +
diagnostics negatives (cargo) · L1 west build gate (`RSEQ_ZEPHYR_WORKSPACE`,
C03 of backend-zephyr-c) · L2 QEMU smoke + teardown + init-fail legs (eval
harness) · L3 MMIO trace differential, teardown segment now compared (eval
harness) · capability sync/covers tests · the non-gating model-equivalence
stretch.

**Grounding.** Code-confirmed: both backend gates
(`linux_c/mod.rs:174-199`, `zephyr_c/mod.rs:180-239`), the identity machinery
(`identity.rs`, `composed_identity.rs`), both fixture trees (incl. base-bearing
oracle traces and `conformance.<os>.json`), `render_match_trace`
(`generic_c/body_emit.rs:5494` — renders `match_set.first()` ONLY, PLAN
SCOPE-1), `ConformanceReport` (`capability.rs:213` — slot-only),
the shared comparator (`pl011/linux/tools/trace-diff/trace_diff.py` — events
match on `(op,width,offset,value)`; segment labels are reporting-only; `LC
register` lines are skipped metadata), the eval smoke app
(`pl011/zephyr/campaign/app/src/main.c`). Spec-derived (read LIVE from the
pinned v4.4.0 checkout, tag `v4.4.0` = `684c9e8f32e4`):
`DEVICE_DT_DEINIT_DEFINE` (`include/zephyr/device.h:243`),
`DEVICE_DT_INST_DEINIT_DEFINE` (`device.h:272`), `device_ops.deinit` gated by
`CONFIG_DEVICE_DEINIT_SUPPORT` (`device.h:504-507`), the Kconfig default-off
(`kernel/Kconfig.device:36`), `z_impl_device_deinit` semantics
(`kernel/device.c:199-218`: `-EPERM` if not initialized; `-ENOTSUP` if no fn
or Kconfig off; driver's negative rc returned VERBATIM with `initialized` left
true; success clears `initialized` → `device_is_ready()` false),
`Z_DEVICE_OPS` silently DROPPING `deinit_fn` under `IF_ENABLED` when the
Kconfig is off (`device.h:1175-1180`). User-ratified: all D-decisions below
(grill session 2026-06-10).

## Decisions

- **D01 — Mixed-match audit: triple-render, mirroring the absent-slot
  precedent.** The foreign-entry omission renders into THREE artifacts from one
  source struct: (i) a new `ignored_match_entries` section of the
  `ConformanceReport` (schema extension, C02), (ii) a generated-C
  `RSEQ-IGNORED-MATCH` comment block at the match table (C03), (iii) the
  `RSEQ-CONFORMANCE` test-log line gains the section. Cross-artifact
  consistency holds by construction (same struct). The license citation is this
  GRILL's D08 via a shared const — NOT a capability-table row: the table's
  domain stays lifecycle slots only (os-capability-disposition deliberate
  boundary). Rejected: report-only (invisible in the artifact a driver reviewer
  reads; breaks the precedent), C-comment-only (not machine-checked; the
  thesis's enumeration artifact would omit a known difference). *Provenance:*
  user-ratified. *Confidence:* high. *Test impact:* the lifted gates' negative
  tests are replaced by audit-positive tests (comment present, report section
  present, line section present); both `conformance.<os>.json` snapshots
  re-blessed. *Surfaces:* S05, S06, S01, S02.

- **D02 — Converged fixture: one dir, OS-suffixed artifacts.**
  `pl011-composed` keeps its name; `pl011-composed-zephyr` is deleted. One
  `input.rs` + one `manifest.toml`; per-OS platform bindings
  (`platform.linux.toml` base 0x09000000 / `platform.zephyr.toml` base
  0x09040000 — they cannot merge, the traces carry the base in every event) and
  per-OS blessed artifacts by suffix (C05). The runner's fixture loader gains
  per-stage platform-file selection; each sole binary names its platform file
  explicitly; BLESS semantics per sole binary unchanged. Rejected: two dirs
  with `include!` (fragile, weakens the headline), two dirs + equality test
  (keeps alive the machinery this unit retires). *Provenance:* user-ratified.
  *Confidence:* high. *Surfaces:* S03, S04, S14. *Contract:* C05.

- **D03 — Zephyr deinit lowering: conditional macro swap (ZE-OQ2 resolved on
  v4.4.0).** Authored `on_deinit` ⇒ emit
  `static int <drv>_deinit(const struct device *dev)` (author body through the
  same lowering pipeline, the SAME nine-row negated-errno adapter as init,
  fused) and swap `DEVICE_DT_INST_DEFINE` →
  `DEVICE_DT_INST_DEINIT_DEFINE(0, <init>, <deinit>, …)` (device.h:272→243 —
  the macro is `DEVICE_DT_DEFINE` + one arg). No authored `on_deinit` ⇒ plain
  `DEVICE_DT_INST_DEFINE`, so the absentslot/init-fail goldens stay
  byte-frozen. `map_region`'s postamble mirror = explicit no-op callout
  (integration §5.2; no unmap exists on Zephyr — not invented).
  `CONFIG_DEVICE_DEINIT_SUPPORT=y` goes into BOTH prj.confs (compiler-staged
  L1 app AND eval campaign app) and into the TU-header Kconfig-pin block (A-9
  pattern) — load-bearing because `Z_DEVICE_OPS` SILENTLY DROPS `deinit_fn`
  under `IF_ENABLED` when the Kconfig is off (device.h:1175-1180): the build
  passes, `device_deinit` returns `-ENOTSUP`, and the L2 teardown leg is the
  loud catch. Conformance: `on_deinit` joins `delivered_slots` citing
  CAP-ZEPHYR-DT-DEINIT-1. Rejected: always-`DEINIT_DEFINE(NULL)` (churns
  unrelated goldens; drags the Kconfig story into TUs without teardown).
  *Provenance:* user-ratified; API facts spec-derived (live v4.4.0 reads).
  *Confidence:* high. *Surfaces:* S02, S07, S15. *Contract:* C04.

- **D04 — Deinit Err-channel witness: synthetic only.** L0 structure/snapshot

  order (init's pattern). No live deinit-fail fixture/leg. Rationale: the

  high. *Surfaces:* S07.

- **D07 — L2 teardown leg: extend the one smoke app with a 3-outcome
  stanza.** If ready: `device_deinit(dut)`, assert `rc == 0` AND

  `RSEQ-SMOKE: PASS|FAIL device_deinit` line (FAIL carries `rc` and `ready`);

  `RSEQ-SMOKE: SKIP device_deinit (dut not ready)` so the gate asserts the

  *Provenance:* user-ratified. *Confidence:* high. *Surfaces:* S10, S15.

- **D08 — Transport-nativeness: per ratified registration form (the D03(a)
  linchpin term).** `native(backend, scaffold)`: linux_c+amba ⇒
  `MatchEntry::Amba`; linux_c+pci ⇒ `MatchEntry::Pci`; zephyr_c (static-DT) ⇒
  `MatchEntry::Devicetree`. Any OTHER recognized identity entry is FOREIGN —
  ignorable with audit when ≥1 native entry exists; an all-foreign set keeps
  the loud reject naming the fix (zephyr A-13 text retained; linux gains the
  analog). Native-but-unsupported keeps the reject (unchanged). Implemented
  uniformly across BOTH linux_c scaffolds (the PCI-arm foreign gate that names
  this unit is lifted by the same rule) and zephyr_c. The per-OS alternative
  was rejected because it is incoherent with the charter: Linux-the-OS can
  carry an `of_match_table` (even on `amba_driver`), so a per-OS reading would
  force linux_c to REJECT the converged fixture — therefore the audit wording
  must say "not consumed by the ratified `<form>` registration form", NEVER
  "unsupported by this OS". The never-synthesize clause binds: linux_c must
  not mint an of_match_table from the compatible. The zephyr
  multi-compatible>1 gate stays (out of scope; the converged set has exactly
  one DT entry). *Provenance:* user-ratified. *Confidence:* high. *Surfaces:*
  S01, S02. *Contract:* C06.

- **D09 — Match-entry order: amba rows first, DT last; no linux re-run.**
  Converged set = `[amba 0x00041011/0x000fffff, amba 0x00abc123/0x00ffffff,
  compatible "regseq,pl011"]` — the linux file simply gains the DT entry.
  Because frozen generic_c renders `match_set.first()` only (PLAN SCOPE-1,
  body_emit.rs:5494), the linux-binding oracle's `LC register` marker — and
  expectedly the whole linux generic_c pair — stays byte-identical
  (mechanically proven by the existing snapshot e2e; an unexpected diff is a
  GATE-REPORT, never a silent re-bless: Open O2). Linux churn = the
  `RSEQ-IGNORED-MATCH` comment in `golden.linux.c` + the
  `conformance.linux.json` section. The archived linux first-light campaign
  evidence STANDS (module MMIO behavior provably unchanged; a re-run would
  re-prove what cargo proves). The zephyr-binding oracle re-blesses regardless
  (teardown events); its register marker becomes `amba:0x41011/0xfffff` —
  normalizer metadata the differential never compares (code-confirmed).
  Rejected: DT-first (re-blesses the linux oracle for aesthetics); linux
  campaign re-run (most expensive resource, zero information). *Provenance:*
  user-ratified. *Confidence:* high. *Surfaces:* S03, S04, S16.

- **D10 — L3 teardown gate: full-stream, teardown unwhitelisted.** The
  order-sensitive comparison now spans init AND teardown: every teardown MMIO
  event (IMSC←0x0, CR←disabled, ICR←0x7ff — pure writes; the A-20 aligned
  read-back value license structurally never applies) must match the oracle
  exactly with ZERO whitelist entries. The markers (`LC teardown present=1`,
  `LC call on_deinit`, `LC postamble`) remain normalizer-discharged segmenting
  metadata. The whitelist header comment is rewritten: the teardown class
  SHRANK from "no MMIO on either side" to "markers only; MMIO compared". A
  QEMU-side surprise between segments fails loud — not pre-licensed. Rejected:
  per-entry licensed teardown (nothing to license; entries would weaken the
  claim gratuitously). *Provenance:* user-ratified. *Confidence:* high.
  *Surfaces:* S11. *Contract:* C07.

- **D11 — Comparator untouched (code-confirmed enabler).** Events match on
  `(op, width, offset, value)` only — segment labels are reporting-only

  metadata in `parse_oracle`, so the D09 marker change is invisible to L3.
  *Provenance:* code-confirmed. *Confidence:* high. *Surfaces:* S11.

- **C02 — ConformanceReport v2 schema** *(design-intended)*:
  ```rust
  pub struct ConformanceReport {
      pub target: &'static str,
      pub os_version_pin: &'static str,
      pub delivered_slots: Vec<SlotEntry>,
      pub absent_dispatch_slots: Vec<SlotEntry>,
      pub rejected_slots: Vec<SlotEntry>,
      /// NEW (this unit): recognized foreign-transport identity entries the
      /// backend did not consume, per the D03(a) rule (GRILL
      /// spec-convergence-pl011 D08). Empty when the match set is all-native.
      pub ignored_match_entries: Vec<MatchAudit>,
  }
  pub struct MatchAudit {
      /// Rendered entry, e.g. "devicetree compatible=\"regseq,pl011\"" /
      /// "amba id=0x00041011 mask=0x000fffff".
      pub entry: String,
      /// Always the fixed reason form: "foreign transport: not consumed by
      /// the ratified <form> registration form; >=1 native entry present".
      pub reason: String,
      /// The license const: "spec-convergence-pl011 GRILL D08 (D03(a) rule)".
      pub license: &'static str,
  }
  ```
  The `RSEQ-CONFORMANCE` line gains a final section
  ` ignored=[<entry>;...]` (empty list rendered `ignored=[]`), keeping the
  existing prefix/format stable; the JSON snapshot serializes the new field
  unconditionally. All three renderings derive from the same struct. The
  reason wording must follow D08: registration-form framing, never
  "unsupported by this OS".

- **C03 — RSEQ-IGNORED-MATCH C audit-block grammar** *(design-intended)*:
  ```c
  /* RSEQ-IGNORED-MATCH: <rendered entry>
   * foreign transport: not consumed by the ratified <form> registration form
   * (>=1 native entry present); consumed natively by <other backend(s)>.
   * [license: spec-convergence-pl011 GRILL D08] */
  ```
  Emitted adjacent to the backend's match table (one block per ignored entry,
  zero when none); the `RSEQ-IGNORED-MATCH:` prefix is stable and greppable;
  generated from the same `MatchAudit` value as the report row.

- **C04 — Zephyr deinit lowering contract** *(design-intended; API facts
  spec-derived from the live v4.4.0 checkout)*:
  - Slot: authored `on_deinit` ⇒
    `DEVICE_DT_INST_DEINIT_DEFINE(0, <drv>_init, <drv>_deinit, NULL, &<drv>_data, NULL, POST_KERNEL, CONFIG_KERNEL_INIT_PRIORITY_DEVICE, NULL)`
    (device.h:272/243); unauthored ⇒ plain `DEVICE_DT_INST_DEFINE` (existing
    scaffold byte-identical).
  - Deinit fn: `static int <drv>_deinit(const struct device *dev)` — author
    body lowered by the full pipeline; `Ok(())` ⇒ `return 0`; `Err(e)` ⇒ the
    nine-row negated-errno adapter (symbol-identical C02 table, deterministic
    variant order, same fusion shape as the init fn).
  - Error channel semantics (cited, kernel/device.c:199-218): the fn's
    negative rc is returned by `device_deinit()` VERBATIM; on failure
    `initialized` stays true (device remains ready); on success
    `initialized` clears ⇒ `device_is_ready() == false`. Kernel-guard edges
    (not ours): `-EPERM` not-initialized, `-ENOTSUP` no-fn/Kconfig-off.
  - Kconfig: `CONFIG_DEVICE_DEINIT_SUPPORT=y` in the compiler-staged L1
    prj.conf AND the eval campaign prj.conf; the TU header pin block gains the
