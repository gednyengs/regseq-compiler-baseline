# PRD — spec-convergence-pl011 (one PL011 spec, two OS backends)

## Problem Statement

The dissertation's cross-OS claim for PL011 currently rests on a fixture PAIR
(`pl011-composed` for linux_c, `pl011-composed-zephyr` for zephyr_c) held to
one spec by an identity test that strips exactly two cited licensed regions
(match-transport entries; the deinit block). The consumable claim is therefore
"same spec, two files, differences cited and machine-checked" — one step short
of the literal one-spec-two-OSes headline. Both licensed differences exist
only because (a) each backend rejects the other's match-transport entries and
(b) zephyr_c rejects authored `on_deinit` (scheduled, undesigned). The
consumers are: the two OS backends (which must accept one file), the generic_c
oracle (which must trace both bindings), the eval harness (which must witness
Zephyr teardown live), and the dissertation (which needs the stronger claim).

## Solution

Make the pair's differences unnecessary, then delete the pair. Implement the
pre-ratified mixed-match-set rule in both OS backends (foreign-transport
entries auditable-ignored, never silently dropped, never synthesized); design
and deliver the Zephyr deinit lowering on the v4.4.0 pin (the slot exists:
`DEVICE_DT_DEINIT_DEFINE`); collapse to ONE `input.rs` carrying both match
forms and `on_deinit`, with per-OS L2 platform bindings and per-OS blessed
artifacts in one fixture dir; retire the identity machinery; and extend the
eval Zephyr campaign with L2/L3 teardown legs — the first teardown behavioral
evidence on a second OS. Conformance reporting is extended so the one
remaining class of cross-OS difference (ignored foreign match entries) is
enumerated, cited, and machine-checked in three artifacts rendered from one
struct.

## Requirements

R01. Given a model whose match set mixes transports, when an OS backend
emits, it must consume every native-transport entry (native = the backend's
ratified registration form: linux_c+amba ⇒ Amba, linux_c+pci ⇒ Pci, zephyr_c
static-DT ⇒ Devicetree), ignore recognized foreign-transport identity entries
only when ≥1 native entry exists, reject native-but-unsupported entries, and
never synthesize transport-equivalent entries. (GRILL D08, C06; rule text
pre-ratified.) [S01, S02]

R02. Given an ignored foreign-transport entry, the omission must surface in
THREE artifacts rendered from one `MatchAudit` value: an
`ignored_match_entries` section of the ConformanceReport (+ JSON snapshot), a
generated-C `RSEQ-IGNORED-MATCH` comment block (linux: adjacent to the id
table; zephyr: adjacent to `#define DT_DRV_COMPAT`), and the
`RSEQ-CONFORMANCE` test-log line's new `ignored=[...]` section. Audit wording
uses registration-form framing, never per-OS capability claims. (D01, C02,
C03, amendments A1/A3/A6.) [S05, S06]

R03. Given a match set whose recognized entries are ALL foreign to the
backend's registration form, emission must fail loudly naming the fix (the
zephyr A-13 text retained; linux gains the analog). (D08, C06.) [S01, S02]

R04. Given mixed entries, native-entry filtering must be explicit before
table emission: foreign entries feed ONLY the audit and never reach the
emitted id table / DT_DRV_COMPAT surface (the linux table emitters currently
`unreachable!` on non-native entries — they must receive a filtered list).
(Amendment A2.) [S01]

R05. Given a model authoring `on_deinit` under `TargetOs::Zephyr`, zephyr_c
must emit a deinit function (author body through the full lowering pipeline;
`Ok(())` ⇒ `return 0`; `Err` ⇒ the same nine-row negated-errno adapter as
init, deterministic variant order) and instantiate via
`DEVICE_DT_INST_DEINIT_DEFINE`; with no authored `on_deinit` the scaffold
stays byte-identical (`DEVICE_DT_INST_DEFINE`), so the absentslot and
init-fail fixtures' goldens are unchanged. (D03, C04.) [S07, S15]

R06. The `map_region` postamble mirror on Zephyr is an explicit no-op callout
(no unmap exists; none invented). (D03, C04.) [S07]

R07. `CONFIG_DEVICE_DEINIT_SUPPORT=y` must be present in BOTH prj.confs
(compiler-staged L1 test app AND eval campaign app) and recorded in the TU
header Kconfig-pin block, because `Z_DEVICE_OPS` silently drops `deinit_fn`
when the option is off — the L2 teardown leg is the loud catch for a missing
pin. (D03, C04.) [S07, S10]

## Failure & Recovery

- All-foreign match set ⇒ loud reject naming the fix (R03); empty match set ⇒
  existing reject unchanged.
- Native-but-unsupported entries ⇒ reject (C06), unchanged.
- Authored `on_deinit` Err path: adapter returns negated errno;
  `device_deinit` propagates it verbatim and the device REMAINS initialized
  (kernel semantics, cited live) — verified synthetically (D04); the live leg
  witnesses the success half.
- Missing `CONFIG_DEVICE_DEINIT_SUPPORT`: build passes (silent macro drop),
  `device_deinit` returns `-ENOTSUP` ⇒ the L2 teardown leg fails loudly
  (R07/R14) — the designed catch.
- Unexpected linux generic_c diff at collapse ⇒ STOP + gate-report (R11);
  never silently re-bless.
- L3: any extra/reordered/mismatched MMIO event (init or teardown) fails the
  differential; nothing teardown-related is whitelistable (C07).
- Strengthener overrun ⇒ drop with gate-report (R17), merge gate unaffected.

zephyr-c GRILL) implemented verbatim with the C06 nativeness definition; the
os-capability-disposition rule (audit single-sourcing, row-citation

`684c9e8f32e4` and recorded in GRILL Grounding/C04). Intended deviation:
none; the linux registration form deliberately does NOT consume DT
compatibles (never-synthesize clause) and says so in registration-form
framing.
