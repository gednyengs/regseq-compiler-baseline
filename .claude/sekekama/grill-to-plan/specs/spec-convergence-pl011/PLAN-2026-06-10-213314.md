# Plan — spec-convergence-pl011 (one PL011 spec, two OS backends)

## Overview

This unit eliminates the two licensed differences that keep the PL011 cross-OS
proof a fixture PAIR, then deletes the pair: (1) the pre-ratified D03(a)
mixed-match-set rule lands in both OS backends with a triple-rendered audit
(C02/C03/C06), (2) the Zephyr deinit lowering lands on the v4.4.0 pin (C04),
(3) the fixtures collapse to one `input.rs` consumed by linux_c AND zephyr_c
with per-OS L2 bindings and per-OS blessed artifacts in one dir (C05),
retiring the identity machinery (D06), and (4) the eval Zephyr campaign gains
L2/L3 teardown legs — the first teardown behavioral evidence on a second OS
(D07, C07). The merge gate is C01; the D12 model-equivalence strengthener is
in scope, scheduled LAST, and explicitly NON-GATING.

The build order honors the predecessor's ordering lesson (strict dependency
order, M1 = vertical slice, no early-milestone reordering): the FIRST
milestone is the converged-fixture vertical slice — converged `input.rs` plus
exactly the backend acceptance needed for each composed sole binary to run
its C05 pipeline (generic_c + its OS backend) from the one file at L0, with a
real (not stubbed) audit. Everything after M1 deepens an already-true claim.

Two repos: compiler work on `unit/spec-convergence-pl011` (worktree
`~/regseq-compiler-worktrees/spec-convergence-pl011`); eval work lands on
eval `main` under `pl011/zephyr/` by explicit-path commits. The comparator
(`pl011/linux/tools/trace-diff/trace_diff.py`) is UNTOUCHED (D11).

### Plan-level decisions delegated by the GRILL (each citing its bound)

1. **Runner loader parameter shape (bounded by C05).** The fixture model
   keeps its legacy presence-discovered `platform.toml` (every non-composed
   fixture unchanged) and gains an explicit `OsBinding { Linux, Zephyr }`
   selector the invoking sole binary passes, resolved to
   `{ platform_file, oracle_golden, oracle_stdout }` using the C05-fixed
   names — linux ⇒ (`platform.linux.toml`, `golden.c`, `expected.stdout`);
   zephyr ⇒ (`platform.zephyr.toml`, `golden.zephyr-oracle.c`,
   `expected.zephyr.stdout`). Selection is explicit per sole binary; BLESS
   writes remain scoped to the invoking binary's artifacts. No filename
   invention: all names are fixed in C05.
2. **Where `MatchAudit` lives.** A NEW module (`match_audit`) in
   regseq-backends holds the struct, the fixed reason-form renderer, and the
   D08 license const. Rationale: I04 — the capability table's domain stays
   lifecycle slots only and the audit cites the GRILL decision const, never a
   capability row; keeping the type out of the capability module makes that
   boundary structural. `ConformanceReport` imports the type for its new
   field.
3. **Backend work order.** Audit core → linux lift → zephyr lift → deinit.
   The two match-rule lifts are contiguous so the ONE rule (C06) is
   implemented and reviewed as a uniform pair; the deinit lowering is
   orthogonal and lands immediately before the collapse (its first consumer).
4. **Chunk boundaries (Codex reviews) — five chunks** *(amended per review
   round 1, finding 1)*: **C1** = backend acceptance (T01–T05: bridge verify,
   audit core, both lifts, deinit); **C2** = loader + collapse (T06–T07; M1
   closes here); **C3** = L1 build gate + docs (T08–T09); **C4** = eval
   L2/L3 legs (T10–T12); **C5** = strengthener + merge-gate sweep (T13–T14).
   This splits the original single high-risk chunk so the backend surfaces
   and the collapse each get their own meaningful review.
5. **O3 fallback (bounded by O3's "decided in plan").** If the deinit
   `LOG_WRN` does not flush within the existing collect window, the fallback
   is a short post-stanza settle (`k_sleep`) in the smoke app after the
   teardown stanza — targeted at the deferred-log flush, preferred over
   inflating the collect window globally. Confirmed/discharged in T10.
6. **O4 mechanics (bounded by D12's drop bound).** In-process double bridge:
   one test process bridges the converged `input.rs` under each platform
   binding, normalizes the OS-conditional fields (target_os; mmio base/size
   literals), and compares structure with interned symbols resolved through
   each model's OWN interner (resolved-string comparison — the
   interner-safety answer). Rejected: two sole binaries + serialized model
   dumps (would invent a RegseqModel serialization — exactly the plumbing the
   drop bound exists to prevent).
