# PRD — backend-zephyr-c (Zephyr PL011 first-light unit)

## Problem Statement

The Regseq compiler lowers a driver spec's `RegseqModel` through `generic_c` (a
host-runnable behavioral oracle) and `linux_c` (the first OS backend, merged at PL011
first light). The thesis claim — one spec, lowered per-OS — has exactly one OS
realization: no backend emits a bootable, idiomatic Zephyr driver from a
`RegseqModel`. Downstream consumers blocked: the cross-OS eval story (nothing real to
validate on Zephyr), the `spec-convergence-pl011` unit (needs both OS legs to exist),
and the Zephyr PCIe unit. Additionally, the authored-`Err` error path has never been
exercised live on any OS — a debt flagged at the linux-c close.

## Solution

A new `zephyr_c` backend in `regseq-backends` that independently lowers `RegseqModel`
(F-1 contract: generic_c = reference + frozen oracle, no shared emission core) into an
idiomatic Zephyr driver translation unit — static `DEVICE_DT_INST_DEFINE`
instantiation, `DEVICE_MMIO_*` scaffold, `sys_read*/sys_write*` register ops, `LOG_*`
format reassembly, the negated-errno RegseqError adapter fused into the device init
function — plus a generated DT binding yaml. Proven end-to-end on a Zephyr-facing
sibling of the composed PL011 spec, with a machine-checked identity invariant tying
the two OS fixtures to one spec, climbing a Zephyr-flavored ladder: emission snapshot
+ structure tests (L0), real west build against the pinned Zephyr v4.4.0 workspace
(L1), QEMU boot with `device_is_ready` smoke (L2), an MMIO trace differential against
the committed generic_c oracle trace with a cited-deviation whitelist (L3), and an
in-gate live witness of the authored-`Err` path. The branch merges at Zephyr PL011
first light (GRILL `C01`).

## Requirements

R01. As the test harness (and any future driver of the compiler), I want a public
`regseq_backends::emit_zephyr_c(model) -> Result<ZephyrEmit, EmitError>` function
family re-exported from the crate root mirroring the existing backend families, so
that the Zephyr backend is invoked exactly like its siblings — the function API is the
backend-selection surface. *(D07, D17; S01, S02 — code-confirmed convention)*

R02. Given any supported `RegseqModel`, `emit_zephyr_c` must produce exactly two
artifacts: one Zephyr-idiomatic driver TU (the scaffold skeleton of
`zephyr-scaffold-and-dispatch.md` §1: `DT_DRV_COMPAT` pin, demand-driven log-module
block, demand-driven includes, config/data structs with `DEVICE_MMIO_ROM`/`RAM` first
members, lowered bodies, the per-instance init function, the instantiation block, the
two `BUILD_ASSERT` guards) and a generated DT binding yaml whose `compatible:` comes
from the model's match set — backend-owned emission shape per §F.1, not generic_c's
five-bank order. Kconfig pins are documented in a TU header-comment block (A-9).
*(D07, D12, D18; S01, S05 — spec-derived)*

R03. Given the composed bring-up path, the lowered TU must observably honor the
ratified materializations: DT `reg` as the normative `(base,size)` source consumed by
`DEVICE_MMIO_ROM_INIT`/`DEVICE_MMIO_MAP(dev, K_MEM_CACHE_NONE)` PLUS the emitted A-1
cross-check `BUILD_ASSERT` comparing `DT_REG_ADDR`/`DT_REG_SIZE` against the
platform.toml literals (D11); the TU-static base carrier paired with the mandatory
single-instance `BUILD_ASSERT(DT_NUM_INST_STATUS_OKAY(DT_DRV_COMPAT) == 1, …)` (A-2);
width-selected value-first `sys_read{8,16,32,64}`/`sys_write*` ops preserving
mask-confinement and RMW semantics (D19); `claim_regions` emitting zero calls (the
ratified elision); one `LOG_DBG/INF/WRN/ERR` statement per log site (reassembled
single cbprintf format, literal `%` doubled, no trailing newline, `[LEVEL]` tag
dropped); `Ok(()) → return 0` and every `RegseqError` variant → its negated C02 errno
symbol in deterministic variant order, fused into the init-fn return path after the
`on_init_failure` cleanup slot; `POST_KERNEL, CONFIG_KERNEL_INIT_PRIORITY_DEVICE` as
the hardcoded documented init level/priority (D13). Authored `on_init` AND
`on_init_failure` lower; the platform.toml is required (literal `is_resolved()` gate).
*(D11, D12, D13, D18, D19; S03, S06 — spec-derived)*

## Invariants & Contracts

I01. `generic_c` is frozen: no commit modifies its sources or goldens; the only new
generic_c-adjacent files are the sibling fixture's blessed outputs. A proven
generic_c fault stops work and escalates; composition bugs are fixed in
bridge/model/recognition only. *(D21; S13)*

I02. `cargo test` is green at every commit, including on machines with no Zephyr
workspace (the build gate skips visibly, never silently passes, never fails for
absence). *(C03)*

I03. The compiler repo embeds no eval-repo paths; cross-repo coupling is exactly the
`RSEQ_ZEPHYR_WORKSPACE` env contract plus the committed oracle-trace artifact.
*(D08, D10, D17)*

I04. Snapshots (`golden.c`, `expected.stdout`, `golden.zephyr.c`,
`golden.zephyr.binding.yaml`, the variant's goldens) are byte-exact regression
locks, re-blessed only via their own sole-binary tests in clean processes. *(S05)*

I05. Every L3 whitelist entry cites a ratified decision; `trace-diff` fails on
citation-less entries; MMIO events are never whitelisted. *(C04)*

I06. No silent truncation anywhere in emission: every unlowered legal shape is a
loud diagnostic per R04; unresolved binding is a hard error; multi-instance fails
the C build. *(D12)*

I07. The identity invariant (GRILL `C02`) holds at merge: the two composed
`input.rs` files differ only in the two marked, cited licensed regions.

I08. Linux first-light artifacts stay byte-frozen: linux goldens/traces unchanged
(mechanically proven by the existing linux e2es staying green with no re-bless); the
linux `input.rs` gains only inert citation-bearing markers. *(D20; S14)*

I09. The normative Zephyr pin is v4.4.0 (D05); emitted code uses no API absent from
that release; teardown lowering remains out of scope regardless (D06).

I10. The two error channels never merge: authored `RegseqError` crosses the negated
adapter at the init-fn boundary only; native Zephyr status from generated preamble
code propagates directly, never wrapped.

Formal contracts: merge gate — GRILL `C01`; identity test — GRILL `C02`;
`RSEQ_ZEPHYR_WORKSPACE` — GRILL `C03`; L3 whitelist — GRILL `C04`; pipeline stages —
GRILL `C05`.

## Implementation Decisions

- `zephyr_c` as a sibling module of `generic_c`/`linux_c` inside `regseq-backends`;
  public surface re-exported from the crate root; no trait/registry, no CLI (D17;
  S16 negative space).
- `ZephyrEmit` = TU + binding yaml; module shell (CMakeLists, Kconfig, module.yml,
  prj.conf, board overlay) is eval-side static material (D07).
- zephyr_c fixture pipeline = bridge → L2 bind → emit → snapshot(s) → env-gated west
  build; no host cc/run stages (C05).
- Chunk order mirrors linux D08 (D17): C1 sibling fixture + identity test + oracle
  bless (M1 = the vertical slice) → C2 emitter to L0 → C3 build gate + eval exporter
  wiring → C4 L2 + L3 + Err witness → gate → merge; Codex review per chunk close.
- Cross-repo split: smoke app, overlay, prj.conf, launch/collect scripts, whitelist
  under the eval repo's `pl011/zephyr/` on eval `main`; compiler ships backend,
  tests, and the committed oracle trace (D09, D10, D17).
- A-series materializations: A-1 → emitted cross-check `BUILD_ASSERT` (D11); A-2 →
  TU-static base + single-instance guard; A-9 → TU header collateral; A-15 →
  hardcoded default, knob deferred (D13); A-18 → policy stands, delivery deferred
  with a scheduling diagnostic (D12).
- Successors recorded: `spec-convergence-pl011` (mixed match-set rule + deinit
  verify/design preconditions, GRILL D03) and `backend/zephyr-c-e1000`; order open
  (D16).

## Failure & Recovery

- **Emission failures** are diagnostics, never wrong code (R04, I06); each names its
  cause and, where applicable, the delivering unit or ratified decision.
- **Build-gate failures** surface west/cmake stderr verbatim; a misconfigured
  workspace fails rather than skips (C03), so a broken environment cannot masquerade
  as coverage.
- **Composition bugs flushed by the sibling fixture** (first composed spec with a
  Devicetree match entry) are fixed in bridge/model/recognition; a proven generic_c
  fault stops and escalates (I01) — the oracle is never quietly patched.
- **L3 mismatches** fail the gate; recovery is (a) fix the backend or (b) add a
  whitelist entry citing a ratified decision — an uncited deviation cannot be waved
  through (I05); whitelist changes are reviewed.
- **Identity-test failures** mean same-spec drift: fix the fixture(s); the licensed
  regions may not grow without a new cited ratification (C02).
- **O1 launch-mechanics failure** (patched-QEMU wiring for the Zephyr legs): first
  task of the L2/L3 chunk; failure escalates with options; L0/L1 chunks and their
  merges of record are unaffected.
- On the init-fail leg, "failure" is the expected observable: the gate asserts
  not-ready + the authored `LOG_ERR`; a device that comes up ready FAILS that leg
  (I10's live witness).

## Conformance

Governing artifacts, in-repo: the GREEN Zephyr lowering spec
(`docs/discussions/zephyr-backend/`, normative pin amended to v4.4.0 per D05/R13),
the backend-lowering foundation (input contract, agnostic-core seam, ratification
sheet), and the D.2 rejection ledger — all `spec-derived` decisions trace there. The
F-1 independent-lowering contract governs the backend's relationship to generic_c.
Intended deviations from the oracle's observable behavior are exactly the L3
whitelist's cited entries plus the two licensed fixture regions (C02) — there is no
other sanctioned deviation channel.

## Testing Decisions

Test external behavior at the ladder's seams, never lowering internals:
- **L0 (cargo test):** byte snapshots + named structure assertions + diagnostic
  negative tests + the identity test. Prior art: the sole-binary pattern
  (`pl011_composed_e2e.rs`, `linux_pl011_e2e.rs`), the 6-stage pipeline, the BLESS
  flow.
- **L1 (cargo test, env-gated):** real west build for `qemu_cortex_a53` — the only
  compile proof that counts for Zephyr code; skip semantics per C03; the staged
  hermetic app is compiler-side test collateral.
- **L2 (eval harness):** boot + `device_is_ready` smoke via the smoke app's console
  line; the patched system QEMU, not the SDK runner.
- **L3 (eval harness):** `trace_diff.py` ordered-MMIO comparison against the
  committed oracle trace; whitelist per C04.
- **Err witness:** the init-fail image's L2 leg (R12) — expected-failure assertions.
- Backend unit seams: width-family accessor selection, arg order, guard polarity,
  errno arm order — synthetic models (the linux T06–T09 pattern).
- C-series verification (C-9, C-5) by reading the local v4.4.0 checkout (R13).

## Assumptions

- **A1 (from GRILL D19, blocking: false):** MMIO width family 1/2/4/8 implemented
  with synthetic-model unit tests; width-8 documented aarch64-validated (C-2
  disposition if another arch ever appears). Low risk; resolved at the backend unit
  seam.
- **A2 (from GRILL O2, blocking: false):** exact licensed-region marker syntax +
  line-based strip mechanics — bounded by C02, spelled in the plan's C1 chunk.
- **A3 (from GRILL O1, blocking: false):** patched-QEMU launch wiring for the
  Zephyr legs (west-built ELF + the second-PL011 machine config) — plan schedules it
  first in the L2/L3 chunk; capture + comparator already exist.

## Out of Scope

E1000/PCIe lowering beyond fail-loud diagnostics; teardown lowering (`on_deinit`
slot design, `on_surprise_remove`, the A-18 PM wrapper delivery); `poll_until`;
non-Generic `ClassTag`; multi-instance/multi-region; sub-word/64-bit config writes;
the `spec-convergence-pl011` work itself and the optional model-level equivalence
strengthener; any generic_c modification beyond the sibling bless; any linux_c or
linux-golden change beyond the inert markers; `BackendOptions` extensions;
CLI/backend registry; the full A-19 citation sweep; interrupts, DMA, clocks,
pinctrl.

## Further Notes

The sibling fixture is the first composed five-construct spec to carry a
`Devicetree` match entry through the bridge — if its bridging flushes bugs, that is
the chunk doing its job. The interim dissertation claim this unit establishes is
"one spec, two OSes, with OS-conditional differences enumerated, cited, and
machine-checked"; `spec-convergence-pl011` upgrades it to literal single-file truth
on the project's own schedule.
