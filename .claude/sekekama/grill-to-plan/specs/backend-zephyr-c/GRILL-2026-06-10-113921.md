# GRILL — backend-zephyr-c (Zephyr PL011 first-light unit)

## Context

**Problem.** The compiler has `generic_c` (frozen behavioral oracle) and `linux_c`
(merged at first light, `cb40658`). The thesis requires per-OS lowering; Zephyr is the
second real OS backend, launch trigger fired at the linux-c merge.

**Goal.** A `zephyr_c` backend in `regseq-backends` that independently lowers
`RegseqModel` to an idiomatic Zephyr driver TU (static `DEVICE_DT_INST_DEFINE`
instantiation, `DEVICE_MMIO_*` scaffold, `sys_read*/sys_write*` ops, `LOG_*`
reassembly, negated-errno adapter fused into the init fn), proven end-to-end on the
composed PL011 spec through a Zephyr-flavored L0–L3 ladder. **Unit merges at Zephyr
PL011 first light** (C01 below).

**Consumers/actors.** Implementer agent (this worktree); Codex chunk-close reviews;
Gedeon as ratifier; downstream: `spec-convergence-pl011` and `backend/zephyr-c-e1000`
(D16). Parallel: `backend/linux-c-e1000` off the same base — first-to-merge-wins,
second rebases (recorded discipline).

**Non-goals.** PCIe/e1000 coverage beyond fail-loud diagnostics; teardown lowering
(`on_deinit`/`on_surprise_remove`/the A-18 PM wrapper); `poll_until`; non-Generic
`ClassTag`; multi-instance/multi-region; any `generic_c` or linux-golden modification;
the convergence work itself.

**Hard constraints (ratified, do NOT relitigate):**
- **F-1**: independent lowering of `RegseqModel`; `generic_c` = authoritative reference
  + frozen oracle; backend-owned emission shape; `linux_c` is a structural sibling, not
  a shared core.
- The GREEN spec baseline: `docs/discussions/zephyr-backend/` (Codex loop GREEN after
  2 rounds) + `docs/discussions/backend-lowering/` (GREEN, ratification sheet).
- The **D.2 rejection ledger** (`zephyr-open-questions.md` §D.2) is normative: every
  legal-but-unlowered input shape is a fail-loud emit-time rejection, never silent.
- Zephyr A-series ratification-sheet semantics: no Zephyr row is gating; empty verdict
  = recommendation stands. This GRILL supplies materializations where first light
  forces one (D11, D12, D13) — it overrides no recommendation.
- linux-c ordering lesson: strict dependency order; M1 = vertical slice through the
  composed fixture; no early-milestone reordering.
- Repo cadence: commit per task close; Codex review per chunk close; `cargo test`
  green at every commit (baseline 2243 passed, verified this session).

**Testing approach & seams.** The ladder: L0 emission snapshot + named structure tests
+ diagnostics negative tests + the identity test (cargo test) · L1 real west build
(env-gated cargo test, C03) · L2 QEMU boot + device-ready smoke (eval harness) · L3
MMIO trace differential vs the committed oracle with a cited-deviation whitelist (eval
harness) · plus the in-gate Err-branch live witness (D14).

**Grounding.** Spec-derived: the 8-doc Zephyr spec, the ratification sheet, the input
contract, vendored stock drivers (`reference-drivers/{pl011,e1000}/zephyr/`).
Code-confirmed: `linux_c` module + e2e patterns (`linux_pl011_e2e.rs`,
`pl011_composed_e2e.rs`), the `pl011-composed` fixture, bridge `compatible = [...]`
match sugar (`bridge/device_lifecycle/recognition.rs:162`), the eval repo's Zephyr
environment (`pl011/zephyr/versions.lock`: Zephyr **v4.4.0**, SDK 1.0.1,
`qemu_cortex_a53`, spike GO) and the linux L3 capture
(`qemu-patches/11-pl011-regseq-mmio-trace.patch`, instance-tagged base-relative
events; `tools/trace-diff/trace_diff.py` + cited TOML whitelist). User-ratified: all
D-decisions below (grill session 2026-06-10, incl. the external-reviewer-refined
fixture/identity/convergence package).

## Decisions

- **D01 — Sibling fixture.** `pl011-composed-zephyr` beside `pl011-composed`: same
  PL011 device facts and `on_init` body, Devicetree-compatible match set, **no
  `on_deinit`**, own platform.toml (`os = "zephyr"`)/manifest/goldens/oracle trace.
  Linux goldens/traces stay byte-frozen. Rationale: the ratified D.2 ledger
  emit-rejects the linux fixture's authored `on_deinit` (B-6) and AMBA-only match set
  (B-5/A-13); modifying the shared fixture would churn merged linux first-light
  artifacts and gut the linux teardown proof. *Provenance:* user-ratified (external
  reviewer package). *Confidence:* high. *Surfaces:* S03, S05, S13, S14.

- **D02 — Identity invariant (merge-gate acceptance).** The two `input.rs` files must
  be byte-identical after stripping exactly two **marked licensed regions**: (i) the
  match-transport entries, (ii) the deinit block — each marker citing its ratifying
  decision (linux_c AMBA match gate; B-6/C-3 via D06). A coverage-runner test strips
  only marked regions and asserts the remainder matches — porting the L3
  cited-deviation-whitelist discipline from traces to spec sources; same-spec drift
  becomes mechanically impossible. Region (i) covers ONLY the match entries: `name`
  and `bus = "amba"` stay in the checked shared remainder (Zephyr accepts
  `bus = "amba"`; Amba folds into the Platform path, per-construct §B.2).
  *Provenance:* user-ratified. *Confidence:* high. *Test impact:* the identity test is
  C01.1 material. *Surfaces:* S03, S04, S16. *Contract:* C02.

- **D03 — Successor unit `spec-convergence-pl011`.** Recorded now with two
  preconditions: **(a)** mixed match sets ratified under the rule: a backend must
  consume every native-transport entry; may ignore recognized foreign-transport
  identity entries only when ≥1 native entry exists; must make the omission auditable
  in output or test log; must reject native-but-unsupported entries; must never
  synthesize transport-equivalent entries — plus lifting linux_c's AMBA-only match
  gate and the Zephyr-side equivalent; **(b)** *(reworded under D05/D06)* verify
  `device_deinit()`/`DEVICE_DT_DEINIT_DEFINE` live on the v4.4.0 pin and design the
  deinit lowering (slot, teardown-body synthesis, deinit error channel). When both
  land: sibling deleted, one file feeds both backends, one-time re-bless per side. The
  interim dissertation claim: "one spec, two OSes, OS-conditional differences
  enumerated, cited, and machine-checked." Optional later strengthener (non-blocking):
  model-level equivalence (bridge both, erase licensed fields, assert structural
  RegseqModel equality). *Provenance:* user-ratified. *Confidence:* high.

- **D04 — Compatible string.** `regseq,pl011`, carried by the eval DUT node (the
  second PL011) via board overlay — the Zephyr analog of linux's reserved test
  periphid: stock `uart_pl011` (matches `arm,pl011`) cannot bind the DUT; the
  generated driver matches ONLY the DUT; console `uart0` untouched; single-instance
  `BUILD_ASSERT` satisfied. *Provenance:* user-ratified. *Confidence:* high.
  *Surfaces:* S03, S08.

- **D05 — Version pin: Zephyr v4.4.0 (re-pin, USER).** v4.4.0 is now the normative
  pin for the zephyr_c backend, aligning spec and the eval harness
  (`versions.lock`). The emitted API surface (`DEVICE_DT_INST_DEFINE`,
  `DEVICE_MMIO_*`, `sys_io`, `LOG_*`, `BUILD_ASSERT`/`DT_NUM_INST_STATUS_OKAY`) is
  stable across 3.7→4.4 and stays corroborated by the vendored drivers. C-series
  pins this unit relies on (C-9 guard macros; C-5 `init_res`/`device_is_ready`) are
  verified by reading the LOCAL v4.4.0 checkout in the eval workspace. Doc
  consequence: D15. *Provenance:* user-ratified. *Confidence:* high. *Surfaces:* S12.

- **D06 — Teardown-free first light despite the re-pin.** Authored `on_deinit` stays
  an emit-time rejection; the diagnostic text re-cited: "teardown slot exists on

- **D07 — Artifact set.** `ZephyrEmit` = the driver TU + a generated DT binding yaml

## Formal Contracts

- **C01 — Zephyr first-light exit criteria (= merge gate for `backend/zephyr-c`)**
  *(design-intended, user-ratified)*:
  1. `cargo test` green, including: the `pl011-composed-zephyr` generic_c sole-binary
     e2e (full 6-stage pass; blessed `golden.c` + `expected.stdout` = the Zephyr-leg
     canonical oracle trace, committed); the `zephyr_pl011` sole-binary snapshot e2e
     (`golden.zephyr.c` + `golden.zephyr.binding.yaml`); the **identity test** (C02);
     the L0 structure suite (named assertions: scaffold skeleton order per
     `zephyr-scaffold-and-dispatch.md` §1, `DEVICE_MMIO_ROM`/`DEVICE_MMIO_RAM` first
     members, single-instance `BUILD_ASSERT` presence, A-1 cross-check `BUILD_ASSERT`
     presence, claim-elision (no claim call emitted), demand-driven
     `LOG_MODULE_REGISTER`, negated errno arms in deterministic variant order,
     `DT_DRV_COMPAT` line, no `main`/runner artifact); the D12 diagnostics negative
     tests (one per rejection); the init-fail variant snapshot e2e (D14).
  2. With `RSEQ_ZEPHYR_WORKSPACE` set to the eval v4.4.0 workspace:
     `zephyr_build_e2e` passes — the staged app + module (TU + binding yaml + DUT
     overlay) builds via west for `qemu_cortex_a53` with zero errors (warnings
     recorded, not gating).
  3. L2: the campaign VM (patched QEMU) boots; the smoke app reports
     `device_is_ready(DUT) == true`; the driver's `LOG_*` lines appear on the
     console; no fault/hang.
  4. L3: `trace-diff` between the committed Zephyr-leg oracle trace and the captured
     DUT MMIO stream reports **zero unwhitelisted deviations**; every whitelist entry
     cites a ratified decision.
  5. Err witness: the init-fail image boots; the smoke app asserts
     `device_is_ready(DUT) == false` AND the authored `LOG_ERR` line is observed.
  6. Codex impl review of the final chunk: CLEAN (or findings dispositioned +
     re-review pass), per repo cadence.

- **C02 — Identity-test contract** *(design-intended, user-ratified)*:
  - Inputs: `pl011-composed/input.rs` and `pl011-composed-zephyr/input.rs`.
  - Each file carries exactly two marked licensed regions, delimited by explicit
    begin/end comment markers; each begin marker cites the ratifying decision for the
    OS-conditional content it licenses:
    - region (i) **match-transport**: the linux file's `amba = [...]` entry rows /
      the zephyr file's `compatible = [...]` list — citations: the linux_c AMBA match
      gate; Zephyr A-13/B-5 (this GRILL D01/D04). Region (i) covers ONLY the match
      entries; `name` and `bus` remain in the shared remainder.
    - region (ii) **deinit block**: the linux file's `on_deinit` impl / an empty
      marked region in the zephyr file — citations: B-6/C-3 as re-cited by D06.
  - The test (coverage-runner) strips marker lines + region contents from both files
    (line-based text operation, independent of Rust parsing — comments inside the
    attribute token tree are lexer-stripped and legal) and asserts the remainders are
    **byte-identical**. Failure names the first diverging line.
  - A marked region lacking a citation fails the test (the L3 empty-`ratified` rule,
    ported to sources).
  - The init-fail variant fixture (D14) is OUTSIDE this contract.
  - Exact marker token syntax: Open O2 (plan detail, bounded by the above).

- **C03 — `RSEQ_ZEPHYR_WORKSPACE` env contract** *(design-intended)*: absolute path
  to a west topdir (the eval workspace: Zephyr v4.4.0 checkout, SDK registered via
  the cmake package registry), with `west` invocable on PATH (the eval-side build
  script — the canonical exporter — activates the venv before exporting). Unset ⇒
